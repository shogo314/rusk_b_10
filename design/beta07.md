# Rusk β07の要件

> 過去の計画・設計記録です。現在の実装と今後の方針は[設計ノートの入口](README.md)から参照してください。本文中の未完了事項は記録当時の状態です。

完成したβ06（`899a47fdc8811dd64e917550ed5459af99a3146e`）を出発点に、変更・副作用・共有・脱出の情報を中間表現で明示し、解析結果に基づいて生成C++を最適化する。言語機能の拡張より、既存の意味を保ちながらRuskで書いた標準ライブラリを速くすることに集中する。

## 実装するもの

### 関数と操作の効果を明示する

引数や値について、読み取り、中身の更新、コンテナの構造変更、共有先の保持・返却、コールバックの呼び出しを区別する。型別に具体化した関数の効果を求め、呼び出し側の解析へ利用する。再帰・相互再帰も保守的な解析で扱う。externや解析できない呼び出しを、安全な根拠なく純粋・非変更と見なさない。

情報は型と名前を解決したHIRで明示し、LIRへ保持・反映する。情報の欠落や矛盾を検査し、中間表現の出力から解析結果と最適化の根拠を確認できるようにする。C++の関数名や生成コード文字列に依存して効果を推測しない。

### 変更・結び直し・脱出の注釈を導入する

各性質の両側に名前を付け、省略時の既定値を決める。3種類は独立して指定でき、片方の指定から別の性質を暗黙に要求しない。

| 性質 | 制限する指定 | 許可する指定 | 省略時 | β07で指定できる場所 |
|---|---|---|---|---|
| 中身の変更 | `readonly` | `mutable` | `mutable` | 引数・ローカル変数 |
| 名前の結び直し | `fixed` | `rebindable` | `rebindable` | 引数・ローカル変数 |
| 共有の持ち出し | `noescape` | `escape` | `escape` | 引数 |

`mutable`・`rebindable`・`escape`はそれぞれ許可を表し、実際に変更・結び直し・脱出することを要求しない。既定値も明示でき、相反する指定を同じ宣言に重ねた場合は診断する。注釈を省略した既存コードの意味は維持する。

以下の構文は実装済み。契約検査の現在の範囲と制約は[実装方針](../docs/development/beta07.md)を参照。

```text
readonly let view := values;                  // readonly / rebindable
fixed let alias := values;                    // mutable / fixed
readonly fixed let frozen_view := values;    // readonly / fixed
mutable rebindable let working := values;    // 既定値も明示可能
fn sum(readonly noescape a: Vec<Int>) -> Int { ... }
fn push_back<T>(noescape a: Vec<T>, escape x: T) { ... }
```

#### readonlyとmutable

readonlyは、その名前から到達する値への変更を禁止する。中身への`=`・複合代入、要素・フィールドへの`:=`、追加・削除・並べ替えなどの構造変更、取得した別名を通じた変更を検査する。入れ子の配列や構造体などにも及ぶ。変更可能なアクセスとしての受け渡し・格納・返却・捕捉によって制約を失わせない。readonly由来の別名をmutable指定だけで変更可能に昇格させない。独立したコピーは別の値として扱う。

readonlyだけでは名前自体の`:=`を禁止しない。別の変数や引数から同じオブジェクトが変更されれば、その変更が見える。注釈だけで呼び出しの間に値が不変であるとは判断せず、別名・効果の解析と組み合わせる。変更可能な共有先への読み取り専用の別名を作ること自体を、一律に禁止する設計にはしない。

#### fixedとrebindable

fixedは、その名前の初期化後の`:=`による結び直しを禁止する。中身の更新は別の性質であり、mutable fixedなら`x = value`は可能とする。`a[i] := value`はa自身の名前の結び直しではないため、fixedだけでは禁止しない。未初期化宣言を許す場合も、最初の初期化とその後の結び直しを区別して検査する。引数のfixedは関数内の仮引数名に対する制約である。

#### noescapeとescape

noescapeは、引数やその内部から得た共有を呼び出し終了後まで外へ残さない契約とする。共有での返却、外部の格納先への保存、外へ残るクロージャによる捕捉、脱出し得る関数への受け渡しを検査する。独立したコピーの返却や、呼び出し中だけの利用は区別する。noescapeでもmutableなら中身の更新は可能である。

例えばpush_backでは、配列aへの共有を外へ持ち出さない一方、追加する要素xへの共有は配列に保持するので、引数ごとに異なる契約になる。escapeは脱出を許可する既定値であり、実際の脱出の有無は解析結果として別に保持する。ローカル変数へのnoescape・escapeは、制約する範囲が別途必要になるためβ07では導入しない。

通常の関数・型引数付き関数・関数値やコールバックを通じた契約も伝播・検査する。externはC++の本体を検証できないため、宣言する契約と信頼境界を明示し、未指定は保守的に扱う。注釈だけでオーバーロードを区別する仕組みや、フィールド・型全体を含む全面的な修飾型体系は今回の前提にしない。

### 注釈した契約と推論した性質を区別する

readonly・fixed・noescapeの注釈は、意図せず契約を破る実装になることを検出するための任意の指定とする。通常のRusk関数では注釈を根拠に無条件で最適化せず、本体と呼び出し先を検査して契約違反を診断する。readonlyは変更経路、fixedは名前の結び直し、noescapeは引数やその内部への共有の持ち出しを制限する。mutable・rebindable・escapeを明示していても、解析で証明できる性質は同じように記録する。

注釈の有無にかかわらず、引数ごとの効果・共有の脱出と、ローカル変数の変更・結び直し・共有を解析する。変更しない・共有を外へ残さないと証明できた場合は、その性質をHIR/LIRの情報として明示する。呼び出しの検査と最適化は、注釈された関数だけでなく、同じ性質を推論できた関数にも適用する。解析できないことと、実際に変更・脱出することは区別して記録し、安全性が不明な場合は保守的に扱う。

利用者が宣言した契約、解析で証明した性質、externなどの信頼する契約は区別して保持する。読み取り専用や非脱出の引数を別の関数へ渡す場合も、既知の性質に基づいて検査する。引数を変更しないことだけでは入出力・実行時エラー・別の共有先からの変更がないことを意味しないため、関数全体の効果や別名の情報も使う。

### 共有と脱出を解析する

値が引数・戻り値・配列や構造体のフィールド・enumのpayload・クロージャの捕捉などを通じて保持されるかを扱う。局所的な別名と、関数外に残る共有を区別する。分岐・ループ・短絡・早期脱出を含め、解析不能な経路では安全側へ倒す。

### 戻り値の共有関係を解析情報として持つ

戻り値について、引数自身、引数から到達する要素・フィールド・payload・捕捉値、独立した新しい値やコピーのどれを共有するかを、関数の解析結果として保持する。例えば`return a[0];`はaの要素を共有し、`return copy(a[0]);`は独立したコピーを返す。分岐で複数の由来があり得る場合は候補を合わせ、不明な場合は保守的に扱う。

呼び出し側ではこの情報を実引数へ対応させ、戻り値の別名・寿命・readonlyの制約の伝播に使う。β07では利用者に共有関係を記述する新しい戻り値注釈を要求しない。externなど解析できない本体については、既知の契約と不明な関係を区別する。

### コールバックの保持と呼び出しの効果を解析する

関数値を引数として受け取る処理について、その場で呼ぶ、別の関数へ渡す、コンテナ・クロージャ・遅延イテレータなどへ保持する、といった使われ方を区別する。既存の静的な関数値の型と具体化を利用し、呼び出したコールバックの変更・入出力・失敗し得る処理・戻り値の共有関係を、呼び出し元の解析へ反映する。捕捉値への共有と、その保持・変更も追跡する。

遅延map・filterはコールバックを返すイテレータに保持する。一方、その場で呼ぶだけの関数も、コールバックが捕捉値や引数由来の共有を戻り値へ持ち出す場合がある。「関数値を保存していない」だけでnoescapeとは判断せず、結果を通じた脱出も検査する。解析できない呼び出しは保守的に扱う。

### 契約違反の理由と経路を表示する

readonly・fixed・noescapeの違反では、違反した操作の位置と、制約を宣言した位置を示す。別名・要素・フィールド・関数呼び出し・捕捉を経由する場合は、どの値からどの経路で制約が伝わり、どの操作で違反したかを説明する。単に「readonly違反」と表示して終わらず、利用者が原因の宣言と操作を辿れる診断にする。

証明できないことと、違反が確定していることを区別して説明する。HIR/LIRの出力でも、戻り値の共有関係、コールバックの保持・効果、解析結果の根拠を確認できるようにする。新しい診断の文書と、直接・間接の違反に対する位置・理由・経路の回帰テストを整備する。

### 解析結果を使って最適化する

- 寿命を保証できる一時参照を借用として扱い、不要なshared_ptrのコピーと参照カウント操作を減らす。
- 共有による同一性が外から観測されない局所スカラーを値で保持し、必要な時点で共有オブジェクト化する。
- コールバックなどによる変更がない走査で、要素の取得・一時保持を軽くする。
- 効果と寿命の情報から安全を証明できる検査・コピーを削減する。

最適化無効版を比較用に維持する。findやsumだけを特別扱いする専用の高速化に偏らず、通常のRusk関数にも利用できる解析とする。

### 標準ライブラリと性能を検証する

β06で移行したfindの速度退行を対象にする。sumはRuskでの実装と既存のextern実装を同じ入力で比較し、移行判断とその根拠を記録する。既存の演算・入出力・コンテナ・クロージャ・データ構造の性能も確認する。確保回数と参照カウント操作の削減を、実行時間と分けて検証する。

## 守る意味

`=`と`:=`、再帰的コピー、オブジェクトの同一性、左から右の一度だけの評価、共有を通した更新の可視性を変えない。文字参照中の長さ変更、走査中の構造変更、コールバックによる更新、取得済みの要素の寿命を守る。位置付きの実行時診断も維持する。

## 今回作らないもの

LLVMバックエンド、動的な共通関数型、トレイト・mixin、フィールド・型全体を含む全面的な修飾型体系、再帰型、スライス、浮動小数点、Unicode対応、新しい例外・Resultの体系は範囲外とする。引数とローカル変数への注釈は任意とし、既存コードに注釈を必須とする変更はしない。

## 完成条件

- 効果・共有・脱出情報の意味、保守的な扱い、HIR/LIRでの表現と検証を文書化する。
- 引数・ローカル変数のreadonly/mutable・fixed/rebindableと、引数のnoescape/escapeを宣言・検査できる。
- 省略時と既定値の明示が同じ意味になり、注釈の組み合わせと矛盾、初期化と結び直し、別名・入れ子・呼び出し・捕捉経由の違反をテストする。
- 別の共有先からの変更を正しく扱い、注釈なし・許可側の明示でも解析結果から同じ最適化を利用できることを確認する。
- 戻り値の共有関係を解析情報として保持し、引数由来・内部要素由来・独立コピー・分岐の複数候補・不明な由来を呼び出し側で正しく扱う。
- コールバックの即時呼び出しと保持を区別し、捕捉値・副作用・戻り値経由の脱出を通常の関数値と遅延イテレータでテストする。
- 契約違反の操作位置・宣言位置・別名や呼び出しを通じた経路を診断し、解析不能による不確かさも区別して説明する。
- 最適化前後で出力・更新・共有・脱出・寿命・診断が一致するテストを整備する。
- 通常版、最適化無効版、サニタイザー、公開ジャッジ、ドキュメントのCIを通す。
- find・sumと既存のベンチマークについて、条件と各回の測定値を残し、改善と残る差を説明できるようにする。

## 実装状況

効果・戻り値の共有・コールバック・脱出の解析とHIR/LIRへの保持、3組の注釈の構文と契約検査は実装済み。引数借用、更新する局所スカラーの値保持と返却、安定した配列スロットの基本ブロック内での直接借用、所有者を残した要素の別名と借用した仮引数の別名の分岐・ループをまたぐ借用に対応している。不明な効果・共有先や解析上限では保守的な表現を維持する。

readonlyは別名・結び直し・既知の格納先・フィールド・payload・呼び出し・捕捉の伝播経路と、通常の呼び出し先の返却・変更箇所を説明する。診断用の履歴を安全性の証明へ使わず、不明性・省略も明示する。noescapeも呼び出し先の仮引数・局所別名・共有の返却・外への保持操作まで、対応する引数と射影の経路を説明する。外部実装・再帰・診断用の上限で内部経路を再構成できない場合は理由を示し、契約の判定は変えない。

完成条件に対応する実装とローカル検証は完了した。全テストCI・文書公開の実行記録から、各更新の最終検証結果を確認できる。さらに広い借用や値保持は追加の性能改善として扱い、完成条件との照合結果と現在の制約は[実装方針](../docs/development/beta07.md)に集約する。
