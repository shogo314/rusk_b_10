# β02 の目標と実装計画

> 過去の計画・設計記録です。現在の実装と今後の方針は[設計ノートの入口](README.md)から参照してください。本文中の未完了事項は記録当時の状態です。

β02の目標は、競プロ用の型やデータ構造をRusk自身で定義し、別ファイルに分けて再利用できる段階に進めること。β01の機能・共有とコピーの規則・既存の問題解答を土台にする。

## 完成条件

- 構造体を定義し、フィールドの読み取り・更新・結び直しができる。
- タプルによる複数値の受け渡しと分解ができる。
- 型引数を持つ関数・構造体を具体化でき、ユーザー定義型を配列に格納できる。
- `include` で自作ライブラリを読み込み、依存先を含む単一のC++20ソースを生成できる。
- Union-Findを構造体として、Fenwick Treeや区間和セグメント木を型を変えて使えるライブラリとして書ける。
- 既存137問、新機能の共有・コピー・診断、新ライブラリを使う公開テストが通る。
- 利用者向けドキュメントに実装済みの機能と制限を記し、性能測定でβ01からの大きな退行がないか確認する。

## 実装順序

1. 構造体とフィールド、再帰的コピー、構造体を格納する配列。
2. タプルと分解。
3. 最小限のジェネリクス。具体化と名前解決の範囲を記録して実装する。
4. ファイル分割とライブラリ化。
5. 実例・公開テスト・利用者向け説明・性能の確認。

構造体は既存の設計に従い、`struct Point { x: Int; y: Int; }`、`Point { x: 1, y: 2 }` を基本とする。構築式は指定した値を共有し、`copy` と `let p = value` は各フィールドを再帰的にコピーする。`p = q` は外側の同一性を保ってフィールドを置き換える。

当初は型・名前付き関数を従来どおりトップレベルに置く。最初の構造体実装は非再帰の型を対象とし、比較・出力は自動生成しない。これはβ02全体や将来の言語仕様での禁止を意味しない。ジェネリクスの名前解決、再帰的な型、比較の生成などの境界は実装に先立って明示する。

クロージャ、読み取り専用の型体系、標準ライブラリの網羅、全面的な高速化はβ02の完成条件に含めない。

## β02の具体化と名前解決

型・名前付き関数はトップレベルに限定する。引数の型から型引数を推論し、`f::<Int>(...)` の明示指定も使える。具体型の完全一致する関数を優先し、ジェネリックな候補同士が複数適用できる場合は曖昧として拒否する。具体化した本体の呼び出しもグローバルの関数群から解決する。戻り値だけからの推論、部分的な型引数指定、トレイト・mixinは今回の範囲外とする。

Fenwick Treeを通常のアルゴリズムで書くため、整数の `&`・`|`・`^` と位置付きの失敗を示す `assert(Bool)` も追加する。シフト演算はこの実装には含めない。

## 実装・検証状況

上記の完成条件を実装済み。構造体・タプル・ジェネリクス・includeと、Ruskで記述したUnion-Find / Fenwick Tree / 区間和セグメント木を追加した。実装上の制限と利用方法は `docs/reference/beta02.md` に記載する。

`python3 tools/test.py` でフォーマット、Clippy、Cargoテスト178件、サニタイザー5例、公開ジャッジ38解答・526ケースが成功した。既存137問を維持し、Library Checkerの同一問題にセグメント木による別解を追加している。

β01最終版との同一プログラムの速度比較では、この環境の3例で約−4〜+4%だった。測定条件と限界は `docs/development/beta02-performance.md` に記録する。
