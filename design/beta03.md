# β03 の要件と実装計画

> 過去の計画・設計記録です。現在の実装と今後の方針は[設計ノートの入口](README.md)から参照してください。本文中の未完了事項は記録当時の状態です。

β03の目標は、β02の共有・コピーの意味を保ちながら、競プロで使う処理を速くすること。2026年11月7日に合意。

## 完成条件

1. バッファを使う入出力を実装し、空白・改行・不正入力・位置付きエラーの仕様を維持する。
2. 算術計算・条件判定・ループで、共有が観測されない基本値のヒープ確保と参照カウント操作を削減する。判断できない場合は従来の共有方式を使う。
3. 型検査後の中間表現を設け、意味の検査とC++生成を分ける。最適化を無効にした実行結果とも比較できるようにする。
4. 整数入力・出力、整数ループ、ソート・探索、BFS、Fenwick Treeについて、同じソース・入力・環境でβ02と比較する。整数入力と整数ループの中央値で2倍以上の高速化を目標とする。
5. 既存137問、共有・コピー・評価順序・診断のテストを維持し、最適化に関する回帰テストと実装方式・測定結果の説明を追加する。

性能の数値をCIの時間制限による合否判定には使わない。反復回数・環境・入力サイズ・全計測値を記録し、他の測定項目で大きな退行がないかも確認する。

## 変更しない意味

`let b := a; a = 2;` の更新はbにも見える。評価は左から右で、先に保持した共有には後続の中身の更新が見える。結び直しには追従しない。格納・受け渡し・戻り値の共有、再帰的コピー、整数の検査、イテレータの無効化、文字の共有中の長さ変更制限も維持する。

## 実装順序

1. 性能測定を拡充し、β02の基準実行ファイルと測定結果を保持する。
2. 入出力をバッファ化し、境界・不正入力・混在入力・出力の互換性を検証する。
3. 型付き中間表現と独立したC++出力処理を導入する。
4. 基本値の一時結果に対する確保削減を実装し、共有が必要な箇所ではオブジェクトを実体化する。
5. 既存テスト・サニタイザー・公開ジャッジ、β02と最適化無効版との比較、文書化。

クロージャ、辞書・集合、再帰的な型、readonly、LLVM対応は今回の範囲外。言語構文の追加より、既存のプログラムを同じ意味で速く実行することに集中する。

## 実装・検証状況

合意した範囲を実装済み。バッファ入出力、型の確定した値・呼び出しの中間表現と独立したC++バックエンド、一時結果の遅延実体化、比較用の `--no-opt` を追加した。制御構文・構築操作は検査済みのC++断片としてIRに保持し、任意の関数や制御フローをまたぐ最適化は行わない。

`python3 tools/test.py` でフォーマット、Clippy、通常版187テスト、最適化無効版77テスト、サニタイザー6例、AOJ・Library Checkerの公開テストが成功した。既存137問を維持し、位置付きエラー・共有・評価順序と実際のヒープ確保回数を検証している。

β02比で整数入力は2.97倍、整数ループは2.18倍となり、この環境で目標の2倍を達成。他の4項目にも大きな退行はなかった。測定条件・全サンプル・実装の制限は `docs/development/beta03.md` と隣接するJSONに記録する。
