# 変換段階の分離

> 過去の計画・設計記録です。現在の実装と今後の方針は[設計ノートの入口](README.md)から参照してください。本文中の未完了事項は記録当時の状態です。

β05の実装後に合意した処理系の再構成。ソース言語の機能を増やす前に、CST → AST → HIR → LIR → C++へ分離する。以前の処理系と同様に、LIRではifやループも基本ブロック・条件分岐・ジャンプへ落とす。

## 各段階の責務

- CST：Parolの解析結果とソース位置。二項演算は列として取り出し、優先順位と結合はAST構築時に規定する。
- AST：構文を整理し、宣言・式・制御構文を表す。includeはASTを読み込む際に展開する。
- HIR：名前と型・オーバーロードを解決し、ジェネリックを具体化する。変数の宣言ごとにID、関数・具体化先にIDを持つ。元の変数名で再検索しない。共有、コピー、更新、結び直し、構築、フィールド、ブロック、分岐、ループ、脱出先を表す。
- LIR：基本ブロックと、jump・branch・return・unreachableの終端命令を使う。SSAにはせず型付きの保持場所へ代入する。スコープを抜ける経路には必要な共有の解放を明示する。
- C++：型と値の表現、標準演算の直接生成、ランタイムとの接続、出力。ラベルとgotoを使う。ブロックをまたぐ保持場所を関数の入口で宣言し、ブロック内で完結する値はラベル後の括弧の内側で宣言する。初期化を飛び越えるgotoを作らない。

型付きのHIR/LIRの関数本体にはC++ソース文字列・ネイティブ型名を格納しない。外部実装と標準ランタイムのC++コードは別のターゲット用の定義として保持する。LLVMを追加するときは、このランタイムと共有・コピー・寿命管理の対応が別途必要。

## 維持すること

β05までの構文と意味、評価順序、共有と再帰的コピー、診断位置、β03の入出力・一時値の確保削減を維持する。HIR/LIRは--no-optで変化させず、C++バックエンドの表現選択だけを変える。

ブロック式やラベル付き脱出は今回の構造変更とは別の追加とする。内部のHIRではループのIDを持ち、LIRでは対応する脱出先へジャンプするため、後続の[ブロック式とラベル](blocks-labels.md)の追加で構文の名前解決を接続した。

## 検証

各段階を--emitで確認できるようにし、HIRの型・ID・呼び出し先・脱出先とLIRのジャンプ先を検査する。既存の全テストを維持し、スコープとジャンプをまたぐ共有の寿命、返却する値の保持、最適化の有無によるIRの一致を確認する。変更前のβ05と同じ入力で性能を比較する。

## 実装とローカル検証

実装済み。CST/AST/HIR/LIR/C++を--emitで出力できる。HIRとLIRの値は宣言ごとのID、呼び出しは解決済みの関数IDを持ち、型・呼び出し・制御フローの整合性を検査する。LIRで解放の前向き解析と到達不能ブロックの削除を行い、C++バックエンドでブロックをまたぐ値とブロック内の値の保持場所を選ぶ。
