# ローカル関数・名前探索の仕様

[関数の設計](functions.md) / [作業計画](../docs/development/plan.md)

この文書はβ10で実装する仕様を記録する。仕様の採用と実装状況は区別する。現在使える構文と実行例は言語リファレンス、各項目の作業状況は作業計画を参照する。仕様に対する境界条件の検証と、検索・API文書などのツールへの接続も作業計画で追跡する。

## 合意した骨格

- 名前付き関数もブロック内で定義でき、外側の変数を捕捉できる。DFSのような再帰を自然に記述できることを重視する。
- 通常の名前探索に、各引数の型の定義スコープからの探索を加える。通常の関数と演算子フックに同じ基盤を使う。
- 候補があるスコープの包含関係で隠蔽する。内側に同名候補があれば外側の候補群を除き、別の枝にあるスコープは両方残す。
- 隠蔽は引数型の適合判定より先に行う。適合しなくても外側へ戻らない。
- 適合する候補のうち、ジェネリックな引数の数が少ないものを優先する。同順位が複数なら曖昧としてCEにする。
- 同じスコープの同じ引数型の関数も別候補として保持し、曖昧な呼び出しをCEにする。同じ宣言を複数経路で見つけた場合は一候補とする。
- 通常名は定義側で解決する。型引数・フィールド型の再帰探索、ジェネリックの構造による特殊化順位、戻り値による候補選択は加えない。

以下に、宣言、環境の初期化、持ち出しを含む具体的な規則を示す。実装時の検証で矛盾が判明した場合は、暗黙に例外を追加せず仕様を見直す。

## 宣言と名前の有効範囲

関数・struct・enumの宣言は、そのブロック全体に属する。関数の署名と型の宣言を先に登録し、定義前参照と相互再帰を扱う。型名は宣言の識別子で区別し、同じ綴りでも別の宣言なら別の型とする。型の重複名は関数のオーバーロードとは別に検査する。

変数は従来どおり宣言後から見える。関数が捕捉できるのは、その関数の宣言位置から見える外側の変数である。後で宣言する変数を遡って捕捉する機能は加えない。トップレベルの実行変数をグローバル関数が捕捉しない現状も維持する。

変数の束縛は宣言を実行するたびに作る。関数の各呼び出し、再帰の各呼び出し、ループの各反復で別の束縛となる。ただし `let x := source` は既存のオブジェクトを共有し、束縛の生成自体はコピーを意味しない。捕捉で共有されたオブジェクトは、元の束縛のスコープを抜けても必要な間は生存する。

変数と関数が同名の場合は、通常の字句スコープで最も近い名前を使う。変数ならその値を呼び、呼び出せない型ならCEにする。関数候補へのフォールバックは行わない。同じスコープでの変数と関数の衝突はCEにする。関数同士の複数候補を許す規則とは区別する。

トップレベルの実行文は、グローバル宣言のルートより内側の実行スコープを持つ。したがって実行文の変数名はグローバル関数名を隠せるが、グローバル関数の捕捉対象にはならない。

ローカルexternの必要性は別に判断する。ローカルRusk関数・struct・enumのために、externの宣言範囲まで自動的に拡張することは前提にしない。

## 候補収集と選択

`f(a, b)` を関数名による呼び出しとして処理する場合、次の順で解決する。

1. 呼び出し式の字句スコープから通常の名前探索を行う。ジェネリック本体では具体化の呼び出し元へ移動しない。
2. 直接の実引数型それぞれの定義スコープから、同名の関数を探す。それぞれ外側へ辿り、最も近い同名候補群を収集する。
3. 宣言の識別子で重複を除く。集まった候補スコープのうち、別の候補スコープの祖先であるものを除く。兄弟スコープには順位を付けない。
4. 明示型引数、引数の個数、引数型の照合・型推論で適合する候補を残す。暗黙の数値変換は導入しない。
5. 宣言の引数型のうち、型パラメータを含む引数の数が最少の候補を選ぶ。
6. 一候補なら採用し、ゼロなら該当なし、複数なら曖昧としてCEにする。
7. 選択後に戻り型、捕捉環境の準備、権限・効果、本体の具体化を検査する。これらの失敗を理由に別候補を試さない。

引数の型から到達したスコープが、通常探索のスコープより外側なら、同じ包含規則で隠れる。探索経路の種類や引数の左右には優先順位を付けない。

`Vec<A>` は `Vec` の宣言スコープだけを関連付け、`A` の宣言スコープは追加しない。struct・enum・extern型は各宣言スコープに対応する。組み込み基本型と構造的なTupleはルートを起点とし、Tupleの要素型は辿らない。将来の型別名は今回の前提に含めない。

UFCSは既存の関数フィールド・関数変数の呼び出し規則を保ったうえで、通常の場合は第一引数を追加した同じ探索へ落とす。演算子は対応するフック名で同じ探索を行う。大小比較フックから `__cmp__` への既存のフォールバックは維持し、曖昧さや不正な戻り型を「候補なし」に読み替えない。

### ジェネリックな引数の数

| 宣言の引数型 | 数 |
|---|---:|
| `(Int, Int)` | 0 |
| `(T, Int)` | 1 |
| `(T, T)` | 2 |
| `(T, U)` | 2 |
| `(Vec<T>, Int)` | 1 |
| `((T, U), Int)` | 1 |

型パラメータの種類数や出現回数ではなく、型パラメータを含む引数位置の数を数える。明示型引数で具体化しても、宣言時の数は変えない。`f<T>(T)` と `f<T>(Vec<T>)` は同順位であり、両方に適合すればCEになる。

期待される戻り型は、選んだ関数の未決定な型引数の補完には引き続き使える。ただし候補間の順位や曖昧さの解消には使わない。整数リテラルの期待型による解決は既存のInt / Int128仕様との接続をテストし、候補の列挙順によって型が変わらないようにする。

## 捕捉と再帰

名前付きローカル関数の捕捉は、既存のラムダと同じく、環境を作成した時点のオブジェクトへの共有とする。

- 外側の `=` による中身の更新は見える。
- 外側の `:=` による結び直しには追従しない。
- 関数内の捕捉名への `:=` は、その呼び出しのローカル名だけを結び直す。
- 次の呼び出しと再帰呼び出しは元の環境から名前を受け取る。呼び出し中の結び直しを新しい環境として暗黙に引き継がない。
- readonly / mutable、fixed / rebindableと寿命の規則を捕捉にも適用する。

```text
{
let n := 0;
fn visit(depth: Int) {
    if depth == 0 { return; }
    n += 1;
    visit(depth - 1);
}
visit(3);
wt n; // 3
}
```

関数の宣言を実行すると、その活性化に対応する捕捉環境を準備する。ループや外側の関数の再実行では別の環境を作る。別の環境が同じオブジェクトを共有してもよい。捕捉なしの関数は宣言前から呼び出し・値としての取得を許す。捕捉ありの場合は環境の準備前の呼び出し・値としての取得をCEにする。

相互再帰は関数のコード識別子と環境を分けて扱い、関数同士を強参照で保持するためだけの循環を生成しない。呼び出す関数自身だけでなく、そこから必要になる関数の環境も準備済みである必要がある。直接・間接呼び出しとも検査し、未準備なら宣言位置と呼び出し経路を示す。

```text
{
let count := 0;
fn even(n: Int) -> Bool {
    count += 1;
    if n == 0 { return true; }
    return odd(n - 1);
}
fn odd(n: Int) -> Bool {
    count += 1;
    if n == 0 { return false; }
    return even(n - 1);
}
wt even(4); // 両方の環境を準備した後なので使用できる
}
```

関数を経由してのみ参照する環境も依存として記録する。例えば `f` が `g` を呼び、`g` が外側の変数を捕捉する場合、`f` だけを持ち出しても必要な環境が生存しなければならない。ジェネリックの具体化で初めて判明する依存も、宣言時点の捕捉先へ接続し、保存した呼び出し・関数値取得の位置の準備状態で検査する。未使用のジェネリック本体は具体化しない。

## オーバーロード集合の受け渡し

関数名の取得は、一関数への選択ではなく、その位置で通常探索した候補群と必要な環境を保持する。保持する候補の環境が未準備なら取得をCEにする。ジェネリック関数も未具体化のまま候補に含める。通常の関数値に共通の動的型は導入しない。

保持する字句的な候補群に必要な捕捉は全体で検査する。例えば捕捉なしのInt向け候補と捕捉ありのStr向け候補がある場合、後でIntを渡すだけでも、取得時にStr向け候補の環境が未準備ならCEにする。候補群の取得後の使い方から一候補だけに絞って、この検査を省略しない。

```text
fn apply<T, F>(x: T, operation: F) -> T {
    return operation(x);
}
let operation := copy;
wt apply(3, operation);
wt apply("abc", operation);
```

候補群を呼ぶ際には、保持した元の関数名と実引数型を使って関連スコープの候補を追加する。上の `operation` という変数名や、`apply` 本体の同名関数を探索に使わない。隠蔽の比較にも、保存した候補の元の宣言スコープを使う。

候補群の型の同一性には宣言群と環境の型を用い、実行時の環境オブジェクトの違いは型の違いにしない。具体化キャッシュも実行時ポインタに依存させない。`let g := f` は環境を共有し、`let g = f` と `copy(f)` は必要な環境をコピーする。自己再帰・相互再帰からもコピー後の環境を参照し、元の環境へ戻らないことを検証する。

## 型から見つける関数の捕捉環境

キャプチャ禁止を基本仕様にはしない。ただし型の宣言位置を静的に知っていることと、その実行で作った環境を取得できることは別である。

例えば外側の関数を二回実行して、同じローカル型の値を二つ作った場合、その型は同一でも、捕捉したオブジェクトは異なり得る。型だけをキーにして「最後に作った環境」や一つのグローバル環境を使ってはならない。

比較した方式は次の二つである。

| 方式 | 意味と確認事項 |
|---|---|
| 呼び出しに環境を渡す | 字句的に取得できる環境をジェネリック呼び出しにも隠れた引数として渡す。値だけを元のスコープの外に持ち出した場合の利用範囲を別途定める必要がある |
| ローカル型の値にも環境を保持させる | スコープ外でも型に関連する関数を呼べる。二つの引数が異なる環境を持つ場合の選択、コピー、環境との循環、型だけを使う呼び出しの扱いが必要になる |

### 採用する初期仕様

β10では前者を採り、オブジェクトの共有と別に、必要な関数環境を隠れた引数として渡す。ローカル型の値そのものには暗黙の環境フィールドを追加しない。

- ローカル型の操作を `sum` や別のジェネリック関数から呼べる。具体化で判明した環境への依存を、呼び出し元まで伝播させる。
- 必要な環境は、関数が宣言されたブロックの該当する実行から取得する。動的な呼び出し履歴や、最後に作った環境から探さない。
- 関数値として持ち出す場合は、その値が必要な環境を保持する。元のスコープを抜けた後も呼べる。
- ローカル型の値だけを持ち出した場合、その値から捕捉環境を復元しない。元の環境が取得できない位置で、捕捉付きの関連操作を暗黙に呼べばCEにする。捕捉のない操作にはこの制限はない。
- 操作もスコープ外で必要なら、関数値として一緒に持ち出す。これに共通の関数型を導入する必要はなく、既存の型引数付きコンテナや具体的な外側の型を通じて保持できる。

この規則なら、型が同一で環境が異なる値を二つ渡した場合に、左右どちらの値の環境を選ぶかという規則は不要になる。環境は値から選ばず、明示的に保持・受け渡されたものを使う。ただし候補群が同じ宣言の別環境を同時に含み得る経路は検査し、宣言の重複除去で環境の違いを消してはならない。

これは捕捉付き関連操作の一律禁止ではなく、環境をどこから取得するかの規則である。型の値だけで環境も自動的に持ち出す方式より利用範囲が狭いことを含め、この方式を採用する。隠れた引数による伝播が具体化・効果解析・コピーと両立することを検証する。

例えば関数値を持ち出す次の例は許す。

```text
let operation := {
    let offset := 10;
    fn add_offset(x: Int) -> Int { return x + offset; }
    add_offset
};
wt operation(1); // 11。関数値がoffsetへの共有を保持する
```

一方、次の例は初期仕様ではCEになる。

```text
let value := {
    let offset := 10;
    struct Item { value: Int; }
    fn adjusted(x: Item) -> Int { return x.value + offset; }
    Item { value: 1 }
};
wt adjusted(value); // 宣言は型から見つかるが、その実行の環境を取得できない
```

この場合、同じブロックの内側からジェネリック処理へ `value` を渡して `adjusted` を呼ぶことはできる。また、`adjusted` を関数値として `value` と一緒に持ち出せば、スコープ外でもその関数値を呼べる。

## 実装で検証する例

1. DFS、捕捉ありの相互再帰、再帰途中の捕捉名への `:=`。
2. 宣言前の呼び出しと関数値取得、準備前の環境に間接的に到達する呼び出し。
3. 同名の内外スコープ、兄弟スコープ、両引数型からの重複探索、同じ引数型の別宣言。
4. ジェネリックな引数の数による順位、同順位の曖昧さ、明示型引数、Int128リテラル。
5. ローカル型と演算子、捕捉する操作をジェネリック関数から呼ぶケース、多段の具体化。
6. 候補群を高階関数へ渡すケース、別名での呼び出し、候補群の共有・コピー。
7. 二回の外側関数呼び出しで異なる環境を作るケース、スコープ外への持ち出し。
8. 捕捉・相互再帰によるリークやコピー先から元の環境への参照がないこと、権限・効果・寿命の維持。

名前付き引数、既定引数、ラムダの引数型省略、動的な共通関数型、制約・トレイトは、この仕様を整えるための前提にしない。
