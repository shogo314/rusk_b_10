## 走査の基本規約

当面、`for` の走査規約は `__iter__` と `__next__` の2関数方式とする。`__iter__(a)` で走査状態を取得し、`__next__(iter)` は次の要素があれば `Some(x)`、終端なら `None` を返す。以前の試作の `__has_next__` は基本規約に要求しない。

取得した要素の共有と読むだけの制限は維持する。配列から走査を作る場合は、それぞれ独立した走査状態を持つ。

イテレータに対する `__iter__` は同じ走査状態を共有し、現在の位置から走査を続ける。`__next__` で一部を取得した後や、`for` を `break` で抜けた後も、残りを走査できる。イテレータの別名同士も同じ進行状態を共有する。

一度 `__next__` が `None` を返したイテレータは、以後も `None` を返す。元データの変化で終了済みの走査が再開することはない。構造変更による未終了のイテレータの無効化と、要素への共有の制限は別途扱う。

`for` の `else` は、`__next__` が `None` を返して正常に走査を終えた場合に実行し、利用者の `break` では実行しない。実装では内部の終端処理と利用者の `break` を区別する。

`zip` の長さ不一致を検出する際は、片方から取得した後に他方の終端が分かる場合がある。エラーの前に一方を一要素余分に消費し得る点は、検出方法や副作用とともに今後詰める。

## 遅延する map と filter

列に対する `map`・`filter` は、それぞれイテレータを返す。呼び出した時点で結果の配列を作らず、走査時に変換や条件判定を実行する。

```rusk
let it := a.filter(_ > 0).map(_ * 2);
for x in it { ... }
let b := it.to_vec(); // 残りを配列にする
```

途中で `break` した場合、残りの要素には関数を適用しない。副作用のある関数も走査時に実行される。`filter` が通す要素は元の共有と読むだけの制限を保ち、`map` の結果は適用する関数の振る舞いに従う。

`to_vec` はイテレータの残りを走査して `Vec` にする。受け取った要素は自動コピーせず共有して格納し、読むだけの制限も維持する。独立した要素を集めたい場合は `.map(copy).to_vec()` のようにコピーを明示する。制限を型としてどう表現するかなどの詳細は未決定。

`collect` ではなく変換先が分かる名前を使う。将来の `to_set` なども同じ命名の方向で検討するが、個別の API の採用は未決定。渡す関数は、既定の方針どおり静的に特殊化でき、外部の変数も捕捉できる。

`Option` の `map` は列の遅延走査とは区別し、値があればその場で一度関数を適用する操作として考える。

## 探索と集計による走査の消費

イテレータに対する探索・集計は、結果を決めるために必要なところまで消費し、未消費の続きは残す。

- `any` は最初に条件を満たした要素まで消費する。
- `all` は最初に条件を満たさなかった要素まで消費する。
- `sum`・`min`・`max` は残りすべてを消費する。

判定に使った最後の要素も消費済みとし、次の走査には含めない。短絡せず終端まで調べた場合は、終端を検出した状態になる。

配列などに直接適用する場合は新しいイテレータを作る。既存のイテレータに適用する場合は、共有している走査状態を進める。

空の列では `any` は偽、`all` は真、整数の `sum` は `0` を返す。`min`・`max`・`argmin`・`argmax` は `Option` を返し、空の場合は `None` とする。既定値は `a.min() ?? INF`、空でないことを前提にする場合は `a.max()?!` のように扱える。これらの演算子の具体的な構文は既存の案に従う。

`sum` は初期値を引数に取れるようにする。この引数は空の場合だけ使う既定値ではなく、合計の出発点とする。たとえば `[1, 2].sum(10)` は `13`、空の列の `sum(10)` は `10` を返す。引数なしの整数の `sum()` は初期値 `0` の省略形とする。

一般の型の集計の初期値を `T()` と同一視しない。独自型でも初期値を明示できるようにする。整数以外で初期値を省略できる範囲などは未決定。

`sum` は初期値を直接 `+=` で更新せず、先頭から `+` を使い、`((init + a[0]) + a[1]) + ...` の順に合計する。加算結果へ累積値の指す先を結び直す形とし、初期値自体を更新対象にはしない。最適化でも観測できる演算の順序や副作用を保つ。

空の場合は `init` 自体を返して共有を保つ。常に独立した結果が必要なら `a.sum(copy(init))` と書ける。ユーザー定義の `+` 自体に副作用や共有がある場合は、その関数の振る舞いに従い、`sum` が純粋性や独立性を追加で保証するものではない。

## 最小値・最大値と位置

`min`・`max` は、選んだ要素を自動コピーせず共有して返す。読むだけの制限も維持する。同値の要素が複数あれば、走査順で最初の要素を選ぶ。空の場合は既定の方針どおり `None` を返す。

```rusk
let a := [2, 1, 1];
let x := a.min()?!;
x = 9;
// a は [2, 9, 1]
```

`argmin`・`argmax` も同値なら最初の位置を選ぶ。位置は今回の走査の先頭を `0` として数え、スライスならスライス内、途中まで消費したイテレータなら残りの先頭を基準とする。

## enumerate と zip

添字と要素を同時に走査する `enumerate` と、対応する要素を組にして走査する `zip` を用意する。新しい配列は作らず、走査時に順次取り出す。要素は元の共有と読むだけの制限を保つ。

```rusk
for (i, x) in a.enumerate() { ... }
for (x, y) in zip(a, b) { ... }
```

`enumerate` の添字は既定で `0` 始まりとし、`a.enumerate(1)` で開始値を変更できる。`zip` は長さが異なる場合にエラーにする。長さの分からない走査での検出方法、3列以上の対応などの詳細は未決定。

## 優先度付きキュー

最小値から取り出す `MinHeap<T>` と、最大値から取り出す `MaxHeap<T>` を用意する。追加は `push`、取り出しは `pop` とする。`pop` は取り出した値を `Option` で返し、空なら `None` を返す。

```rusk
let q := MinHeap<Int>();
q.push(3);
q.push(1);
let x := q.pop(); // Some(1)
```

`push` は再帰的コピーして格納し、元の値の変更で内部の順序が壊れないようにする。

削除せず次の要素を取得する操作は `top` とし、読むだけの共有を `Option` で返す。空なら `None` とする。`pop` は要素を削除し、その値を更新可能な共有として返す。取り出し時に追加のコピーは要求しない。

`top` で取得済みの共有は、要素が削除された後も引き続き使用でき、読むだけの制限は残る。`MinHeap` の `top` は最小値、`MaxHeap` の `top` は最大値を返す。

優先順位は、通常の値の比較に加えて、比較関数・キー関数の両方で指定できる方向とする。具体的な引数の書き方はソートと併せて検討する。

キー方式では、`push` 時に値を格納用に再帰的コピーし、そのコピーからキー関数を一度だけ評価する。キーも再帰的コピーして値とは別に保持し、保存したキーでヒープを維持する。`top`・`pop` は格納した値を返す。キーが同値でも値自体を追加で比較しない。外部の値が変わっても、保存済みのキーは再計算しない。

比較関数方式では、格納した値に比較関数を適用する。比較関数は「左が右より小さい」を `Bool` で返し、利用中に順序関係を変えないことを要求する。捕捉した外部変数の変更によって比較の意味を変えることも、この規約に反する。

同じ優先順位の要素の取り出し順は、既定では保証しない。挿入順を保ちたい場合は、利用者が優先順位に連番などを組み合わせて順序を指定する。`MinHeap` では `(priority, insertion_id)` の辞書順、`MaxHeap` では同順位時に連番の順序を反転する方法などが考えられる。安定ソートを既定とする方針とは区別する。

実装案として、比較処理を静的に特殊化し、キー関数・比較関数の捕捉環境はヒープが保持する。通常版・キー版・比較関数版の内部表現や型の構文は未決定。関数による副作用や規約違反の扱いなども今後詰める。

## 辞書と集合のキー

辞書・集合に格納するキーは、格納時に再帰的にコピーし、外部のオブジェクトから独立させる。格納後に元の変数やその内側の値を変更しても、格納済みのキーには影響しない。

格納済みのキーを取得・走査する場合は、読むだけの共有を返す。内側の要素や別名を通じた変更も禁止し、ハッシュや順序との整合性を保つ。独立して変更したい場合は `copy` を使う。

辞書の値はキーと区別し、更新可能にできる。ハッシュ・順序付けの仕組みや各コンテナの詳細な API は今後詰める。

## 辞書の値の格納と更新

辞書の値は、渡されたオブジェクトをコピーせず共有して格納する。`dict.set(key, a)` の後で `a` の中身を更新すると、辞書からも更新が見える。独立させる場合は `dict.set(key, copy(a))` と明示する。キーは引き続き格納時に再帰的にコピーする。

`dict.set(key, x)` は値の格納先を `x` に結び直す。`dict[key] := x` も同じ結び直しに対応し、以前取得した値への共有は古いオブジェクトを指し続ける。一方、`dict[key] = x` は添字アクセスで取得した値オブジェクトの中身を更新する。

存在しないキーへの `dict.set(key, x)` と `dict[key] := x` は、`V()` を作らず直接 `x` を共有して格納する。引数なしで構築できない値型でも使用できる。

`dict[key] = x` と `dict[key] += x` は、先に添字アクセスで対象を取得する。キーがなければ `V()` を作って格納し、そのオブジェクトを更新する。`=` だからという理由で初期値の構築を意味上省略することはしないが、観測できる振る舞いを保てる場合は最適化できる。

## 辞書と集合の種類と走査順

辞書・集合には、検索・更新の効率を重視するハッシュ型と、キーの順序を扱う順序付き型を用意する。

基本の辞書・集合はハッシュ型とし、型名は `Dict<K, V>`・`Set<T>` とする。走査順は保証しない。

順序付き型の名前は `SortedDict<K, V>`・`SortedSet<T>` とする。キーの昇順で走査でき、境界探索にも対応する。挿入順を保持する意味の型ではない。各操作の詳細な計算量の保証や、ハッシュ・比較の指定方法などは未決定。

辞書の走査は `(key, value)` を返す。キーは読むだけの共有、値は更新可能な共有を基本とする。ただし、読むだけの辞書からの走査では値にもその制限を引き継ぎ、制限を迂回できないようにする。

## 辞書と集合の走査中の変更

辞書の値の中身の更新はイテレータを無効化しない。新しいキーの追加と既存キーの削除は、未終了のイテレータを無効化し、次に使った時点でエラーにする。集合も追加・削除で同様に無効化する。キーは従来どおり読むだけとする。ハッシュ型・順序付き型の両方に適用し、別名や関数を通じた操作も同じ規則に従う。

```rusk
for (key, value) in dict {
    value += 1;       // 許可
    dict[other] += 1; // 未登録なら挿入し、次の走査時にエラー
}
```

既存キーの値の結び直し、コンテナ全体への代入、構造変更の厳密な範囲や検出の実装方式などは未決定。

## 辞書の取得と既定値

`dict.get(key)` は挿入せずに `Option` で返し、`dict[key]` はキーがなければ値型の `V()` を格納して更新可能な共有を返す。`get_or_insert` 相当の公開操作も候補とする。`V()` はキーが存在しない場合だけ評価する。

`count[x] += 1` はゼロから数え、`groups[x].push_back(y)` は空配列から追加できる。取得を伴う添字アクセスには `V()` が使えることを要求する。読むだけの辞書での添字アクセスなどの詳細は未決定。

## 配列リテラルと繰り返し初期化

通常の配列リテラル `[x, y]` は指定したオブジェクトを共有する方向で考える。

初期値で埋める場合の要素ごとの再帰的コピーは、通常の共有とは異なる操作なので、専用リテラルを用意する。構文候補は `[x; N]` とし、初期値と個数をそれぞれ一度だけ評価した後、各要素に独立したコピーを作る。

```rusk
let grid := [[0; W]; H];
grid[0][0] = 1;
// 他の行は変わらない
```

配列リテラルの要素の型はすべて同じとし、暗黙の型変換で揃えることはしない。たとえば `[1, 2, 3]` は `Vec<Int>`、`[1, 2.0]` は型の不一致でエラーとする。型名は既存のノートと同様に仮の表記を含む。

空配列 `[]` は、型注釈や渡し先などから要素型が分かる場合に使える。`let a: Vec<Int> := [];` は使え、型が決まらない `let a := [];` はエラーとする。後続の使用からの推論を認めるかは将来の検討事項とする。

既定の配列リテラルは通常の共有型配列を作る。高速な配列の構築は別の書き方を用意する方向とし、具体的な記号や書き分けは未決定。

## 配列の連結と追加

配列の `a + b` は新しい外側の配列を作り、`a += b` は既存の `a` に要素を追加する。

通常の共有型配列の `+=` は、既存の要素の共有を保ち、追加する `b` の要素もコピーせず共有する。追加する要素を独立させたい場合は `a += copy(b)` と書く。

専用の `__iadd__` は、`a = a + b` への自動展開と共有関係まで同じである必要はない。通常の配列では、既存の要素を保持して追加する意味を優先する。

通常の配列の `+` は、新しい外側の配列に元の要素を共有して格納する。再帰的コピーはしない。これは算術演算の独立性というライブラリ規約に対して、列の連結では内側の共有を保つ例外とする。`Str` や直接格納する配列の詳細、自己連結などは未決定。

## 要素ごとの演算の構文案

列の連結と区別し、要素ごとの演算やスカラーの適用には、Julia のようなドット付き演算子を使う案を検討する。

```rusk
a + b   // 連結。外側は新規、要素は共有
a .+ b  // 対応する要素の加算結果を並べる
a .+ 3  // 各要素に 3 を足した結果を並べる
```

ドット付き演算の展開先の名前は、ひとまず `__broadcast__` とする。`a .+ b` を `__broadcast__(__add__, a, b)` のような関数適用へ展開する方向とする。要素の結果の共有や独立性は、適用する関数の振る舞いに従う。

多次元の配列には再帰的に適用する方向で考える。列同士ならその段の長さの一致を要求して対応する要素へ再帰し、列とスカラーならスカラーを各要素へ再帰的に適用する。両方がスカラーになった時点で渡された演算関数を呼ぶ。たとえば `[[1, 2], [3, 4]] .+ 10` は `[[11, 12], [13, 14]]` となる。さらに複雑な形状の自動調整は、当面の規則に含めない。

複数のドット付き演算も通常の関数呼び出しとして意味を定め、既定の評価順序に従う。`a .* 2 .+ b` は乗算側の呼び出しを完了してから加算側を実行する。構文による走査の融合は保証せず、副作用やエラーの発生順序、共有など、観測できる振る舞いを変えないと確認できる場合だけ最適化で融合できる。

一般の関数へのドット構文、列・スカラーの判定範囲、結果の型、単一の呼び出し内の再帰的な走査順序などの詳細は未決定。

`a .+= b` のような更新版も候補だが、同じオブジェクトを複数の要素が共有している場合の更新回数などが未決定のため、採用は保留する。

## 高速化を意識した配列の要素

要素を直接格納し、要素が指す先を変更できない配列を設ける。この配列と `Str` は、要素アクセスに共通のルールを使う。

取得した要素への共有を許す。`let x := a[0]; x = 10;` は元の要素も更新する。一方、`a[0] := y` のように要素の指す先を変更する操作は禁止する。独立した値が必要なら `copy(a[0])` と明示する。`Str` でも `let c := s[0]; c = 'z';` は元の文字を更新する。

要素への共有の使用中は、追加・削除など参照先を無効にする構造変更を禁止し、エラーにする。使用中とみなす範囲、禁止する操作の詳細、検出方式、配列の型名は未決定。読むだけの制限も要素への共有に引き継ぐ。

## 並べ替えと要素への共有

通常の配列の並べ替えは、要素が指すオブジェクトの配置を入れ替える。取得済みの要素への共有は、元のオブジェクトを指し続け、同じ添字の位置に追従するものではない。

```rusk
let a := [3, 1, 2];
let x := a[0];
sort(a);
x = 9;
// a は [1, 2, 9]
```

要素を直接格納する高速な配列と `Str` では、要素への共有の使用中はソートなどの並べ替えも禁止し、エラーにする。

通常の配列でも、`for` 走査中やスライスの使用中の並べ替えには、それぞれの走査・スライスの制限を適用する。単一要素への共有と、配列の区間や走査への依存は区別する。

## 添字アクセスの展開

`a[i]` は `__getitem__(a, i)` に展開し、要素への共有を取得する。`a[i] = x` は取得した対象への中身の更新として `__assign__(__getitem__(a, i), x)` に対応させる。

`a[i] := x` は、要素の指す先を変更する専用操作 `__setitem__(a, i, x)` に対応させる。取得したオブジェクトの中身の更新とは区別する。直接格納する高速な配列と `Str` では、この結び直し操作は許さない。

`:=` の左辺の一番外側が添字アクセスの場合に、この専用操作へ展開する。内側の添字アクセスは通常の取得として評価する。たとえば `a[i][j] := x` は `__setitem__(__getitem__(a, i), j, x)` に対応する。

左辺の一番外側がフィールドアクセスならそのフィールドを結び直す。`a[i].field := x` は取得したオブジェクトのフィールドを結び直し、`a[i]` 自体を結び直さない。意味のないグループ化の括弧はこの判定を変えず、`(a[i]) := x` も `a[i] := x` と同じ操作とする。

これらは意味の対応を示す表記であり、実際の展開では既定の左から右の評価順序を保ち、対象や添字を重複評価しない。

公開 API の `get`・`set` と、演算子用の `__getitem__`・`__setitem__` は必ずしも同一の操作にしない。セグメント木の整合性を保つ更新など、コンテナごとに適切な取得・更新操作を定義できるようにする。型ごとの対応や内部関数の直接利用の範囲は今後詰める。

## 配列の添字

配列では負の添字を使えるものとする。`a[-1]` は末尾、`a[-2]` は末尾から2番目を表す。

要素への範囲外アクセスは実行時エラーにする。スライスの端点が範囲外の場合も、暗黙に切り詰めず実行時エラーにする。たとえば長さ3の配列では `a[-1]` は有効だが、`a[-4]` と `a[0..4]` はエラーになる。

スライスでの負の端点や、開始位置が終了位置を超える場合などの詳細は未決定。

## スライス

`a[l..r]` のようなスライスは、要素をコピーせずに作れるものとする。スライスは一つの列として扱い、探索結果などの位置はスライスの先頭を `0` とする。

スライスは元の配列の区間を参照する、長さ固定のビューとする。要素の中身の更新も、要素が指す先の変更も元の配列に反映する。スライス自体への追加・削除は許さない。読むだけの配列から作ったスライスには、読むだけの制限を引き継ぐ。

スライスの使用中に元の配列の構造を変更する操作はエラーにする。使用中とみなす範囲、構造変更の具体的な範囲、検出方法などは未決定。

## 走査中の配列の変更

配列の要素の中身の更新はイテレータを無効化しない。追加・削除や並べ替えなど、走査対象を変える操作は未終了のイテレータを無効化し、そのイテレータを次に使った時点でエラーにする。変更自体をイテレータの存在だけを理由に禁止しない。別名や関数を通じた操作にも同じ規則を適用する。

追加しながら処理する場合などは、`while` と添字を使って走査を明示する。構造変更を検出する方式、配列全体への代入や要素の結び直しなどの具体的な判定範囲は未決定。

## イテレータの無効化

構造変更で無効化された未終了のイテレータは、次の `__next__` などで走査状態を再利用した時点でエラーにする。`for` を `break` で抜けた後でも同じとする。変更後に新しくイテレータを作れば走査できる。これは以前の「走査中の変更時にエラー」とする方針を見直したもの。

変更回数をイテレータ作成時に保持して照合する方式が候補だが、実装方式は未決定。要素を直接格納する配列や `Str` の要素への共有、スライスの使用中の構造変更を禁止する規則は維持する。イテレータから取得済みの要素への共有がある場合も、その共有自体の制限に従う。
