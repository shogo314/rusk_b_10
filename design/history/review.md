## 合意の土台

- 競技プログラミングが目的。作者自身の書きやすさと、十分な実行速度を重視する。
- 変数や引数はオブジェクトを共有する。`:=` は結び直し、`=` は外側を維持した再帰的コピーによる更新。
- オブジェクトは変数名のスコープを超えて使用できる。寿命管理方式は未決定。
- 結び直し禁止と読むだけの制限は別の性質。読むだけの制限は別名・要素・戻り値にも維持し、型検査で守る。
- 演算は基本的に通常の関数へ展開する。短絡など評価制御の詳細は別途設計する。
- 評価は原則左から右。共有する値を評価時点で自動コピーしない。
- 関数の受け渡しは静的な特殊化を基本とし、オーバーロード集合の受け渡しは有力案。
- 標準ライブラリは原則自動で使え、入出力は関数呼び出しへの糖衣構文。

各分野の詳細な合意は、それぞれのノートを正とする。この一覧は全仕様の列挙ではない。

## 根幹で未解決の組み合わせ

| 論点 | 決まっていること | まだ決めていないこと |
|---|---|---|
| 名前探索と初期実装 | 通常名は定義側を基準。最も内側の同名関数群から選ぶ方針 | mixin・トレイト等の選択、何段も具体化する場合、初期実装をグローバル限定にするか |
| 型の持ち出し | オブジェクトの寿命はスコープを超えられる | ローカル型の定義・持ち出し、無名構造体、通常関数の推論された戻り値の表記 |
| 捕捉 | 作成時のオブジェクトを共有し、外側の結び直しには追従しない | 再帰で捕捉名を結び直した場合、候補集合ごとの環境、相互再帰の環境初期化 |
| コピーと共有 | 再帰的コピー。外側の代入対象だけ同一性を保つ | コピー元の内部で同じオブジェクトが複数回現れる場合、その共有関係を再現するか。コピー元・先が重なる代入の詳細 |
| 循環 | 再帰的な型は許す | 循環共有の可否と解放、コピー・比較・ハッシュ。優先度を下げて保留 |
| 読み取り制限 | 外側と要素の権限を区別し、危険なコンテナ型変換は禁止 | 正式な型表記、取得関数の権限の引き継ぎ、内部に readonly を含む値を copy した結果の型 |
| 直接格納する要素 | 共有可能で、使用中は無効化する変更を禁止 | 使用中の範囲と検出方式、要素だけが外へ残る場合の所有者の生存、スライスへの適用 |
| イテレータの無効化 | 構造変更後、未終了の古い走査を再利用したらエラー | 具体的に無効化する操作、合成イテレータが終了済みの場合、直接格納した要素への共有との組み合わせ |
| 代入 | 右結合と結果の共有、左辺の形に応じた結び直し | 正確な括弧規則、一時値への代入、関数結果への `:=`、分解代入の対象の評価順 |
| 演算関数 | 加算は `__add__`、更新は `__assign__` 等へ展開 | copy・assign の利用者定義の範囲、規約と強制する仕様の境界、具体化失敗時のフォールバック |
