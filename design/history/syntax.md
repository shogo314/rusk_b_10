## プログラムの開始位置

トップレベルに実行する処理を直接書けるようにし、その処理を上から実行する。明示的な `main` の定義は必須にしない。コンパイラは必要に応じて内部のエントリーポイントへまとめられる。

関数や型もトップレベルに定義できる。小さな解答は処理を直接書き、大きな解答では `solve` などの関数へまとめられる。

```rusk
fn solve() {
    ...
}

in T: Int;
rep T {
    solve();
}
```

読み込んだファイルのトップレベル処理も、取り込んだ位置で実行する。読み込みはトップレベルに限定する。詳細は [標準ライブラリと入出力](../library.md) に記録する。トップレベル変数の可視範囲や初期化と捕捉の具体的な関係などは未決定。

## ループと回数指定

区間などを走査する `for` を基本とし、頻出する回数指定には `rep` を糖衣構文として用意する。

```rusk
for i in 0..N { ... } // 0 から N-1
rep N { ... }        // N 回繰り返す
rep i, N { ... }     // i は 0..N
rep i, L, R { ... }  // i は L..R
```

回数や区間の端点は、ループ開始時に一度だけ評価し、その時点の値で繰り返す範囲を固定する。端点のオブジェクトを共有して保持するだけではなく、元の変数の中身が途中で更新されても範囲が変わらないようにする。

整数区間の `for` と `rep` では、反復の進行を内部で管理し、ループ変数の中身の更新や結び直しが次の反復に影響しないようにする。ループ変数には反復ごとに独立した整数オブジェクトを渡す。

```rusk
let a := Vec<Int>();
rep i, 3 {
    a.push_back(i);
}
// a は [0, 1, 2]。後の反復で保存済みの整数は変わらない
```

これは整数区間の値の生成に関する規則であり、配列の `for` が既存の要素を共有する規則は維持する。毎回の実際の確保が必要かは、観測できる振る舞いを保って最適化できる。

走査順の逆転には `rev()`、走査する並びから先頭を含めて k 個ごとに要素を選ぶ操作には `step(k)` を用意する。区間だけでなく、配列などの走査にも適用できる方向とする。

```rusk
for i in (0..N).rev() { ... }   // N-1 から 0
for i in (0..N).step(2) { ... } // 0, 2, 4, ...
```

逆順反復の糖衣構文として `rrep` も用意する。`rrep i, N` は `(0..N).rev()`、`rrep i, L, R` は `(L..R).rev()` を走査する形を想定する。細かな構文は今後詰める。

`step` の引数の許容範囲や操作の組み合わせ、負の回数、開始位置が終了位置を超える場合などの詳細は未決定。

## while と無限ループ

`while cond { ... }` は反復のたびに条件を評価する。`loop { ... }` は `break` などで抜けるまで繰り返す。いずれも当面は値を返さない文として扱う。

本体を少なくとも一度実行し、その後に条件を評価する `do while` も用意する。基本の構文は `do { ... } while cond;` を想定する。

## ループの else

正常に終了するループには `else` を付けられるようにする。`for` の走査が尽きた場合や `while` の条件が偽になった場合など、`break` せずに終了したときだけ実行する。

```rusk
for x in a {
    if x == target {
        break;
    }
} else {
    // break せず走査を終えたときだけ実行
}
```

`rep`・`rrep` も対応する走査の糖衣構文としてこの規則に従う。β05のラベル付き中断とreturnの扱いは[ブロック式とラベル](../blocks-labels.md)に具体化した。

`while` にも `else` を付けられる。条件が最初から偽の場合も、`break` せず正常終了したものとして `else` を実行する。

```rusk
while cond {
    ...
} else {
    // 条件が偽になって終了した場合
}
```

`do while` にも `else` を設けるか、その場合の具体的な構文などは未決定。

## ループの中断と継続

`break` は最も内側のループを終了し、`continue` は最も内側のループの次の反復へ進む。

ループに名前を付け、対象のループを指定して中断・継続できるようにする。β05では次の構文を実装した。

```rusk
outer: for i in 0..N {
    for j in 0..M {
        if found(i, j) {
            break outer;
        }
    }
}
```

`continue outer;` は指定した外側のループの次の反復へ進む。有効な外側のラベルとの重複を拒否し、関数・クロージャの境界を越えない。有効範囲などの詳細は[ブロック式とラベル](../blocks-labels.md)を参照する。

## 比較の連鎖

`0 <= i < N` のように比較を連鎖できるようにする。隣り合う値を比較し、途中で偽になったら残りを評価しない。比較結果を次の比較のオペランドにする解釈はしない。

`a < f() <= b` では `a`、`f()` の順に評価し、中間の `f()` は一度だけ評価する。最初の比較が真のときだけ `b` を評価して次の比較を行う。中間のオブジェクトは既存の共有ルールに従って保持し、自動的な値のコピーは行わない。

各比較の真偽値は、その場で判定してから次の比較へ進む。通常の比較関数と短絡分岐に展開できるようにする。連鎖を許す比較演算子の厳密な範囲などは今後詰める。

## match

ガード条件（`Some(x) if 条件 => ...` のような形）の導入は保留する。ガード中だけ束縛を読む専用にする案も採用していない。必要な具体例が出た段階で再検討する。

値や構造に一致する分岐を選ぶ `match` を用意する。上から最初に一致した分岐だけを実行し、次の分岐へ勝手に進むフォールスルーは行わない。

```rusk
match query_type {
    0 => { ... }
    1 => { ... }
    _ => { ... }
}
```

パターン中の `_` は値を束縛せず何にでも一致するものとして扱う。選択肢を表す型の分岐を判定し、中身を分解できるようにする。分解した中身は共有と読むだけの制限を保つ。タプルなどを含むパターンの詳細は今後詰める。

`match` は文・式の両方で使える。式では全分岐の結果の型を揃え、必ずどれかの分岐に一致することを要求する。結果は自動コピーせず、選ばれたオブジェクトを共有する。

```rusk
let answer := match kind {
    0 => a,
    1 => b,
    _ => c,
};
```

文頭の `match` は文として解釈し、結果を使って式を続ける場合は丸括弧で囲む。文として使う場合にも一致を必須とするかは未決定。パターンの対応範囲、分岐の具体的な構文、網羅性を検査する方式などの詳細も今後詰める。

## 変数宣言

変数宣言には `let` を付ける。宣言時は型推論を基本とし、必要に応じて型を明示できる。`let` は不変を意味せず、宣言した変数の中身は変更可能とする。

```rusk
let a := 10;       // 型を推論して宣言
a := 20;           // 既存変数の指す先を変更
a = 30;            // 既存オブジェクトの中身を更新
let b = a;        // 独立したコピーを指す変数を宣言
let c: Int := 10;  // 型を明示して宣言。整数型名の表記は未確定
```

宣言時も共有とコピーを区別する。`let x := value;` は右辺のオブジェクトを共有し、`let x = value;` は右辺を一度評価してから再帰的なコピーを作り、その新しいオブジェクトを指す変数を宣言する。後者は `let x := copy(value);` と同じコピーの規約に従う。型を明示した `let x: T = value;` も使える。

`:=` だけでは新しい変数を宣言しない。宣言と既存変数の結び直しを明確に区別する。以前の例にある `a := ...` 形式の初回の変数導入は、`let a := ...` の省略された仮の表記として読む。

## 初期化なしの宣言

型を明示した場合は、`let answer: Int;` のように初期化せず変数を宣言できる。使用前に必ず初期化されていることをコンパイラが検査し、初期化前に読むことは禁止する。

初期化なしで宣言した後は、初回の `:=` で指すオブジェクトを設定する。`=` は既存のオブジェクトの中身を更新する操作なので、未初期化の変数には使えない。結び直しを禁止する指定（仮の `fixed`）があっても、最初の一度の初期化は許す。

```rusk
let answer: Int;
if cond {
    answer := 1;
} else {
    answer := 2;
}
wt answer;
```

制御フローを検査する厳密な範囲、ループや捕捉との関係などは未決定。初期実装では単純な制御フローに対応範囲を絞ることもできる。

## スコープと再宣言

変数名は宣言の後から見える。初期値の式を評価する段階では、宣言する新しい名前をまだ導入せず、同名の外側の変数があればそちらを参照する。未初期化宣言では宣言後から名前は見えるが、初期化前に読むことはできない。

ループ本体の変数は各反復で作り直し、前の反復のローカル変数を次の反復から名前で参照することはない。外側に `let x := 10;` がある場合、ループ本体の `let x := x + 1;` の初期値は毎回その外側の `x` を参照する。

ループ変数と本体直下の変数宣言は、重複判定では同じスコープとして扱う。`for x in a { let x := ...; }` は同名再宣言のエラーとする。名前の解決はコード上の位置で固定し、反復ごとに変数や捕捉環境の実体が作られることと区別する。

型名・関数名は変数名とは区別し、同じスコープなら定義順によらず参照できる。関数の相互再帰も許す。ただし名前が見えていても、必要な捕捉環境が用意される前の呼び出しはエラーにする。詳細は [関数とジェネリクス](../functions.md) に記録する。

`{ ... }` は文・式のどちらでも新しいスコープを作る。関数の引数はその関数本体から参照できる。ループ変数はそのループの本体だけで使え、ループ後やループの `else` からは参照できない。`match` のパターンで束縛した変数は、その分岐だけで使える。

内側で宣言した変数名は外側へ出ない。一方、そのスコープから返したり他の場所へ共有したオブジェクトは、既定の寿命の方針どおり引き続き使用できる。

内側のスコープでは、外側と同じ名前の変数を宣言できる。同じスコープでの同名変数の再宣言は禁止する。

内側の宣言が外側の同名定義を隠す場合に、コンパイル時に標準エラー出力へ警告を出せるようにする。変数以外の定義も対象として検討し、オプションで有効にできるものとする。オプション名や既定の設定、関数の候補探索などとの詳細な関係は未決定。

同じスコープでの型・変数の同名定義はエラーにする。同名関数はオーバーロードの規則で扱い、型名と同名の構築関数は意図した組み合わせとして許す。重複エラーでは両方の定義位置を示す。異なる種類の名前の衝突など、名前空間の詳細は今後詰める。

変数の型は宣言後に変わらない。`:=` による結び直しでも、異なる型のオブジェクトを指すようにはできない。

## ブロックと if の文と式

ブロックと `if` には文と式の両方を設け、置かれた構文上の位置で区別する。同じ波括弧を使い、式の位置ではブロックの末尾の式を結果とする。値を返す `if` は `else` を必須とし、両分岐の型を同じにする。結果は自動コピーせず、選ばれたオブジェクトの共有を保つ。

文頭の `{` や `if` は、それぞれブロック文・`if` 文として解釈する。その結果を使って式を続ける場合は、丸括弧で囲んで式であることを明示する。当面はこの規則を採用する。

```rusk
let x := { calc() + 1 };
let y := if cond { a } else { b };
({ ... })[i] = x;
(if cond { a } else { b }).sort();
```

β05では、ブロック式の末尾に式がなければUnitとする。値を返して継続するif式の分岐の型を一致させ、脱出する経路は結果の型から除外する。ループは値を返さず、名前付き関数の本体には明示的returnを使う。詳細は[追加合意](../blocks-labels.md)を参照する。

## 代入式と代入先

共有されたオブジェクトを返す関数呼び出しにも代入できるようにする。たとえば更新可能な共有を返す `get(a, i)` に対して `get(a, i) = 2` と書くと、返されたオブジェクトの中身を更新する。読むだけの制限はこの場合も適用する。

代入を右結合の式とし、結果は代入後の左辺のオブジェクトを共有する案を検討している。`a = b = 0` は `a = (b = 0)` と解釈でき、それぞれの中身を更新し、両変数を新たに共有させることはない。`a := b := x` は両変数を `x` に結び直す。

文全体が代入式なら括弧を不要とし、条件式などの別の式に代入を埋め込む場合は括弧を要求する方向で考える。また、`a + b = 2` のような形には左辺の括弧を要求する案がある。具体的な構文規則、独立した一時オブジェクトへの代入を許すかなどは未決定。評価順序は左から右とする。

関数呼び出しの結果に対する `=` は中身の更新であり、呼び出し元の変数や配列要素の指す先を変更する操作ではない。関数呼び出し結果に `:=` を適用できるかは未決定。

独立した一時オブジェクトへの代入は、基本的には必要ないと考えている。ただし、これを禁止するために特別な判定や仕組みを設ける必要があるかは、設計がより具体的になった段階で検討する。現時点では許可・禁止の決定を保留する。

## タプルと分解

タプルによる複数の値の返却と、`let (a, b) := pair` のような分解宣言を用意する。タプルへの格納と分解宣言では、自動コピーせず共有を保つ。

既存変数への分解代入は、`(a, b) := pair` で指す先を変更し、`(a, b) = pair` で中身を更新する。分解する構造と各要素の型が対応することを検査する。具体的な型検査規則は今後詰める。

分解代入では右辺を一時保存してから左辺に反映し、`(a, b) := (b, a)` や `(a, b) = (b, a)` による交換を実現する。`:=` では右辺の共有を保持し、`=` では更新前の値を再帰的にコピーして保存する。`=` で保存と代入のために2回コピーする実装も許容する。左辺の対象を確定する順序などの詳細は未決定。

分解で不要な要素を `_` で読み捨てる案を検討する。分解パターンや代入先では読み捨て、式では無名関数のプレースホルダーとすることで区別する方向が考えられる。正確な構文規則は未決定。
