## 標準ライブラリの利用

標準ライブラリは、原則として明示的な読み込み宣言なしで使えるようにする。基本機能と高度な機能で読み込みの要否を覚え分ける必要を減らす。

使わなかった機能が生成コードや実行時コストを増やさないことを目指す。実現方式とコンパイル時間への影響は、実装時に検討する。

自作ライブラリは `include "graph.rusk";` のように、別ファイルの内容をその場所へ取り込む方式とする。ファイル名から自動で名前空間を作らず、読み込んだ型や関数をそのまま使えるようにする。

パスは読み込み元のファイルを基準に解決し、同じファイルは一度だけ取り込む。提出用には依存先を含めた単一の C++ コードなどへ変換する。

診断では取り込み後の位置だけでなく、元のファイル名とソース位置を示せるようにする。

`include` はトップレベルに限定する。読み込み先のトップレベル処理も取り込んだ位置に配置して実行する。同じファイルは一度だけ取り込むため、その処理も一度だけ配置される。関数内やループ内には `include` を書けない。

読み込みの依存関係を DAG に限定し、ファイルを先頭から読み、`include` の位置で DFS 順に展開する案を検討している。未訪問・展開中・展開済みを区別し、展開中のファイルへ再到達した場合は循環エラー、展開済みなら省略する。循環エラーでは経路と各 `include` のファイル名・ソース位置を示す方向とする。

名前の衝突や標準ライブラリとの同名定義、同一ファイルの判定、依存関係の展開方式の最終確定などは未決定。

## 名前の表記規則

標準ライブラリの実装では、内側の定義で外側の同名定義を隠す書き方を避ける。利用者のコードでは許される名前隠しも、標準ライブラリの記述方針としては行わない。同名関数のオーバーロードは名前隠しと区別する。

標準ライブラリとドキュメントでは、変数・引数・関数は `snake_case`、型は `PascalCase`、定数は `UPPER_SNAKE_CASE` とする。型引数は `T` のような短い大文字、または `Value` のような `PascalCase` とする。

これらは命名の規約であり、利用者の識別子をコンパイラで制限するものではない。

## 標準ライブラリの名前と呼び出し方

メソッド形式の呼び出しは、対象を第1引数に渡す関数呼び出しの糖衣構文とする。たとえば `a.sort()` は `sort(a)` に相当する。メソッド形式の名前解決などの詳細は未決定。

標準ライブラリの基本語彙として、要素数には `len`、取得には `get`、更新には `set` を使う。

配列の末尾への追加は `push_back`、末尾からの取り出しは `pop_back` とする。

コンテナや操作の性質から追加位置が明らかな場合は、単に `push` を使う。位置の明示が必要な場合は、`push_back` のように名前で位置を示す。他のコンテナでの取り出しの名前など、個別の対応は未決定。

共通の名前を使うことと、取得時の共有・コピーなどの振る舞いは別途区別して設計する。

更新する操作と新しい結果を返す操作は、`sort` / `sorted` のように分かりやすい名前の対を採用できる。ただし、新しい結果が内側まで独立するかは各 API の規則に従う。すべての操作に対になる名前を用意することは求めず、必要に応じて `copy` と組み合わせる。

存在を調べる操作には `contains` を用意する。位置を探す操作を `find` とするか `index` とするかは未決定。

β06では最小値の`<?`・最大値の`>?`と、更新の`<?=`・`>?=`を実装する。`chmin` 関数を併せて用意するかは未決定。

区間は半開区間に統一する。`0..N` のような記法で区間を表し、それを関数の引数として渡す案を検討する。区間を表す値と、配列の一部を参照するスライスとの関係は未決定。

整列済み列で、指定した値以上となる最初の位置を探す操作は、ひとまず `bisect_left` を採用する。指定した値より大きくなる最初の位置を探す対の操作の名前は未決定。

真偽値を返す操作は、性質の判定に `is_sorted` や `is_prime` のような `is_*`、存在の判定に `contains`、全要素・いずれかの条件判定に `all`・`any` を基本語彙として使う。

値と位置を返す操作は名前で区別する。たとえば最小値は `min`、最小値の位置は `argmin` とする。

セグメント木の区間に対する汎用演算の集計には `prod` を使う。

ソートは比較関数による順序指定と、キー関数による順序指定の両方に対応する。`sort_by_comp`・`sort_by_key` のように名前を分けるか、単一の関数にまとめるかは未決定。

`sort`・`sorted` は安定ソートを既定とし、比較上同値の要素は元の順序を維持する。安定性を要求しない場合に使う `sort_unstable` も用意する。具体的なアルゴリズム、計算量と追加メモリの保証、非更新版などの API の範囲は未決定。

通常の共有型配列の `sorted` は、外側の配列だけを新しく作り、要素のオブジェクトは共有する。元の並び順は変えないが、結果の要素の中身を更新すると元の対応する要素にも変更が見える。読むだけの制限も維持する。

```rusk
let a := [3, 1, 2];
let b := a.sorted();
b[0] = 9;
// a は [3, 9, 2]、b は [9, 2, 3]
```

完全に独立した結果が必要なら `let b := copy(a); b.sort();` のようにコピーを明示する。直接格納する配列や `Str` への適用と結果の型などは今後詰める。

キー関数を使うソートでは、並べ替え前の順序で各要素につき一度だけキー関数を評価し、返されたキーをその都度再帰的にコピーして保存する。すべてのキーを用意した後、その保存済みのキーで要素を並べ替える。比較のたびにキー関数を呼び直すことはしない。

キー関数が元の要素への共有を返しても、保存したキーは独立させる。キー関数自体による入力の更新や構造変更の扱いなどの詳細は今後詰める。`sort_by_key` などの正式な関数名は引き続き未決定。

ソートの比較関数は `Bool` を返し、「左の要素が右の要素より小さい（前に置かれる）」を表す。たとえば `(a, b) => a < b` や `_ < _` のように書ける方向とする。3種類の順序を返す関数は基本の比較関数として要求しない。

比較関数は厳密弱順序を満たすものとし、`comp(a, b)` と `comp(b, a)` の両方が偽なら、並べ替え上は同値として扱う。これは必ずしも `a == b` と同じ意味ではない。`<=` のように同じ値同士でも真になる関数は、この比較規約を満たさない。必要な規則をドキュメントで説明し、規約違反時の検査・診断などの詳細は今後詰める。

## 入出力の書き方

入力は試作の `in` を使う専用構文を採用する方向とする。型を指定して変数を宣言しながら読み込み、配列は長さを指定してまとめて読めるようにする。出力には `wt` を使う書き方を採用する方向とする。

```rusk
in N: Int;
in A(N): Vec<Int>;
wt A;
```

`in A(N): Vec<Int>;` は、宣言と読み込み関数の呼び出しの糖衣構文とし、展開時に読みたい型を明示する。たとえば `let A: Vec<Int> := __read__::<Vec<Int>>(N);` のような形を想定する。型引数の具体的な構文や関数解決の詳細は未決定。

将来的には、代入先や呼び出し側が期待する戻り値の型から、関数の型引数などを推論することにも対応したい。入力構文の展開で型を明示する方針は、この将来の推論を禁止するものではない。推論の範囲や、戻り値の型だけが異なる関数のオーバーロードを許すかは別途検討する。

`wt x;` は `__write__(x); __write__('\n');` の糖衣構文とする。`__write__` 自体は末尾の改行を自動追加せず、`wt` の展開で改行を別に出力する。実際の値の出力は型ごとの関数に委ねる。真偽値の標準出力は、真を `Yes`、偽を `No` とする。

複数項目の `wt x, y;` は項目間に空白を1つ入れ、最後に改行する。引数なしの `wt;` は改行だけを出力する。

```rusk
wt x, y;
// __write__(x);
// __write__(' ');
// __write__(y);
// __write__('\n');
```

配列の `__write__` は要素間だけに空白を入れ、末尾の空白や改行は付けない。`wt len(A), A;` のように他の項目と同じ行に組み合わせられる。空配列を項目として渡した場合も、項目間の区切りの空白は出力する。

多次元配列でも行や次元の境界で改行しない。各要素の `__write__` を再帰的に呼び、各段の要素間を空白で区切る。`wt` が最後に付ける改行だけとする。たとえば `wt [[1, 2], [3, 4]];` は `1 2 3 4` と改行を出力する。空の内側の配列がある場合も、外側の要素間の区切りは省略しない。

複数項目の入力は左から順に、個別の宣言と読み込みへ展開する。同じ型の `in N, M: Int;` は `N`、`M` の順に別々に読み込む。`in A(N), B(M): Vec<Int>;` もそれぞれの引数を使って順に読み込む。

```rusk
in N: Int, A(N): Vec<Int>;
// let N: Int := __read__::<Int>();
// let A: Vec<Int> := __read__::<Vec<Int>>(N);
```

先に宣言して読み込んだ値を、後の項目の長さなどの指定に使える。型や引数の指定は各読み込みに適用し、複数項目をまとめた特別な入力処理にはしない。

通常の `in` とその基礎となる読み込みは入力が存在する前提とし、入力終端・形式不正・整数の範囲外ではソース位置を示して異常終了する。診断は元のファイル名を含む既定のエラー方針に従う。

EOF まで読む用途には、正常な終端で `None`、読めた場合に `Some(value)` を返す別の関数を用意する。名前の候補は `try_read::<Int>()`。形式不正や範囲外まで `None` にせず、エラーとして正常な終端と区別する。

通常の入力は空白区切りを基本とする。`in s: Str;` は先頭の空白を読み飛ばして次の空白までを読み、`in c: Char;` は先頭の空白を読み飛ばして1文字を読む。

配列の読み込みは、最初の引数を外側の長さとして使い、残りの引数を各要素の読み込みへ渡す。`in grid(H, W): Vec<Vec<Int>>;` は、H 個の行をそれぞれ長さ W の配列として読む。三次元以上も同じ規則で再帰的に扱う。

```rusk
__read__::<Vec<Vec<Int>>>(H, W)
// H 個の要素を、それぞれ __read__::<Vec<Int>>(W) で読む
```

タプルの引数なしの読み込みは各要素を左から順に読む。`in edges(M): Vec<(Int, Int)>;` は M 組の整数を読む。行ごとに長さが異なる入力は、まずループ内で長さを読みながら組み立てる形で扱う。タプルへの読み込み引数の指定や長さが負の場合などの詳細は未決定。

空白を含む行や空行には `read_line()` を用意し、現在の入力位置から行末までを読み、末尾の改行は結果に含めない。自動で次の行へ進めたり、空行を読み飛ばしたりしない。

```rusk
in n: Int;
let s := read_line();
// 整数の直後が改行なら、s は空文字列
```

トークン入力は、トークンの後ろの区切りの空白を消費しないものとして行入力と組み合わせる。型名や EOF 用の関数名の正式な表記、複数要素の途中で EOF に到達する場合、改行コードや行入力の EOF の扱い、タプルなど他の型の出力の詳細は未決定。多次元配列を自動改行しない方針は上記のとおり。
