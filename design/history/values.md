## 値の変更に関する設計方針

共有するオブジェクトの中身を、変数・関数引数・要素などを通じて更新できるようにする。

たとえば `sort(A)` や `push_back(G[v], u)` のように、指定した配列やその要素を更新する。各操作の詳細はコンテナとライブラリのノートを参照する。

指す先を変える代入と、対象のオブジェクトを保って中身に値をコピーする代入を区別する。演算子は、それぞれ `:=` と `=` とする。`=` には値のコピーに応じたコストがかかり得る。詳細な構文規則は検討を続ける。

通常の配列では、要素を別の変数から共有して変更することも、要素が指す先を変更することも可能にする方向で考える。仮の構文では `x := A[i]`、`x = 10`、`A[i] := y` のような操作を想定する。

高速化を視野に入れ、要素を直接格納し、要素が指す先を変更できない配列も別に設ける。要素への共有と中身の更新を許し、その共有の使用中は参照先を無効にする構造変更を禁止する。詳細と未決定事項は [配列とスライス](../collections.md) に記録する。

引数はデフォルトで呼び出し元の対象を更新可能とし、明示的な指定で読むだけに制限できるようにする。競技中の記述を簡潔にすることを意図する。指定の構文は未決定。

読むだけに制限した引数から、要素や別名を通じて元のデータを変更することも禁止する。内側の配列にも制限を引き継ぎ、更新可能な引数への引き渡しによる変更も許さない。`copy` で作った独立したコピーは変更できる。これは、その引数を経由した変更の制限であり、他の経路からもオブジェクトが変更されないことまで保証するかは未決定。

`=` は、多次元配列の内側も含めて再帰的に値をコピーする。コピー後の値を変更しても、コピー元には影響しないことを意図する。

`=` が同一性を保つのは、左辺が直接指すオブジェクトだけとする。内側には新しいオブジェクトを作って再帰的にコピーし、以前の内側のオブジェクトは更新しない。

たとえば次の操作後、`B` は `[[1, 2]]` になり、`row` は以前の行 `[0, 0]` を指し続ける。`alias` は `B` と同じ外側のオブジェクトを指すため、`[[1, 2]]` が見える。以下の構文は仮のもの。

```rusk
let B := [[0, 0]];
let alias := B;
let row := B[0];
B = [[1, 2]];
```

関数の引数は、呼び出し時に渡されたオブジェクトを共有する。引数に対する `=` はそのオブジェクトの中身を更新するため、呼び出し元にも変更が見える。`:=` は関数内の引数が指す先だけを変更し、呼び出し元の変数が指す先には影響しない。このルールは整数にも適用する。

```rusk
fn f(x: Vec<int>) {
    x = [1, 2];
    x := [3, 4];
}

let A := [0];
f(A);
// A は [1, 2]

fn reset(x: int) {
    x = 0;
}

let a := 10;
reset(a);
// a は 0
```

`copy(x)` は、`x` の内側まで再帰的にコピーした、新しい独立したオブジェクトを返す。宣言時には `let a = x;` と書いても同じコピーを作れる。`let a := x;` は共有する。

`a := copy(b)` は新しいコピーに `a` を結び直す。以前の `a` を共有していた変数は古いオブジェクトを指し続ける。`a = b` は既存の `a` の中身を更新するため、共有している変数からも更新が見える。どちらも再帰的なコピーのコストがかかり得る。

ライブラリ作成時の基本規約として、数値などの算術演算は新しい独立したオブジェクトを返す。配列の連結は外側だけを新規作成し、内側の要素は共有する例外とする。標準の加算では、たとえば `c := a + 0` の後で `c` の中身を更新しても、`a` には影響しない。言語が演算関数の結果に独立性を強制・検査するものではない。最適化は実際の関数の振る舞いを保ち、演算子の見た目だけを根拠に独立性を仮定しない。

複合代入は更新専用の関数へ展開できるようにする。`a += b` は `__iadd__(a, b)` を優先し、適用可能な定義がない場合は `a = a + b` 相当の処理へ自動的に展開する。左辺は一度だけ評価して更新対象を保持し、右辺を評価した後に操作を行う。

ライブラリ作成時の規約として、更新専用の関数は既存の対象を更新し、共有先にも変更が見えるようにする。`__iadd__` は配列や文字列のその場での追加など、通常の演算と代入の組み合わせより効率的な実装を持てる。`a := a + b` は別の操作であり、変数の指す先だけを演算結果に変える。

複合代入の式の結果は、更新後の左辺の対象を共有したものとする。更新専用関数に戻り値は要求せず、その戻り値を複合代入の結果としては使わない。

単純な変数で表すと、`a += b` は `{ __iadd__(a, b); a }`、専用の定義がなければ `{ __assign__(a, __add__(a, b)); a }` に展開するイメージとする。実際の展開では左辺を一時変数に共有して保持し、右辺も一度だけ評価する。展開用の一時変数名は利用者の名前と衝突しないものとする。

他の複合代入にも同じ方式を使う方向とする。曖昧な候補や具体化に失敗した候補を自動展開とどう扱い分けるかは未決定。

関数の `return` は自動的にコピーせず、返すオブジェクトの共有を保つ。たとえば配列の要素を返した場合、戻り値を通じた中身の更新は元の要素にも反映される。独立した値を返す場合は `return copy(...)` と明示する。

関数内で作ったオブジェクトも、戻り値として返した後まで使用できる。寿命を実現する管理方式は未決定。

値の寿命が関数の外に及べることは、簡単にコードを書くために重要な性質とする。関数内で作った値を外に渡す際、利用者が寿命を延ばすための特別な管理をしなくても使える設計を重視する。

変数にはスコープがあってよい。変数名を使える範囲と、その変数が指すオブジェクトの寿命は区別する。変数名がスコープを外れても、戻り値や別の変数などを通じて使われるオブジェクトは引き続き使用できる。スコープと再宣言の規則は syntax.md に記録する。

読むだけの引数から要素や別名を返す場合は、戻り値にも読むだけの制限を引き継ぐ。関数から返すことで制限を迂回することはできない。戻り値の型や制限をどう表記・検査するかは未決定。

配列を `for x in A` で走査するとき、ループ変数 `x` は現在の要素を共有する。`x += 1` などの中身の更新は元の要素にも反映される。`x := x + 1` のような結び直しはループ変数の指す先だけを変更し、配列の要素が指す先は変更しない。以下の構文は仮のもの。

```rusk
let A := [1, 2, 3];
for x in A {
    x += 1;
}
// A は [2, 3, 4]
```

読むだけの配列を走査するときは、ループ変数にも読むだけの制限を引き継ぐ。高速化を意識した配列での要素の共有と、走査中の構造変更の規則は [配列とスライス](../collections.md) に記録する。

通常の配列への要素の追加は、渡されたオブジェクトをコピーせず共有する。たとえば `push_back(A, x)` の後で `x` の中身を更新すると、追加された要素からも更新が見える。独立させたい場合は `push_back(A, copy(x))` と明示する。

同じ初期値で配列を埋める場合は、各要素に初期値の再帰的なコピーを作る。各要素は初期値のオブジェクトからも、他の要素からも独立し、一つの要素の更新が他の要素に伝わらないようにする。初期化の構文は未決定。

## 評価順序と演算の捉え方

式は原則として左から右に評価する。関数の引数も左から右に評価する。代入は左辺を評価して対象を確定し、右辺を評価した後で更新する。

右結合と評価順序は区別する。たとえば `a[i()] = b[j()] = value()` は、`i()`、`j()`、`value()` の順に評価し、更新は内側の `b`、外側の `a` の順に行う。

プログラムを記述する最も抽象的な段階では、二項演算などを基本的に関数呼び出しとして整理し、演算子表記をその糖衣構文と捉える。最適化後の表現や実装を、実際の関数呼び出しに限定するものではない。

`a + b` は `__add__(a, b)` の糖衣構文として扱う。加算の型ごとの定義も、この関数のオーバーロードとして整理する。演算用の関数は、型の外に通常の関数として定義できる。独立した結果を返すことはライブラリ作成時の規約であり、演算子構文自体がコピーや独立性を付加することはない。

`a = b` の中身の更新は `__assign__(a, b)` に対応させる。代入式の結果は更新対象の共有とし、複合代入の自動展開でもこの関数を使う。利用者による直接呼び出しや定義の範囲、他の操作の正式な関数名などは未決定。

`:=` のように変数や配列要素の指す先を変更する操作では、更新対象そのものを扱う必要がある。短絡評価を伴う論理演算や不在時の選択では、右辺を必要なときだけ評価する必要がある。これらを通常の関数とどう区別・統合するかは未決定。

引数を左から右に評価するとき、共有するオブジェクトの値を各評価時点で自動的に保存することはしない。後続の引数の評価で同じオブジェクトが更新されると、先に評価した引数からも更新が見える。

```rusk
let a := 1;
f(a, (a = 2));
// f の呼び出し時には両引数が同じオブジェクトを共有し、中身は 2
```

評価時点の値を独立して保持したい場合は `f(copy(a), (a = 2))` のようにコピーを明示する。
