## 整数の基本方針

標準の `int` は符号付き64ビット整数とする。通常の整数演算でオーバーフローした場合はエラーにする。実行モードによって暗黙に折り返す動作には切り替えない。

意図的な折り返しが必要な場合は、明示的な操作を用意する。関数名などの具体的な表記は未決定。安全性のための検査を含めても競技プログラミングで十分な実行速度を目指し、実際の性能は実装時に測定する。

整数除算と剰余は、負数を含む場合も Python の整数除算・剰余に寄せる。商は数学的な商を負の無限大方向に丸め、剰余はゼロまたは除数と同符号とする。たとえば `-7 / 3` は `-3`、`-7 % 3` は `2`、`7 / -3` は `-3`、`7 % -3` は `-2` とする。ここで `/` は仮の整数除算の表記であり、具体的な演算子の表記は別途決める。

ゼロ除算の扱いは未決定。最小値を `-1` で割る場合はオーバーフローをエラーにする方針と整合させる必要があり、詳細は今後詰める。

## 広い整数型

符号付き128ビット整数 `Int128` と、メモリが許す範囲で任意精度の整数を扱う `BigInt` を用意する方向とする。通常は基本の64ビット整数を使い、必要な計算だけ広い型へ明示的に変換する。

`Int128` の範囲外の算術演算はエラーとする。除算・剰余は両型とも基本の整数と同じく Python 寄りの規則とする。

整数型間の変換は明示し、狭い型へ変換した結果が範囲に収まらなければエラーにする。

```rusk
let product := Int128(a) * Int128(b);
let large := BigInt(a) ** 100;
```

型名の最終確定、初期実装の対応範囲、ビット演算やシフトを各型へどこまで適用するかなどは未決定。64ビット整数のシフト規則を、そのまま全整数型へ適用するものではない。

## 整数リテラルの型

整数リテラルは、期待される整数型が文脈から分かる場合はその型の値として扱う。文脈がなければ基本の符号付き64ビット整数とする。これは既存の型付き変数の暗黙変換ではなく、リテラル自体の型決定として区別する。

```rusk
let x := 1;             // 基本の整数型
let y: Int128 := 1;     // Int128 のリテラル
let z := BigInt(a) + 1; // 1 を BigInt として扱う
```

決まった型の範囲にリテラルが収まらなければコンパイルエラーとする。オーバーロード候補が複数ある場合の優先順位、負数と単項マイナスの境界、型指定用の表記などの詳細は未決定。

## 累乗

累乗演算子は `**` とする。`^` はビット XOR のままとする。`**` は右結合で、底に付く単項マイナスより優先する。

```rusk
2 ** 3 ** 2 // 2 ** (3 ** 2)
-2 ** 2     // -(2 ** 2)、結果は -4
```

整数同士の累乗は整数を返す。指数は非負に限定し、負の指数はエラーにする。`0 ** 0` は `1` とし、結果が整数の範囲を超える場合はエラーにする。実数の負の指数を扱う場合は `Float` へ明示変換する方向とし、浮動小数点数の累乗の詳細は今後詰める。

剰余付き累乗には、中間値全体を構築せずに計算する `pow_mod(a, b, mod)` を用意する。引数の許容範囲や剰余の詳細などは未決定。

## ビット演算とシフト

`&`・`|`・`^`・`~` は符号付き64ビット整数の2の補数のビット列に対する操作とする。左シフトは下位を `0` で埋め、上位にはみ出したビットを捨てる。右シフトは符号を保つ算術右シフトとする。左シフトのビットのはみ出しは、通常の算術演算のオーバーフローエラーと区別する。

負のシフト量は逆方向へのシフトとして扱う。`a << -k` は `a >> k`、`a >> -k` は `a << k` に相当する。

シフト量が大きいことを理由にエラーにはしない。方向を決めた後、1ビットずつ繰り返し動かした場合と同じ結果とする。左方向に64ビット以上動かした結果は `0`。右方向に64ビット以上動かした結果は、元の値が非負なら `0`、負なら `-1` とする。シフト量を64で剰余にする仕様ではない。

```rusk
8 << -1   // 4
-8 << -1  // -4
8 >> -1   // 16
1 << 64   // 0
-8 >> 64  // -1
```

シフト量が整数の最小値でもこの規則を適用する。実装で方向を反転する際の符号反転のオーバーフローを、利用者のエラーにしない。論理右シフトを別途用意するかは未決定。

## ビット列の型

整数とは用途の異なるビット列型として、コンパイル時に長さを指定する `Bits<N>` と、実行時に長さを決める `BitVec` を用意する方向とする。具体的なジェネリクスの構文や、初期実装で対応する範囲は未決定。

基本操作は、`bits[i]` で `Bool`、`len(bits)` でビット数、`count(bits)` で立っているビット数を得る形とする。ビット演算にも対応する。

シフトはゼロ埋めとし、負の量は逆方向へ動かす。1ビットずつ繰り返した場合と同じ挙動とし、ビット数以上動かせばすべてゼロになる。`Int` の符号を保つ右シフトとは区別する。

`Bits<64>` は整数と同じ64ビットの表現を利用できる方向で考える。整数とビット列を言語上は別の型として扱い、暗黙変換はしない。ビット列を保った明示変換を低コストで実現する案がある。変換の表記、数値変換との区別、共有と更新の関係は未決定。

`bits[i]` は独立した `Bool` を返し、元のビットへの更新可能な共有は返さない。取得した値を変更しても元のビット列には影響しない。元のビットの更新には `set(bits, i, value)`（メソッド形式なら `bits.set(i, value)`）を使う。ビットへの特殊な参照型は当面設けない。

`bits[i] = value` は取得した独立した値への代入となり、元のビットを更新する操作にはしない。この書き方を禁止・警告するかは、一時オブジェクトへの代入の扱いと併せて保留する。

添字は最下位ビットを `0` とする。負の添字は末尾から数え、`bits[-1]` は最上位ビットを指す。範囲外はエラーにする。走査は添字順、つまり最下位ビットから行い、文字列として表示する場合は通常の二進表記に合わせて最上位ビットから表示する。

ビット列同士の `&`・`|`・`^` は同じ長さを要求する。`Bits<N>` 同士の長さの不一致はコンパイルエラー、`BitVec` 同士の長さの不一致は実行時エラーとする。暗黙のゼロ埋めや切り詰めは行わず、長さを合わせる操作は明示する。

固定長と可変長の混在、長さを変更する操作とその際に残す側、可変長の構造変更、表示時の先頭のゼロや接頭辞などの詳細は未決定。

## 浮動小数点数の基本方針

基本の浮動小数点型は64ビットの `Float` とする。`1.5` のような小数リテラルは `Float` として扱う。

整数からの変換は `Float(n)` のように明示する。整数同士の `/` は整数除算のままとし、実数の商が必要なら `Float(a) / Float(b)` と書く。

```rusk
let probability := Float(success) / Float(total);
```

既定の出力は指数表記を使わず、小数点以下15桁で丸め、小数点以下の末尾の `0` と不要な小数点を除く。たとえば `1.5` は `1.5`、`2.0` は `2` と出力する。十分小さい値が丸めによって `0` になることは許容する。

大きな値も、整数部分を省略せず通常の十進表記で出力する。整数部分の桁数が増えて出力が長くなることは許容し、値の大きさを理由に指数表記へ自動で切り替えない。

指数表記で出力する手段も用意する。出力の精度も明示的に指定できるようにする。具体的な API、丸め方式、負のゼロの表示などは未決定。

`Float` から `Int` への明示変換 `Int(x)` は、小数部分を捨ててゼロ方向に丸める。たとえば `Int(1.9)` は `1`、`Int(-1.9)` は `-1` とする。整数除算の負の無限大方向への丸めとは区別する。

変換後の整数が `Int` の範囲に収まらない場合、および `NaN`・無限大からの整数変換はエラーにする。

浮動小数点数のゼロ除算、無限大・`NaN` の演算や比較、`floor`・`ceil`・`round` などの詳細は未決定。

## 文字列の基本方針

基本の文字列は変更可能な `Str` 型とし、ASCII を前提とする。

Unicode 対応は当面の基本型に含めず、ライブラリが充実した段階で専用の型を設ける方向とする。

ASCII の1文字を表す `Char` 型を設ける。文字リテラルは `'a'` のように書き、文字列リテラル `"a"` と区別する。

`Char - Char` は `Int` の差を返す。`Char + Int`・`Char - Int` は `Char` を返し、結果が ASCII の範囲（0〜127）を超える場合はエラーにする。これは暗黙の型変換ではなく、型の組み合わせごとに定義する演算とする。整数型名の正式な表記は引き続き別途決める。

`Str` の要素アクセスは、高速化を意識した「要素の指す先を変更できない配列」と同様に扱う。取得した文字への共有を許し、その中身の更新は元の文字列に反映する。要素の結び直しは禁止し、共有の使用中は参照先を無効にする構造変更をエラーにする。詳細は [配列とスライス](../collections.md) に記録する。

ASCII 範囲外の入力や値の扱いなどは未決定。

## ユーザー定義型

名前付きフィールドを持つ型を `struct` で定義できるようにする。以下の詳細な表記は今後詰める。

```rusk
struct Point {
    x: Int;
    y: Int;
}
```

通常のフィールドは、既存の共有ルールに従う。`let x := p.x` はフィールドのオブジェクトを共有し、`x = 10` は元のフィールドの中身にも反映される。`p.x := y` はフィールドの指す先を変更する。

`copy(p)` はフィールドも再帰的にコピーする。`p = q` は外側の `p` の同一性を保ち、内側のフィールドには新しい再帰的コピーを作る。読むだけの制限はフィールドとその別名にも引き継ぐ。

構築は `Point { x: 1, y: 2 }` のようにフィールド名を指定する形を基本とする。指定したオブジェクトは自動コピーせずフィールドで共有する。独立させたい場合は `Point { x: copy(a), y: copy(b) }` のようにコピーを明示する。

通常の関数からこの構築式を返して、用途に合った構築処理を定義できる。型名と同じ名前の関数を定義し、通常の関数と同じ引数・戻り値・共有のルールで呼び出せるようにする。

```rusk
fn Point(x: Int, y: Int) -> Point {
    return Point { x: x, y: y };
}

fn Point() -> Point {
    return Point { x: 0, y: 0 };
}

let p := Point(1, 2);
let origin := Point();
```

フィールドを指定する構築式を、実際にオブジェクトを作る基本操作とする。引数なしで構築する関数を定義しなければ、`Point()` は使えない。フィールドの公開範囲、省略・重複したフィールドの扱い、型名と関数名の名前解決の詳細などは未決定。

β02で実装した構築・コピー・フィールド操作と現段階の制限は、利用者向けの [β02の説明](../../docs/reference/records.md) に記録する。

## 型引数を持つユーザー定義型

利用者も型引数を持つ `struct`・`enum` を定義でき、型引数ごとに具体化する。まず型引数を基本とし、整数や関数を受け取る引数の具体的な構文は引き続き別途検討する。

```rusk
struct Pair<A, B> {
    first: A;
    second: B;
}

enum Option<T> {
    Some(T),
    None,
}
```

`Pair<Int, Str>` のように型引数を明示できる。構築時に省略した型引数をどこまで推論するかや、具体的な構文の詳細は未決定。

## 再帰的な型

木などを表すため、再帰的なユーザー定義型を許す。利用者がポインタ型を明示しなくても、既存の共有の仕組みでノードを扱える方向とする。

```rusk
struct Node {
    value: Int;
    children: Vec<Node>;
}
```

再帰的な型を定義できることと、実際のオブジェクトの共有に循環を作れることは区別する。循環した共有の可否は優先度を下げて保留し、禁止も採用も現時点では決めない。親付きの木など具体的に書きたいコードと寿命管理方式を検討するときに、コピー・比較・ハッシュの扱いも併せて判断する。初期段階ではノード番号と配列で関係を表す方法も使える。

## 公開範囲とファイルの境界

ファイルの境界を、そのまま名前や公開範囲の境界にはしない。ファイルを分割・結合したこと自体でアクセス権が変わる設計を前提にしない。

Rusk は競技プログラミング用の言語であり、内部実装を非公開にする機能の優先度は高くない。非公開指定やモジュールの導入、公開範囲の具体的な規則は保留とする。デフォルトの公開範囲や、モジュール単位のアクセス制限を採用したという意味ではない。

## ユーザー定義型のコピーと比較

`struct` には、全フィールドを再帰的にコピーする機能を基本機能として用意する。

等値比較と大小比較は、明示的に指定した場合に自動生成する。等値比較は全フィールドが等しいかで判定し、大小比較はフィールドの宣言順の辞書順とする。フィールドの型にも必要な操作があることを要求する。フィールドを定義しただけで、自動的に比較可能になるものではない。

独自の比較が必要な場合は、演算用の関数を定義できるようにする。自動生成を指定する構文、等値比較と大小比較の指定の分け方、自動生成と手動定義の衝突時の扱いなどは未決定。

## ハッシュ

整数・文字・文字列などの基本型には、標準でハッシュを用意する。配列・タプルは、各要素がハッシュ可能なら、要素のハッシュを組み合わせてハッシュ可能とする。

`struct` は明示的に指定した場合に、全フィールドのハッシュを組み合わせる処理を自動生成する。比較の自動生成と同様に、フィールドを定義しただけで自動的にハッシュ可能にはしない。

`a == b` ならハッシュ値も同じになることを要求する。異なる値のハッシュが衝突することは許される。独自の等値比較を定義した場合は、それに整合するハッシュも定義する必要がある。

具体的な関数名、戻り値の型、自動生成の指定構文、ハッシュのアルゴリズムや乱数化、独自の等値比較と自動生成の組み合わせを検査する範囲などは未決定。

## 引数なしの構築と初期値

自然な初期値がある型には、`T()` で引数なしに構築する手段を用意する。すべての型に引数なしの構築を要求することはしない。ユーザー定義型にも、引数なしで構築する処理を定義できるようにする。

| 構築 | 初期値 |
|---|---|
| `Int()` | `0` |
| `Bool()` | 偽 |
| `Str()` | 空文字列 |
| `Vec<T>()` | 空配列 |
| 辞書・集合の引数なし構築 | 空のコンテナ |

型名の未確定部分や構築の詳細は別途決める。ユーザー定義型の構築は、同名の通常の関数とフィールドを指定する構築式を使う既定の方針に従う。

## 値の比較

`==` は同じオブジェクトを共有しているかではなく、中身の値が等しいかを比較する。配列やタプルの要素も値として比較し、独立したコピーでも中身が等しければ等しいとする。

配列・タプル・`Str` の大小比較は辞書順とする。先頭から最初に異なる要素で順序を決め、一方が他方の接頭部分なら短い方を小さいとする。要素の比較が必要なため、対応する要素の型でその比較が可能であることを要求する。

異なる型同士を比較するための暗黙の型変換は行わない。同じオブジェクトを共有しているかを調べる専用操作を設けるかは未決定。

## 型変換と条件式

暗黙の型変換は原則として行わない。条件式では例外として、暗黙の `bool` 変換を許す。

整数は `0` を偽、それ以外を真とする。コンテナは空なら偽、それ以外は真とする。

真偽値を整数として計算する暗黙の変換は、この例外に含めない。論理演算子や否定での変換、その他の型の真偽値解釈などの詳細は未決定。

真偽値を整数として使う場合は、`count += Int(ok)` のように明示的に変換する。`false` は `0`、`true` は `1` に変換する。これまで標準整数型を `int` と表記しているため、`Int` と `int` の正式な表記の統一は別途決める。

真偽値リテラルを `true` / `false` とするか、`TRUE` / `FALSE` とするかは保留する。ここまでの表記は仮のものとして扱う。

## 結び直しと更新の制限

変数の結び直しを禁止する指定と、その経路から中身を更新することを禁止する指定を独立に設ける。組み合わせて両方を禁止することもできる。以下の `fixed`・`readonly` は仮の表記。

```rusk
let a := ...;                 // 結び直し・更新とも可能
let fixed b := ...;           // 結び直し禁止、中身は更新可能
let readonly c := ...;        // 結び直し可能、中身は更新禁止
let fixed readonly d := ...;  // 両方禁止
```

結び直し禁止は変数の性質とする。`fixed b` から `let x := b` と別名を作っても、`x` 自身の結び直しは禁止しない。

読むだけの制限は共有する経路の性質とし、要素・フィールド・別名・戻り値などにも引き継ぐ。別経路からもオブジェクト自体が変わらない保証とは区別する。後者を設けるかは未決定。

更新可能な共有と読むだけの共有は、型検査で区別する。更新可能な共有を読むだけとして扱うことは許し、読むだけの共有を更新可能として扱うことは禁止する。これは制限を弱める暗黙変換ではなく、読み取り権限を制限する扱いとする。

`let b := a` では、`a` が読むだけなら `b` も読むだけとして推論する。既存の更新可能な共有を持つ変数へ読むだけの共有を結び直して、更新権限を得ることはできない。関数の引数・戻り値やコンテナへの格納でも、この制限を型検査で維持する。

`copy(a)` は独立した更新可能な値を作れる。共有の権限と、変数自体の結び直しの可否は別の性質として扱う。

各指定の正式な名前・構文、引数への指定方法などは未決定。

コンテナ自体の更新可能性と、格納する要素への共有の更新可能性を区別する。仮の表記では `Vec<readonly T>` は外側の配列を変更できるが要素の中身は更新できず、`readonly Vec<T>` はその経路で外側も取得した要素も読むだけとする。

読むだけの要素を `filter` などで選び `to_vec()` で集めた場合、新しい外側の配列は変更可能とし、要素への読むだけの制限は維持できるようにする。並べ替え・削除は可能だが、共有した要素の中身の更新は禁止する。

更新可能なコンテナを外側も読むだけとして見ることは許すが、外側を更新可能なまま共有して要素の権限だけを変える変換は禁止する。仮の表記では `Vec<Int>` から `readonly Vec<Int>` は許し、同じ外側のオブジェクトを `Vec<readonly Int>` として扱う変換は許さない。後者を許すと、元の配列に読むだけの要素が挿入されるなど、元の型の保証を壊すため。

新しい外側の配列を作り、要素を読むだけの共有として集めることは許す。`to_vec()` による構築はこの場合に当たる。この区別の正式な型表記や入れ子の型への適用などは未決定。

## 型の明示と推論の範囲

ローカル変数は型推論を基本とし、必要なら注釈できる。関数の引数と `struct` のフィールドは型を必須とする。ジェネリックな引数も `T` などの型を明示する。

通常の関数の戻り値は、既定どおり省略すると `Unit` とし、本体から別の戻り値の型を自動推論しない。無名関数は呼び出し先などの文脈から分かる引数型を省略できる。

## コンパイル時定数

コンパイル時定数の初期値は、コンパイル時に計算できる式に限る。結び直しと中身の更新の両方を禁止し、別名にも読むだけの制限を引き継ぐ。独立した変更可能な値が必要なら `copy` を使う。

コンパイル時に確定することは、結び直しや更新の制限とは区別する性質であり、実行時に決まる値にも変更の制限を指定できる。

コンパイル時に実行できる処理なら、特別な関数宣言を要求せず通常の関数も評価できるようにする。計算中のローカル変数の更新やループは許し、完成した結果にはコンパイル時定数の変更禁止を適用する。配列へ書き込みながら定数表を作る処理などを想定する。

コンパイル時の評価に入力など実行時にしかできない操作が必要になった場合はエラーにする。

宣言の正式な表記（`const`・`comptime` など）、評価可能な操作の厳密な範囲、外部の共有や副作用の扱い、評価の資源制限、初期実装の対応範囲などは未決定。

## Unit

値を返さない処理を表す `Unit` 型を設け、唯一の値を `()` とする。関数定義で戻り値の型を省略した場合は `Unit` を意味する。

```rusk
fn update(x: Int) {
    x += 1;
}
// 戻り値の型は Unit
```

更新専用関数や出力関数なども、`Unit` を返す関数としてジェネリックな処理で扱える。これは文全体を式として扱うことを意味せず、ブロック文とブロック式の区別は維持する。

## 選択肢を表す型

複数の選択肢のいずれかを表し、選択肢ごとに値を持てる型を利用者も定義できるようにする。構文の候補は `enum` とする。

```rusk
enum Option<T> {
    Some(T),
    None,
}
```

`Option` もこの仕組みで表す方向とし、成功・失敗や種類の異なるクエリなどにも使えるようにする。`match` で選択肢を判定し、中身を分解できる。取り出した中身は自動コピーせず共有を保ち、読むだけの制限も引き継ぐ。

```rusk
match result {
    Some(x) => { use(x); }
    None => { ... }
}
```

`=` で選択肢を切り替えた場合も、外側のオブジェクトの同一性だけを保ち、以前の中身を更新しない。取り出し済みの中身への共有は、古いオブジェクトを指し続け、引き続き使用できる。

```rusk
let result := Some([1, 2]);
let x := result?!;
result = None;
x.push_back(3);
// result は None、x は以前の配列 [1, 2, 3] を指す
```

この例の `Some`・`None` は同じ `Option` 型の選択肢であり、切り替えても変数の型が変わるわけではない。具体的な構文、選択肢の名前解決、構築方法や型推論などは未決定。

## 正常には戻らない型

正常には呼び出し元へ戻らない処理を表す型を設ける。仮の名前は `Never` とする。`Unit` は値に意味のない処理が正常に戻ることを表すが、`Never` は正常に戻らないことを表す。

異常終了する関数や、抜けない無限ループなどをこの型で扱う。`Never` を戻り値に指定した関数が正常に戻ることは許さない。具体的な制御フロー検査の規則は今後詰める。

```rusk
let x := if cond { 10 } else { fail("invalid") };
// fail が Never を返すなら、全体の型は Int
```

分岐式では、正常に戻らない分岐を結果の型を合わせる対象から外す。これは暗黙の数値変換とは区別する。正式な名前・記号、すべての分岐が戻らない場合などの詳細は未決定。

## 値の不在の構文案

値の不在を `Option<T>` のような型で表し、簡潔に扱える構文を検討している。現在の候補は、値があれば中身を取り出し、不在なら右辺を評価する `a ?? b` と、不在なら実行時エラーにする後置の `a?!`。以前の `a ?: b` 案から、この対になる記号の案へ進んでいる。採用と詳細仕様は未確定。

この案では左辺を一度だけ評価し、存在する `0` や偽も正常に取り出す。`Option` の条件式での解釈は、中身の真偽ではなく存在の有無を基準にする案。取り出し時は自動コピーせず共有と読むだけの制限を保つ方向で考える。

Option を返すと決めた API（イテレータの next、辞書の get、ヒープの top・pop、列の min・max など）と、探索関数の未確定な API は区別する。探索関数の最終的な名前と型、演算子の優先順位、具体的な表記などは未決定。
