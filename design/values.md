# 値と共有

[設計ノートの入口](README.md)

## 現在

名前はオブジェクトを指す。`let b := a;`は共有、`let b = a;`と`copy(a)`は型別のコピーである。宣言後の`a = b`は外側の同一性を保って中身を更新し、`a := b`は名前の共有先を変更する。整数も同じ規則を使う。

配列・フィールド・タプル・enumのpayload・捕捉環境への格納は共有を基本とする。コピーは各子の通常の`copy`を呼ぶ。集約値への`=`は外側だけを保ち、子をコピーで置き換えるため、以前取得した子への共有は古い値を保持する。

`let x = value;`はコピーによる初期化として使える。`let x: Int;`のように初期値なしで宣言した後は、最初に`x := value;`が必要である。未初期化の`x = value;`は更新する対象がないため使えない。

`fixed`は名前の結び直し、`readonly`は共有経路からの変更、`noescape`は引数の共有の持ち出しを制限する。省略時はrebindable・mutable・escapeである。readonlyは別名・要素・フィールド・戻り値へ伝播するが、別の更新可能な経路からの変更を禁止するものではない。コピーで独立した更新可能な値を作れる。

評価は左から右に一度ずつ行い、オブジェクトを保持する。後続の式が同じ実体を更新すれば、先に保持した値からも更新が見える。名前の結び直しは保持済みの共有先を変更しない。短絡する右辺は必要な場合だけ評価する。

スコープが終わっても、他から共有されるオブジェクトは生存する。文末・条件の終了・ジャンプで不要な一時共有を解放し、文字の共有などが不必要に構造変更を妨げないようにする。詳細は[現行の意味規則](../docs/reference/semantics.md)にある。

## 今後の方針

外側のコンテナと格納要素の更新権限を区別して表現したい。外側を新しく作り、readonlyな要素を共有して集めた配列では、外側の並べ替え・削除を許しながら要素の更新を禁止できる方向とする。

同じ外側のコンテナを共有したまま、更新可能な要素型をreadonlyな要素型へ変える変換は許さない方向とする。readonlyな要素を挿入されると、元の経路が持つ更新権限の保証を壊すためである。

## 未決定

`Vec<readonly T>`などの正式な型表記、返却権限の表現、入れ子の権限の推論・変換規則は未決定。現行の変数・引数注釈と共有経路の推論を置き換えた仕様ではない。

循環共有の可否と解放方式、共有の同一性を直接調べる公開操作、一時値への代入の最終的な制限は保留する。[型](types.md)と[構文](syntax.md)も参照する。
