# ソースの整形

`rusk fmt`は、Ruskのソースを構文に基づいて整形します。型検査やC++生成は行わず、include先も読み込みません。未定義の名前や未実装のextern本体があっても、構文が正しければ整形できます。

## 出力とファイル更新

```bash
rusk fmt main.rusk
rusk fmt --check main.rusk helper.rusk
rusk fmt --write main.rusk helper.rusk
```

| 指定 | 動作 |
|---|---|
| ファイル1つだけ | 整形結果を標準出力へ表示。入力は変更しない |
| `--check` | 整形済みなら終了コード0、差があればファイル名を標準エラーに表示して1。入力は変更しない |
| `--write` | 整形結果でファイルを更新。整形済みのファイルには書き込まない |

複数ファイルには`--check`か`--write`が必要です。両方の同時指定はできません。引数の指定ミスは終了コード2、構文・読込・書込のエラーは1です。`-`で始まるパスは`rusk fmt --write -- -source.rusk`のように指定します。標準入力・ディレクトリ・再帰走査の指定には対応していません。

`--write`では全入力の読込と整形を済ませてから更新を始めます。構文エラーがあれば、どの入力も更新しません。各ファイルは同じディレクトリの一時ファイルへ書き、内容を再確認してから置き換えます。権限を保持し、読み取り専用ファイルは変更しません。シンボリックリンクはリンク先を更新し、リンク自体を保持します。ハードリンク先すべてを同時に変更する保証はありません。

複数ファイルの更新全体は不可分ではありません。更新途中のI/Oエラーでは、それ以前のファイルは整形済みになる場合があります。

## 整形規則

- インデントは空白4つ。空の波括弧は`{}`、空でない波括弧の中身は改行して字下げします。ただし、開き括弧の直後に同じ行のコメントがある場合はその位置関係を保ちます。
- 二項演算子の前後、コンマとコロンの後ろに空白を入れます。単項演算子、フィールド参照、添字、型引数は構文に応じて詰めます。
- 丸括弧・角括弧・型引数のグループは、目安の100文字に収まらなければ改行します。長いリテラル・コメントや任意の式を100文字以内へ分割する保証はありません。
- 文の区切りで改行し、区切りの空行は最大1行に揃えます。外側の改行はLFに揃え、空でないファイルの末尾に改行を付けます。
- 括弧、末尾コンマ、`;`は追加・削除しません。ブロックの末尾式と、`;`を付けた文の違いを保ちます。
- コメント、文字列・文字リテラル、externのC++本文は内容を保持します。それらの内部の改行や空白も変更しません。

```rusk
/// 入力を1増やした値を返します。
fn increment(x: Int) -> Int {
    return x + 1;
}
wt increment(4);
```

このプログラムの出力は`5`です。[文書コメント](../development/doc-comments.md)も整形前後で同じ宣言に対応します。

## リポジトリ全体を確認する

```bash
cargo build --locked
python3 tools/check_format.py
python3 tools/check_format.py --write
```

対象は`lib/`と`examples/`内のすべての`.rusk`ファイルです。`tools/test.py`のローカル検証とCIでも、この整形チェックを実行します。
