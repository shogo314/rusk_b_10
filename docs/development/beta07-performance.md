## 読み取り専用の格納先を追跡する

`src/readonly/heap.rs` は、構築命令ごとのオブジェクトIDと、フィールド・payloadから共有先への辺を保持します。同じオブジェクトを指すローカルの別名や、先に取り出した内部オブジェクトも同じIDを使います。関数が引数自身・内部の値・それらを包んだ新しい集約を返す場合は、関数効果の共有経路から対応関係を復元します。

以前は読み取り専用の参照を一度格納すると、無関係なオブジェクトも広く拒否していました。現在は、ローカルに直接構築した既知の格納先で、次のコードを許可できます。

```text
struct Pair { left: Int; right: Int; }
let pair := Pair { left: 0, right: 0 };
let alias := pair;
let other := Pair { left: 0, right: 0 };
readonly let value := 1;
pair.left := value;
alias.right = 2;
other.left = 3;
wt alias.left, alias.right, other.left;  // 1 2 3
// alias.left = 4;                     // 読み取り専用なのでエラー
```

ループでは一つの構築命令が複数の実行時オブジェクトを作ります。共有先・格納内容は弱い更新で合流させ、過去の反復で外側へ残した参照の制約を消しません。循環や深い経路も、制約を落とす代わりに保守的に広げます。

引数由来の格納先や、外部への保持・未知の返却を通じて追跡外の別名を持ち得るオブジェクトは、引き続き広い制約へ戻します。配列のネイティブ操作や任意の関数による書き込みを、すべてフィールド単位で追跡する実装ではありません。noescapeの一般的なヒープ効果解析にも保守的な処理が残っています。

## 解析した効果から引数を借用する

本体を解析したRusk関数について、次を満たす引数をC++の`const Obj<T>&`で受け取ります。

- その引数を経由した更新・構造変更・脱出がすべて`No`。
- 関数の外部書き込みが`No`で、不明な外部効果を含まない。
- 最適化が有効。

注釈の有無ではなく推論結果で選択するため、`mutable`・`escape`を明示しても、同じ性質を証明できれば同じ表現になります。外部実装のABIは変更しません。

```text
fn add_one(value: Int) -> Int { return value + 1; }
```

このような引数では、C++関数への入場時のshared_ptrコピーを一つ減らします。呼び出し元の引数の一時値は呼び出し終了まで生存し、関数内の通常の引数変数は引き続き所有するコピーです。仮引数名の結び直しは可能で、別の引数から同じオブジェクトを更新した場合も更新が見えます。`const Obj<T>&`は、共有先の`T`そのものを凍結する指定ではありません。

## 閉じたBoolの別名を値で保持する

`BoolCopy`・enumのvariant判定・既知のスカラー演算が作った新しいBoolは、まず`RuskTemporary<bool>`へ保持します。さらに、`Declare`と`Share`でつながる別名のグループについて、次を検査します。

- 元になる新しいBoolが一つで、引数や取得済みのフィールドに由来しない。
- 使用先が生成済みのスカラー演算内で完結し、その引数の更新・構造変更・脱出が`No`。
- 結び直し、集約への格納、捕捉、返却、通常の関数や不明な外部実装への受け渡しがない。

条件を満たす別名は、その一時値を指すC++参照にします。参照元の保持場所を関数入口へ配置して寿命を保証し、別名への所有者の解放処理を生成しません。Boolのスナップショットは元の共有値と独立した値のままです。閉じていると証明できない場合は、従来のObjへの昇格と所有を使います。Intなど一般のローカル変数全体の値保持は、まだ今回の実装に含めません。

`find`の比較結果を一時的なBool変数へ入れる形にも、この一般的な処理が適用されます。findという関数名を見て特別扱いする最適化ではありません。

[既存11項目の全結果](beta07-representation-benchmarks.json)は各7回、[個別の効果測定](beta07-effects-benchmarks.json)は順序を交互に反転して各7回の中央値です。確保回数はoperator new、shared_ptrコピー回数はGCCの前処理済みlibstdc++にある参照数増加処理を別の実行ファイルで計数します。実行時間と計数用バイナリは分離します。この参照数計測はGCC内部実装に依存する開発用の測定です。

再測定には、比較元の処理系を用意して次を実行します。

```bash
python3 tools/benchmark.py --baseline-compiler /path/to/baseline --baseline-all-cases --repeats 7 --output /tmp/beta07-all.json
python3 tools/benchmark_effects.py --baseline-compiler /path/to/baseline --repeats 7 --reference-copies --output /tmp/beta07-effects.json
```

`--reference-copies`を省略するとGCCヘッダーの計装を行いません。計装先のGCC内部構造が変わった場合は、その旨を表示して停止します。
