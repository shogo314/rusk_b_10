# β05の実装と検証

<!-- rusk-docs: history -->

!!! note "過去の開発記録"
    このページの計画・件数・パス・測定値は記録当時のものです。現在の構成は[開発ガイド](index.md)、対応範囲は[言語リファレンス](../reference/status.md)を参照してください。

β05は、不在を扱う式とハッシュ型の辞書・集合を追加する段階です。対象範囲はリポジトリの `design/beta05.md`、言語仕様は[分岐式・Option・比較の連鎖](../reference/expressions.md)、APIは[辞書・集合と入力](../library/collections.md)に記録しています。

!!! note "処理系の構造変更"
    機能追加後に[HIR・LIRを経由する方式](pipeline.md)へ移行しています。このページの215/105テストの結果と測定JSONは、その移行前の記録です。移行後の検証はパイプラインのページに記載します。

## 変換の方式

if式と `??` は `src/compiler/expressions.rs` の共通の条件分岐生成処理を使います。現在は型付きHIRへ格納し、LIRの分岐とジャンプを経由してC++を出力します。結果用の共有ポインターを分岐の外へ置き、選んだ分岐の結果をそこへ格納します。未選択の式は実行せず、両分岐で一致する型と初期化状態を検査します。後続の[ブロック式とラベル](../reference/blocks-labels.md)の追加では、分岐内の文と末尾式、途中の脱出にも対応しています。

比較が一つなら従来の二項演算として扱います。連鎖の場合は各項を共有した一時値で保持し、比較が真のときだけ次の項を生成した分岐へ進みます。前の項をコピーせず、評価順序と共有を保ちます。`?!` はOptionの取得関数を演算子の位置で呼びます。

Optionの中身は共有ポインターで、不在は空のポインターです。DictとSetはC++の `std::unordered_map` / `std::unordered_set` を使います。キーのハッシュ・等価性は値に基づき、登録・取得時のコピーで可変なキーの漏出を防ぎます。基本型・タプルにキー型を限定し、readonlyや独自ハッシュは導入しません。整数の標準ハッシュをそのまま使うと、公開ケースの特定のキー列で60秒を超えたため、起動ごとの種と64ビットの混合を追加しています。衝突がなくなる保証ではなく、最悪計算量は引き続きO(n)です。

Ruskの具体的な型ごとに固有のC++コンテナ型を作ります。コピー関数は型の具体化が終わるまで順に解決し、Option・辞書・集合・構造体・タプル・配列・捕捉環境の入れ子でも論理的なRusk型のcopyを呼びます。異なる外部Rusk型が同じC++型へ接続される場合にも、コピーの選択を分けます。

走査子は所有者を共有して保持し、C++のカーソルと構造変更の世代番号を持ちます。カーソルに触る前に世代を検査し、遅延操作のコールバック後にも検査します。辞書の走査結果はキーのコピーと値への共有を組にします。削除後も、外へ取得済みの値は共有が残る間生存します。

構造化入力では型と次元数に応じた読み取り関数を生成し、既存のバッファ入力を再利用します。try_readはトークン前の正常EOFだけをNoneに変え、既存の不正入力の検査を保ちます。

## 回帰検証

共通コマンドは `python3 tools/test.py` です。通常版と `--no-opt` の両方でβ05のテストを実行します。

`tests/beta05.rs` は次を確認します。

- if式と??の短絡、結果の共有、型と確実な初期化。
- 比較の連鎖の左からの評価・一度だけの評価・短絡と中間値の共有。
- Optionの再帰的コピー、外側の同一性を保つ代入、保持済みの中身の寿命。
- 辞書の値の更新と結び直し、削除後の寿命、既定値の有無。
- タプルキーの登録・取得・走査でのコピー保護。
- 240回の辞書・集合の変更を独立したBTreeMap/BTreeSetと照合。
- 遅延map/filter/foldと走査子のコピー、構造変更の検出。
- 多次元・タプル・タプル配列の入力、EOF、不正入力と長さの検査。
- Option内のクロージャや構造体・配列・辞書を組み合わせたコピー。
- 不在取得のエラーが?!のソース位置を示すこと。

サニタイザーにはOption、削除後の辞書の値、タプルキー、辞書の遅延走査、文字への共有を含む分岐結果を追加しています。

公開問題の追加例は `examples/beta05/README.md` にまとめています。AtCoderの既存100問とAOJ・Library Checkerの既存例を維持し、辞書のAssociative Array、集合のALDS1_4_Cと二つの別解を共通入口・CIで検証します。公開ケースの成功はオンライン提出のACとは区別します。

## 性能の再測定

```bash
cargo build --release --locked
python3 tools/benchmark.py --compiler target/release/rusk \
  --baseline-compiler /path/to/beta04/rusk --compare-no-opt \
  --repeats 7 --output /tmp/rusk-beta05-benchmark.json
```

既存6項目を同じソース・入力でβ04と比較します。辞書の集計とタプルの集合はβ04では書けないため、β05・最適化無効版・手書きC++・利用可能ならPyPyを比較します。`--case dictionary --case tuple_set` で追加分だけを実行できます。手書きC++は直接の値、Ruskは共有と再帰的コピーを使うため、そのコストも含む処理全体の比較です。コンパイル時間を除き、プロセスの起動と入出力は計測に含めます。全回の出力一致を検査し、中央値と各回の値を保存します。CIで時間を合否判定には使いません。

## β04からの性能変化

2026年11月7日、WSL2 / Linux 6.6.87.2、AMD Ryzen AI 9 HX 370、GCC 15.2.0で測定しました。C++は `-std=c++20 -O2`、7回の中央値です。他のテストを終えてから実装を交互に実行し、全回の出力一致を確認しました。基準はβ04最終コミット `36619dbbd27b42a44eaafe7a34682463e85a1732` の処理系です。

| 既存処理 | β04 | β05 |
|---|---:|---:|
| 整数入力100万個と合計 | 28.90 ms | 29.69 ms |
| 整数出力20万行 | 5.11 ms | 5.17 ms |
| 整数ループ100万回 | 14.53 ms | 14.04 ms |
| ソート・探索 | 14.27 ms | 14.19 ms |
| グリッドBFS | 28.19 ms | 29.07 ms |
| Fenwick Tree | 41.57 ms | 43.13 ms |

この6項目では約−3〜＋4%で、大きな退行は見られません。単一環境の短時間の測定で、数%の差を有意な改善・悪化とは扱いません。

## 追加した辞書・集合の性能

| 処理 | β05 | β05最適化無効 | 手書きC++ | PyPy |
|---|---:|---:|---:|---:|
| 整数キー20万件・1万種類の集計と全件走査 | 12.88 ms | 18.70 ms | 7.58 ms | 33.14 ms |
| タプル20万件・1万種類の集合への登録と全件走査 | 20.62 ms | 22.92 ms | 15.69 ms | 43.85 ms |

Ruskの共有ポインター、キーの再帰的コピー、ハッシュの混合、走査時のキー保護も含む時間です。この入力ではPyPyより短い時間でしたが、問題・入力分布・実行環境全体への保証ではありません。ハッシュが衝突を起こした場合の最悪計算量は残ります。

既存の関数付き処理も実行し、100万要素のmap/filter/foldは86.14 ms、同じ計算をRuskの単一ループにした版は22.36 msでした。静的な関数呼び出しでも列処理の連結に約3.85倍の時間が掛かり、引き続き最適化の課題です。キー付き安定ソートは27.39 ms、タプルを直接ソートするRusk版は22.26 msでした。

[測定JSON](beta05-benchmark.json)に全10項目の各回の値、処理系・ソース・入力のハッシュと環境を保存しています。関数付き2項目は同じβ05内の手書き処理との比較で、β04との同時測定は上の6項目です。

追加した汎用enumと、同じ表現へのOption移行の実装・検証は[enumとOption移行](enums.md)を参照してください。
