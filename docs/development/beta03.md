# β03の高速化と検証

<!-- rusk-docs: history -->

!!! note "過去の開発記録"
    このページの計画・件数・パス・測定値は記録当時のものです。現在の構成は[開発ガイド](index.md)、対応範囲は[言語リファレンス](../reference/status.md)を参照してください。

β03ではβ02の文法・共有・コピーの規則を維持し、入出力のバッファ化と、基本値の一時結果に対するヒープ確保削減を実装しています。C++20を生成する方式と、通常の関数・配列・フィールドに共有オブジェクトを渡すABIは継続しています。

## 入出力の実装

`lib/io.hpp` に入力・出力それぞれ64 KiBのバッファがあります。生成C++へ埋め込むため、提出時に別のヘッダーファイルを配る必要はありません。

入力は `fread` で補充し、トークン読み取りはバッファから直接文字を取得します。整数はトークン全体を `from_chars` で検査します。文字・真偽値・文字列・`read_line()` も同じ入力バッファを使い、トークンの後の区切り文字を残す規則を維持します。

出力では整数を `to_chars` で変換し、文字・文字列・真偽値と共通のバッファへ書き込みます。配列・タプルの空白、`wt` の最後の改行も同じ出力へ送ります。終了時に残りを出力し、位置付きエラーで終了するときもそれ以前の標準出力を保持します。

標準の `std::cin` / `std::cout` にも同じ `streambuf` を接続するため、外部関数でこれらを使っても先読みしたデータを失わず、出力の順序も維持できます。`printf` / `scanf` との混在を保証するものではありません。この版で測定しているのは一括入力を受け取る通常のバッチ実行です。対話問題への適性は別途検証が必要です。

    この節はβ03時点の実装記録です。現在は[HIR・LIRを経由する方式](pipeline.md)へ移行し、制御構文や構築操作も型付き命令で表しています。

## 型付き中間表現とC++生成

処理を次のように分けています。

1. `src/compiler.rs` と `src/compiler/`：名前・型・初期化・関数候補を検査し、具体化した関数を解決する。
2. `src/backend/ir.rs`：型が確定した値、リテラル、解決済み呼び出し、位置を命令列として保持する。
3. `src/backend/intrinsics.rs`：埋め込まれた標準ライブラリの既知の演算を、値を直接扱う演算へ置き換える。
4. `src/backend/cpp.rs`：選んだ表現でC++を生成する。

このIRはC++に近い低水準の表現です。制御構文、変数宣言、構造体などの構築・フィールド操作は、検査済みのC++断片を順序どおり保持します。全プログラムを対象にする制御フロー解析や、任意の式を並べ替える最適化は行いません。今の最適化は型付きの値・呼び出しに限定します。

ユーザー関数・外部関数を名前だけで標準演算とみなすことはありません。標準ライブラリ由来の宣言に解決されたことと引数型を確認してから置き換えます。自作の `__add__` や更新関数の副作用は通常どおり実行します。

## 一時結果を共有するまで実体化しない

整数・真偽値・文字のリテラル、整数計算、比較、条件の真偽変換、範囲走査の次の値などは、新しい独立した値を返します。これらの一時結果は `lib/scalar.hpp` の `RuskTemporary<T>` で最初は値を直接保持します。`Unit` の一時結果にも同じ仕組みを使います。

変数・配列・フィールド・タプルへ格納したり、通常の関数へ渡したり、共有する値を返したりする時点で `Obj<T>` が必要になれば、共有オブジェクトを一度だけ作ります。その後の読み取り・更新は、その同じ共有オブジェクトを使います。式の途中で実体化した場合も、元の一時結果との共有関係を保ちます。

既存の変数・要素・フィールドを読む操作は、最初からオブジェクトへの共有を保持します。これを値のスナップショットへ置き換えることはしません。そのため、先の引数で保持した共有に、後の引数での更新が見える規則も維持します。

例えば `a += 2` は、加算結果を新しいヒープオブジェクトにする代わりに、検査済みの値を `a` のオブジェクトへ書き込みます。`a` と他の名前が共有していれば、更新は引き続き両方に見えます。`a := ...` は変数の共有先を変更する処理のままです。

現時点では名前付き変数を一律にネイティブ値へ変える解析は行いません。範囲ループの変数にも共有が必要になれば確保が発生します。共有・コピーや外部ABIを維持しながら、まず一時結果の確保を削減する実装です。

## 最適化を無効にして比較する

```bash
cargo build --release --locked
target/release/rusk compile main.rusk -o /tmp/optimized.cpp
target/release/rusk compile main.rusk --no-opt -o /tmp/reference.cpp
g++ -std=c++20 -O2 /tmp/optimized.cpp -o /tmp/optimized
g++ -std=c++20 -O2 /tmp/reference.cpp -o /tmp/reference
```

`--no-opt` は基本値の確保削減と標準演算の置き換えを無効にします。C++コンパイラ自体の `-O2` は有効です。バッファ入出力は両方に共通なので、これはβ02の再現モードではありません。β02との比較には別にビルドしたβ02の処理系を使います。

`tools/test.py` は通常のCargoテストに加え、E2E・構造体・タプル・ジェネリクス・include・データ構造の77テストを `--no-opt` でも実行します。専用の回帰テストでは両モードの出力・終了コード・エラー位置を比較し、外部関数への受け渡し、早期終了、整数境界などを確認します。

アロケーターを計測するテストでは、同じ整数ループの計算結果を照合し、実際のヒープ確保が最適化無効版の半分未満になったことを検査します。CIでは実行時間の閾値を使いません。

## β02との速度比較

β02最終版 `c1b99afc1d72e79dfb45da62cb2ae6b9a366bff7` と同じソース・入力で比較しました。測定は2026年11月7日、WSL2 / Linux 6.6.87.2、AMD Ryzen AI 9 HX 370、GCC 15.2.0、生成C++は `-std=c++20 -O2` です。コンパイルを除き、プロセス起動・入出力を含む7回の中央値を使います。

| 項目 | 入力規模 | β02 | β03 最適化無効 | β03 | β02比の高速化 |
|---|---|---:|---:|---:|---:|
| 整数入力と合計 | 1,000,000個 | 106.32 ms | 52.71 ms | 35.76 ms | 2.97倍 |
| 整数出力 | 200,000行 | 14.02 ms | 9.35 ms | 5.33 ms | 2.63倍 |
| 整数ループ | 1,000,000回 | 30.43 ms | 28.85 ms | 13.94 ms | 2.18倍 |
| ソート・探索 | N=200,000、Q=2,000 | 32.02 ms | 15.66 ms | 15.48 ms | 2.07倍 |
| グリッドBFS | 障害物なし200×200 | 62.37 ms | 61.66 ms | 29.48 ms | 2.12倍 |
| Fenwick Tree | N=100,000、Q=100,000 | 132.70 ms | 119.90 ms | 41.67 ms | 3.18倍 |

整数入力と整数ループで目標の2倍を超え、この測定の他の項目にも大きな退行はありません。基本値処理と入出力のそれぞれの効果は、最適化無効版も含めて比較できます。整数入力の例はパースだけでなく、読み取りループと合計も含みます。

全実装について各実行の出力一致を確認し、計測の順番による偏りを減らすため実装を交互に実行しています。環境情報、コンパイラと入力・ソースのハッシュ、各回の時間は [測定JSON](beta03-benchmark.json) に記録しています。手書きC++とPyPyの値も含みます。単一環境・限られた入力の結果であり、全ての問題でPyPyを超えることやジャッジ上の実行時間を保証しません。

再測定するにはβ02を別ディレクトリでビルドして次を実行します。

```bash
python3 tools/benchmark.py --compiler target/release/rusk \
  --baseline-compiler /path/to/beta02/target/release/rusk \
  --compare-no-opt --repeats 7 --output /tmp/rusk-beta03-benchmark.json
```

特定の項目だけなら `--case integer_input --case range_sum` のように指定できます。β02の基準はβ03の初期コミットに含まれる処理系とも言語実装が同じですが、出典を明確にするためβ02リポジトリの最終コミットを使うことを推奨します。
