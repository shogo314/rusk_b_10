# extern・C++参照・標準宣言の契約

外部ジェネリック型・関数、型・関数・コールバックの参照、共有ABI・信頼元・効果と保持情報の実装規則をまとめる。利用者が書ける外部宣言と、埋め込み標準ライブラリだけが使える信頼情報を区別する。全体の役割分担は[処理系とライブラリの境界](architecture.md)、実行検証は[テストの実行](verification.md)を参照。

## 読む順序と使用できる情報

利用者の外部型・関数を追加する場合は、宣言・共有ABI、C++参照、コールバック、Unit、資源ファイルの規則を使う。標準ライブラリを実装する場合は、さらに信頼元・生成情報・表現・導出・効果と保存先の対応を扱う。

| 情報 | 利用者extern | 埋め込み標準 |
|---|---|---|
| 型引数、`cpp_name`、C++の`code`、型・操作・コールバック参照 | 利用できる | 利用できる |
| フィールド・variant・引数の列挙、論理型による分岐 | 公開される構造に利用できる | 捕捉環境を含む導出にも使う |
| `return_abi`、`implicit_call`、シンボルの資源と依存宣言 | 利用できる | 利用できる |
| `representation`・`retains`・`effects`・`aliases` | 指定できない | 署名・型・依存を検査して使う |
| `lower`系列・`derive`・`operation` | 指定できない | 直接生成と共通の意味情報として使う |

`code`は共有ABIを持つC++関数の定義全体である。`lower`は評価済み引数から結果の本体値を得る式、またはUnitの処理を表す。`$0`・`$1`・`$loc`はlower系列の評価済み引数・位置の参照であり、通常のRusk構文ではない。詳細は[直接生成](#native-lowering)を参照する。

## 宣言と共有ABI

```rusk
extern type<T> Cell {
    cpp_name: "std::shared_ptr<{T}>",
}
extern fn cell<T>(x:T)->Cell<T> {
    code: "Obj<@{Cell<T>}> @{fn}(Obj<@{T}> x,Loc){return make_obj<@{Cell<T>}>(std::make_shared<@{T}>(*x));}",
}
extern fn get<T>(x:Cell<T>)->T {
    code: "Obj<@{T}> @{fn}(Obj<@{Cell<T>}> x,Loc){return make_obj<@{T}>(**x);}",
}
let c:=cell(3);
wt get(c),get(cell("hello"));
```

出力は`3 hello`。型引数は通常の関数と同様に引数から推論でき、`cell::<Int>(3)`のように明示もできる。適合候補のうちジェネリックな引数位置が最少のものを選び、同順位なら曖昧にする。明示した型引数はジェネリック候補を選ぶ。重複候補の保持、型の照合、具体化キャッシュはRusk関数と共通である。

型注釈・返却先・引数の文脈から分かる期待型も、型引数の推論に使う。例えば`empty<T>()->Cell<T>`を宣言すれば、`let c:Cell<Int>:=empty();`で`T=Int`と決まる。`let c:Cell<Cell<Int>>:=cell(empty());`のように期待型を引数の呼び出しへ伝えることもできる。これは通常のRuskジェネリック関数とメソッド形式の呼び出しにも共通の規則である。

実引数・明示型引数・期待型は一致する必要がある。期待型で明示型引数を上書きしない。期待型は未確定の型引数を補うために使い、すでに型引数が決まった候補同士を戻り型だけで選び分けることはしない。期待型がなく型変数が決まらない`empty()`はエラーとなる。後続の文や未評価の後続引数まで戻る型推論は行わない。

型パラメータは`extern type<T> Cell`の位置で束縛する。既存の`extern type Iter<Int> { ... }`は具体型の宣言のまま扱う。`extern type Cell<T>`を新旧両方の意味にすると、`T`が既存の型か型変数かによって宣言の意味が変わるため、型パラメータを束縛する位置を分けた。ジェネリック関数は`extern fn name<T>`で宣言する。

`{T}`は具体化したRusk型の**C++本体型**を表す。例えば`{Int}`は`std::int64_t`であり、`Obj<std::int64_t>`ではない。引数・返却値の共有ABIに必要な`Obj<...>`は本体に明記する。`Unit`返却の関数はC++では`void`となる。通常のexternと同様に末尾の引数として`Loc`を受け取る。

この例の`Cell<Int>`の本体型は`std::shared_ptr<std::int64_t>`、引数のABI型は`Obj<std::shared_ptr<std::int64_t>>`となる。内側のポインタはこの外部型の意味の一部で、処理系が削除したり共有ラッパーと同一視したりしない。

同じC++本体型を持つ別名のRusk型は別の型として照合する。`First<Int>`と`Second<Int>`のC++表現が同じでも、互いの引数として渡せない。利用者の外部型はIRで不透明型として保持する。標準由来の宣言の表現・共有先の情報は、後述の検査を通して接続する。

## 宣言の重複と順序

通常の型コンストラクタは、その名前の系列全体を所有する。`extern type<T> Cell`と`extern type Cell<Int>`を併記して、一部の具体化だけを別定義にすることはできない。Ruskの`struct Cell<T>`・`enum Cell<T>`と具体的なextern型の組み合わせも同様に拒否する。宣言順を逆にしても拒否し、前の宣言位置を診断に含める。

外部型には、対象を限定した型パターンも記述できる。例えば次の宣言は`Slot<Vec<Int>>`や`Slot<Vec<Str>>`に一致する。

```text
extern type<T> Slot<Vec<T>> {
    cpp_name: "std::shared_ptr<{T}>",
}
```

型パターンの末端に現れる型変数を束縛し、すべての型パラメータが束縛されることを未使用でも検査する。`PairCell<Tuple<A,B>>`なら、外側の型引数は一つで、そこからA・Bの二つを求める。実際の型引数自体も検査するため、C++本体が使わない外側の形状であっても、不正な型や要素型の制限をすり抜けない。

同じ名前の複数の型パターン・具体型は、有限の具体型に対して重ならない場合だけ併記できる。上記の宣言と`extern type Slot<Int>`は共存できるが、`Slot<Vec<Int>>`の別定義や、型変数名だけを変えた同じパターンは拒否する。宣言ごとの型変数を区別し、同じパターン内の繰り返しは同じ型に束縛する。無限に入れ子の型を仮定して重なると判定することはしない。重複判定には深さ64・比較作業4096の上限を設け、超過時は診断して停止する。

テンプレートを持たない共通の具体型宣言は維持する。例えば`extern type Legacy<Int>`と`extern type Legacy<Str>`は異なる具体型として併記できる。ただし同じ具体型の二重宣言や、裸の型名`Legacy`との併記は拒否する。

外部型の型参照は、型・関数の宣言を登録した後で具体化する。後に宣言した外部型やRusk構造体を参照でき、入れ子の型参照も解決する。循環する展開は拒否する。これはRusk型の参照に関する規則であり、任意のC++断片の依存関係を解析して並べ替える機能ではない。

## C++参照の展開規則

| 場所 | 記法 | 意味 |
|---|---|---|
| 外部ジェネリック型の`cpp_name` | `{Int}`、`{T}`、`{Cell<T>}` | 検査・具体化した型のC++本体型 |
| 同じ`cpp_name` | `@{value_call evaluate(T)->Int}` | 論理型から解決した値返却ABIの関数参照 |
| 外部ジェネリック関数の`code` | `@{Int}`、`@{T}`、`@{Cell<T>}` | 同じ本体型。通常のC++の波括弧と区別する |
| 同じ`code` | `@{fn}` | この具体化に割り当てたC++関数名 |
| 同じ`code` | `@{call copy(T)->T}` | 通常の名前解決で選んだ関数・操作のC++名 |
| 同じ`code` | `@{invoke F(T)->R}` | 関数値Fの型を検査した呼び出し先。捕捉環境を第一引数に渡す |
| 同じ`code` | `@{return R}` | 返却ABI型。Unitなら`void`、それ以外は`Obj<本体型>` |
| 同じ`code` | `@@` | リテラルの`@`。`@@{T}`は展開後に`@{T}`となる |

関数名は処理系が割り当てるので、ジェネリックextern関数には`cpp_name`を指定しない。型引数の異なる具体化同士で関数本体が衝突せず、同じ具体化を再利用する。生成名の綴りは公開ABIにはしない。

参照の中では型名と山括弧形式の型引数を使える。型参照には`Tuple<Int,Str>`のような山括弧形式を使い、型名の内部の空白やTupleの丸括弧略記は使わない。関数・コールバックの署名参照では空白を除いて解釈する。未定義の型、不正な参照、閉じていない参照、型引数の個数違い、再帰する外部型の展開はRusk側でエラーにする。参照によって型を具体化したときに補助関数が増えても、呼び出し先の関数IDがずれないよう登録を行う。

`@{nonunit T}`は、本体で論理型TがUnit以外であることを検査し、そのC++本体型へ展開する。型名と束縛は未使用宣言でも検査し、Unitの拒否は選んだ具体化の要求位置で診断する。外部型の`cpp_name`では使えない。標準のmap/filterはこの参照で共通のUnit結果の制限を維持する。mapへのUnit入力は`boxed_call`で実オブジェクトを渡せるため、入力と結果の制限を混同しない。

これは明示したマーカーだけを展開するテンプレートであり、C++字句解析ではない。`T`という単語や`{Int}`をC++本体から一律に置換しない。通常のコメント・文字列・raw文字列・初期化子はそのまま残る。ただし`@{...}`はコメントや文字列の中でも展開するため、その記法自体を残す場合は`@@{...}`と書く。既存の具体的なextern宣言にはこの展開を適用しない。

## 関数・操作の参照

```rusk
extern fn detached<T>(x:T)->T {
    code: "Obj<@{T}> @{fn}(Obj<@{T}> x,Loc loc){return @{call copy(T)->T}(x,loc);}",
}
let x:=[1,2];
let y:=detached(x);
y[0]=9;
wt x,y;
```

出力は`1 2 9 2`。参照は`call 名前(引数型,...)->返却型`の形で、型を具体化した後、通常の具体関数・Ruskジェネリック関数・外部ジェネリック関数の候補から選ぶ。明示型引数は`@{call echo::<T>(T)->T}`と書ける。適合する候補のうちジェネリックな引数位置が最少のものを選び、同順位が複数なら曖昧として拒否する規則は共通である。指定した返却型と選んだ宣言が一致しない場合もエラーにする。

参照先の解決は通常の呼び出しと共通にし、構造化入力等の導出された操作も同じ入口で解決する。例えば`@{call __read__()->Tuple<Int,Str>}`はTupleの入力操作を参照する。本体は通常の型付き参照を使う標準テンプレートから導出する。

既存の具体的なexternが`cpp_name:"reader::row"`のような名前空間付きのC++名を指定していても参照できる。具体的なexternの定義をABIアダプタとジェネリックexternの定義より前に出力し、名前空間付きの名前に不正なグローバル前方宣言を作らない。通常の`call`・`value_call`・Unitの格納／破棄用の参照に共通の規則である。任意のC++断片の依存関係を解析するものではなく、具体的なextern同士のC++上の宣言順や必要な前方宣言は同じ規則で本体の記述側で扱う。

捕捉付きのローカル関数も参照できる。Rusk側は必要な捕捉先を隠れた引数で渡し、ABIラッパーがC++本体の実行中に各参照へ接続する。C++本体には従来どおりソースの引数と`Loc`を書く。再入呼び出し後は呼び出し元の環境に戻す。環境が未準備、または取得できない呼び出しはC++生成前に診断する。捕捉が必要な具体化では、ソースの引数だけを想定したlower系列を適用しない。

型付きの名前参照は、C++関数の参照であり、捕捉環境を所有するRuskの関数値ではない。捕捉付きの参照は、環境を接続したnative呼び出しの間に使う。関数を保存して後で呼ぶ場合は、環境を保持したRuskの関数値を明示的な引数`F`として渡し、`invoke`で呼ぶ。外部型の関数参照も、その型を使うnative操作を通じて環境を得る。型の値そのものに環境は追加しない。

オーバーロード集合や未具体化ジェネリック関数も`F`として渡せる。`invoke`に記述した引数型から呼び出し口を具体化し、返却型の型引数には呼び出し側の期待型も使える。関数値のUnit結果はRuskのコールバックと同じ`void`のABIへそろえる。参照先のexternがUnitの実オブジェクトを返しても、関数値の呼び出し完了時に破棄し、`boxed_invoke`では通常のUnitを箱に入れる。externの実オブジェクトを保存する直接参照には`boxed_call`を使う。

この参照は関数名だけを展開する。引数の式と末尾の`Loc`はC++本体に明記する。参照先がRusk関数なら推論された借用ABIの宣言と一致させ、外部関数なら通常の所有付きABIを使う。利用者externでは、参照先を呼ぶ場合も外側の宣言にある引数契約だけを作成者の保証として使う。

`@{value_call 名前(引数型,...)->返却型}`は、`i64`・`bool`・`char`表現の型の本体値を返す共通アダプタを参照する。候補解決・型推論・前方宣言は通常の`call`と共通で、引数は`const Obj<...>&`、末尾は`Loc`になる。標準宣言に信頼された`lower`がある場合はその式を使い、それ以外は通常の所有付き結果を返す関数を呼び、宣言されたObj型の変数で結果を受け取り、呼び出し文の完了後に結果の値を取り出す。値渡しの引数や一時オブジェクトの解放が返却値を書き換える場合も、その後の値を観測する。利用者関数の本体やC++名を調べて式へ置き換えない。戻り値は共有を返すABIとは異なり、独立したC++の値である。Unit以外の集約値の参照は拒否する。最適化無効時も、この明示的な値参照のABIは同じである。

Unitの`value_call`はC++で`void`を返す。標準宣言の`lower`があればその処理を行い、なければ実際の関数を呼ぶ。`return_abi:"object"`の関数も呼び出し、返却オブジェクトをいったん保持し、呼び出し文の引数の解放後に破棄する。Unitの通常の破棄用ABIアダプタでも同じ順序を使う。Unitを保存したい場合は`boxed_call`を使う。これにより、配列出力から標準の要素出力を余分な共有コピーなしで呼びながら、利用者定義の出力関数や返却オブジェクトの後処理も実行できる。

`@{owned_call 名前(引数型,...)->返却型}`は、`Obj<返却型の本体型>`を返す所有付き参照で、引数は`const Obj<...>&`になる。信頼された`lower_owned`があれば使う。スカラーの`lower`しかない場合は、結果が新しい割り当てであり、引数や不明な共有先への別名を返さないと証明できた場合に限り、その値から新しいObjを作る。それ以外は通常の関数を実際に呼び、返った共有値をそのまま使う。利用者関数が返す別名をコピーへ置き換えない。Unitにも使え、オブジェクトABIの結果はそのまま、voidの処理は既存の格納用ブリッジでObjに包む。`boxed_call`は通常の所有付き引数ABIを使う参照として維持する。

値参照と所有付き参照は、互いの生成式から参照できるよう、すべての前方宣言を本体より先に出力する。最適化無効時も明示した参照のABIは同じであり、外側のexternの効果が自動的に安全になるわけではない。

これは比較ソート等のextern本体から余分なBoolの確保を避けて標準比較を参照するためにも使う。未知のexternやRusk関数には通常の呼び出しを残すため、副作用と関数から戻る前の後処理を維持する。この参照によって外側のexternの効果・保持を安全と仮定することもない。Tupleの自動比較は標準の役割テンプレートを使い、フィールドの通常の比較と同じ生成情報を使う。

`@{writes 名前(引数型,...)->返却型}`は、同じ操作候補を解決し、引数または外部状態を変更する可能性をC++の`constexpr bool`として参照する。LIRの効果解析後に値を決め、すべての書き込みが`No`と証明できた場合だけfalseにする。未知のexternはtrueになる。問い合わせ自体は操作を実行せず、呼び出し先の型やC++名から安全性を仮定しない。標準の信頼契約とRusk本体の推論を共通に参照するが、利用者が契約を追加する権限は与えない。外側のextern全体にこの効果を自動合成する仕組みでもない。

静的に分かる関数値には、`@{writes_invoke F(引数型,...)->返却型}`で同じ問い合わせを行う。捕捉環境への変更も含めて判定し、問い合わせ自体はコールバックを呼ばない。sort_by_keyでは、キー関数・コピー・比較のいずれも変更しないと証明済みの場合に変更検査を省き、未知の操作や変更する操作には検査を残す。Tupleの自動コピーも、再帰的に標準の値だけから成ると確認できる場合に限って信頼契約を付ける。利用者定義のcopyを呼び得る一般の構造体に、この契約を一律に付けることはしない。

`@{fails 名前(引数型,...)->返却型}`は、同じ仕組みで実行時エラーの可能性を参照する。未知もtrueとして扱う。sort_by_keyは変更もエラーもないと証明済みの比較に限って、位置を捕捉しない比較関数を作る。それ以外は実際の呼び出し位置を保持する。これは位置情報を省ける条件の問い合わせであり、未知のC++関数が失敗しないと仮定する機能ではない。

効果の問い合わせだけで参照した外部関数には、C++の前方宣言・本体の出力を要求しない。例えばUnitの操作について照会するだけで、値を呼び出すABIが必要になるわけではない。未知の外部関数のC++本体が未使用でも、その効果は未知のまま参照できる。

参照の返却型に未確定の型引数がある場合、引数型が決まった参照先の署名から補える。例えば`call __iter__(S)->I`と`call __iter_next__(I)->T`から、Sのイテレータ型Iと要素型Tを求める。コールバック・期待型の情報と合わせ、束縛が増えなくなるまで照合する。署名を調べる段階では本体の生成や型の具体化を行わず、選ばれなかった候補の生成物を残さない。

署名の問い合わせもジェネリックな引数位置の数で順位を付け、一意に決まる場合だけ返却型を補う。通常の具体関数と、引数型に型パラメータを含まないジェネリック関数は同じ0個の順位になる。すでに分かっている返却型を理由に通常のオーバーロードを選び直さない。最終的な参照の解決と署名検査は具体化時に同じ規則で行う。循環・過大な問い合わせには深さ32・処理量4096の上限を設け、上限を超えた候補を黙って除外して別の候補を選ぶことはしない。

具体化の登録を本体展開より先に行い、依存する外部関数を本体より前に宣言する。同じ型での自己参照やextern同士の相互再帰を扱い、型を無限に増やす展開には関数の具体化上限を適用する。修飾名を持つ具体的なexternは、その定義をアダプタより前に置く前述の規則を使う。任意のC++断片やsymbol間の依存を解析して並べ替えるものではない。

この仕組みで参照できるのは、通常の候補解決に登録された関数である。コンパイラの専用経路だけで実装している構築・高階操作が自動的に参照可能になるわけではない。捕捉環境を持つ関数値には、次の専用の型付き参照を使う。

## 外部型のC++表現から関数を参照する

外部型の`cpp_name`にも、明示した引数・返却型を持つ`@{value_call 名前(型,...)->型}`を使える。例えば`NativePolicy<{T},@{value_call evaluate(T)->Int}>`は、C++テンプレートの非型引数へ共通の値返却アダプタを渡す。Ruskの型から通常の候補解決を行い、同じC++型を使う異なるRusk型の操作を混同しない。後に宣言するRusk関数・修飾名付きの具体的externも参照できる。型の準備は関数を実行しない。

引数は`const Obj<本体型>&`と末尾の`Loc`、返却は宣言されたスカラーの本体値、Unitならvoidという既存の値参照ABIを使う。Unitの実オブジェクトを返すexternも、通常の値参照と同じ順序で呼び出しと後処理を行う。型の表現中には`fn`・コールバックのinvoke・本体の構造展開・効果問い合わせ・暗黙の引数列を置けない。

関数参照を含む具体型は、論理型の登録後、関数の署名がそろってからC++表現を準備する。必要な型別名とアダプタの前方宣言を、明示した型参照・関数署名の依存順に出す。関数本体は通常どおり後に定義できる。型別名を定義するためにその型別名自身を使った関数宣言が必要になる等、循環する宣言依存はC++生成前に拒否する。通常の関数本体の相互再帰とは区別する。

関数参照を含む具体型は512個、宣言依存は深さ128・処理量16,384を上限とする。マーカーの構文・型は未使用の宣言でも検査し、具体化時の不足する操作や宣言依存の診断には要求元の位置も付ける。生成する型別名や関数名の綴りは公開ABIではない。任意のC++名・断片の依存は推測せず、C++テンプレートの定義やincludeは同じ規則で宣言側で用意する。

[実行例](https://github.com/shogo314/rusk_b_10/blob/main/examples/beta08/native_type_function_references.rusk)は、構造体・入れ子の型・同じC++型の別の論理型・Unitの後処理を含む。

## 捕捉を持つコールバック

```rusk
extern fn apply<F,T,R>(f:F,x:T)->R {
    code: "@{return R} @{fn}(Obj<@{F}> f,Obj<@{T}> x,Loc loc){return @{invoke F(T)->R}(f,x,loc);}",
}
let total:=1;
let add:=(n:Int)=>(total+=n);
wt apply(add,2),total,apply((n:Int)=>"ok",1);
```

出力は`3 3 ok`。`invoke F(T)->R`はFが静的に分かる関数値であることと、その引数・返却型を要求する。この明示した参照を宣言の型要件として保持し、既存の関数値の型情報と照合する。型引数Rはコールバックの返却型から推論できる。コールバックを先に引数として渡せば、例えば`apply((xs:Vec<Int>)=>xs.len(),[])`の空配列にも型を伝えられる。

`invoke`の展開結果は呼び出し先の関数名であり、捕捉環境f、実引数x、LocはC++本体に明記する。型だけから捕捉値を作ったり、コンパイル時の値を埋め込んだりしない。同じ環境を共有した関数値と、`copy`で捕捉値を分離した関数値を、同じ具体化済みのexternへ渡せる。名前付きの具体関数も、共通の関数値への変換を通して渡せる。

`@{return R}`を使うと、RがUnitの場合も同じ宣言で扱える。C++では`void`を返す関数から`return callback(...);`と書けるため、値を返す場合とUnitの場合を分岐せずに表せる。このマーカーは返却型用であり、Unit型の引数の表現を変更するものではない。

関数値から別の関数値を返す場合も、それぞれの型情報から型引数を補える。型引数が増えなくなるまで照合を繰り返すので、参照マーカーの記述順には依存しない。これは明示した`invoke`参照による型の要件であり、任意のC++本体やRusk関数本体から一般の型要件を推論する機能ではない。文字列等に参照記法そのものを残す場合は、同じ規則で`@@{...}`でエスケープする。

関数値の捕捉環境の所有・コピーには既存の仕組みを使う。[外部型に関数値を保持する例](https://github.com/shogo314/rusk_b_10/blob/main/examples/beta08/extern_callback_lifetime.rusk)では、ブロック内の文字列の要素を捕捉し、外側で関数値を取得・コピー・呼び出す。元の文字列の共有先の寿命を維持し、コピーした捕捉値は分離する。

externによるコールバックの呼び出し回数や他の効果は保守的に扱う。作成者がコールバック引数に契約を指定する場合、コールバックの実行に伴う変更・保持や、返却値が捕捉値を共有する場合も保証の範囲に含める。コールバック内での実行時エラーは、通常のRuskの位置情報を保持する。

## externの引数契約 { #extern-parameter-contracts }

通常のexternとジェネリックexternの引数に `fixed`・`rebindable`・`readonly`・`mutable`・`noescape`・`escape` を指定できる。Rusk関数では本体を解析して注釈を検査する。externでは作成者がC++本体の動作を保証し、処理系はその宣言の`readonly`・`noescape`を呼び出し側の解析に使う。契約違反の検出は保証しない。

```rusk
extern fn detached_int(fixed readonly noescape value: Int) -> Int {
    cpp_name: "detached_int",
    code: "Obj<std::int64_t> detached_int(Obj<std::int64_t> value, Loc) { return make_obj<std::int64_t>(*value); }",
}
readonly let original := 3;
let result := detached_int(original);
result = 7;
wt original, result;
```

- `readonly` は、呼び出し中にその引数を経由して共有値・要素・フィールド・コンテナの構造を変更しないことを保証する。返却や保持を許す場合、呼び出し元ですでに付いている読み取り専用の制約も伝播し得る。
- `noescape` は、その引数やその要素・フィールド・捕捉値を、戻り値や外部の格納先に共有として残さないことを保証する。
- 省略、`mutable`、`escape` は対応する効果を未知として扱う。別の引数にも同じ値を渡した場合は、各引数経由の効果を検査する。I/O、外部状態の変更、失敗、停止性も未知のまま扱う。
- `fixed` はC++実装内の仮引数の共有先を結び直さないという作成者の保証として受け付け、`rebindable`は結び直しを許す。これらの注釈だけの場合、共有値の変更・保持・返却は未知として解析する。重複・矛盾の検査は通常のRusk関数と同じ。
- 契約はC++の `const`、引数の所有規約、戻り値の新規割り当てを指定しない。 `readonly`・`mutable`・`noescape`・`escape` と、標準ライブラリ内部の `effects`・`aliases`・`derive` との併用はできない。

ジェネリックexternでは、具体化されたC++本体とそこから呼ぶ関数が契約を守る必要がある。具体化やコールバックを含む例は [extern_contracts.rusk](https://github.com/shogo314/rusk_b_10/blob/main/examples/beta09/extern_contracts.rusk) を参照する。

## Unitの呼び出しと保存する値のABI

UnitのABIアダプタは、それを参照する値アダプタや外部本体より前に定義する。直接生成の式から通常・保存用のUnit参照を使う場合も、前方参照と同じ共有ABIを保つ。

通常の呼び出しでは、Unitは`void`、他の型は`Obj<本体型>`を返す。Unitを構造体・enumのフィールドや外部の保持型に保存する場合は、`Obj<Unit>`の値を扱う。この違いを関数名やC++本体の文字列から推測しない。

外部関数には`return_abi:"object"`を指定できる。C++本体がUnitでも`Obj<Unit>`を返すことを表し、他の型では通常の所有付き返却と同じになる。coreのUnitコピーにもこの宣言を付け、前方宣言を実装と一致させる。これは呼び出し形式の指定であり、利用者が効果・保持の信頼契約を付ける権限ではない。未知のexternの解析は引き続き未知である。不正なABIの値は未使用でも拒否する。

| 参照 | Unitの場合 | 他の型の場合 |
|---|---|---|
| `@{call name(Types)->R}`・`@{invoke F(Types)->R}` | 通常の`void`返却。実装が共有オブジェクトを返す場合はアダプタ内で破棄する | 通常の所有付き返却 |
| `@{boxed_call name(Types)->R}`・`@{boxed_invoke F(Types)->R}` | `Obj<Unit>`返却。実装が`void`なら呼び出し後に空のUnitオブジェクトを作り、オブジェクトABIなら実際の戻り値を保つ | 通常の所有付き返却 |
| `@{finish R}(std::move(value))` | 保存していた値を通常の`void`返却へ合わせる | 値の所有を余分にコピーせず返す |

`@{return R}`は通常の返却型を表すままなので、オブジェクトABIの定義側は`Obj<@{R}>`と明記する。参照には通常と同じ型照合・依存順序を使い、実際の関数が持つ効果を飛ばさない。Unitの変換アダプタ自体は引数を`const Obj<...>&`で受け、実際の関数の所有付き・借用ABIに合わせて渡す。関数から戻る前の後処理と、保存したUnitオブジェクトの実際の所有・破棄を維持する。

foldはコピー・コールバックの結果を保存する参照を使うため、Unitの初期値も扱える。返却は論理型の分岐を使い、Unitなら`return;`、それ以外ならaccumulatorを直接返す。通常のローカル値の返却を補助関数経由にするとC++の名前付き返却値の最適化（NRVO）の対象でなくなるため、`finish`が必要な式の変換と区別する。構造体・enumの自動コピーも、保存する値のABIを参照する。Unitの参照も論理型と返却ABIを区別して登録し、voidの呼び出しと格納用のオブジェクト返却を混同しない。

## 宣言の信頼元

標準ライブラリ・利用者ソース・処理系の生成物を、読込時の由来として区別する。表示用のファイル名では判定しない。この由来を関数宣言とジェネリック関数の具体化へ保持し、ネイティブ効果契約と直接生成の可否に使う。

標準ライブラリのジェネリックexternでは`effects`を指定でき、具体化した署名で既存の契約検証を通す。利用者のexternでは指定を拒否する。`<stdlib/core/types.rusk>`という表示名を与えても利用者宣言に権限は付かず、標準ライブラリの表示名を変更しても契約の意味は変わらない。由来を変更するソース構文やexternプロパティは提供しない。

標準ライブラリのRusk関数が呼び出し元のエラー位置を引き継ぐ規則も、同じ由来で判定する。表示名の変更で診断位置の扱いが変わったり、標準風の表示名を持つ利用者関数に引き継ぎ規則が適用されたりしない。

由来は信頼元を伝える情報であり、任意のC++本体の安全性の証明ではない。型・保持・操作の意味情報、直接生成、子の呼び出しとコールバックの効果・別名・保存先の合成は、後述の検査済みの宣言情報へ接続する。

## 標準宣言に付随する生成情報

標準ライブラリのexternには、通常の所有付きC++本体に加えて、直接生成に使う式を付けられる。以下は埋め込み標準宣言の記述例であり、利用者ソースに追加するコードではない。

```text
extern fn __add__(a:Int,b:Int)->Int {
    cpp_name:"rusk_add",
    code:"Obj<std::int64_t> rusk_add(Obj<std::int64_t> a,Obj<std::int64_t> b,Loc loc){return make_obj<std::int64_t>(checked_int(static_cast<__int128>(*a)+*b,loc));}",
    effects:"checked_read_fresh",
    lower:"checked_int(static_cast<__int128>(*$0)+*$1,$loc)",
}
```

`lower`は宣言されたスカラー表現の本体値、またはUnitの処理を表す。`lower_owned`は所有付きの結果を返す式、`lower_borrowed`は同じ結果を既存の所有元から借用する式で、後者には前者も必要になる。所有・借用の選択には共通の効果・寿命・区間解析による証明が必要であり、プロパティの存在だけでは借用にしない。`lower`と`lower_owned`の併用は拒否する。

参照は評価済みIR引数の`$0`・`$1`等と、呼び出し位置の`$loc`に限定する。`$$`はドル記号そのものを表す。引数の式を再評価する仕組みではない。引数の範囲と参照構文を検査し、任意のC++式の正しさは標準ライブラリの実装と回帰検証で保証する。`operation:"assign"`は、同じ型の二引数・Unit返却・`write_first`契約を持つ代入を表し、共有先の解析へ接続する。

これらは埋め込み標準宣言だけに認める信頼情報で、利用者宣言では表示ファイル名にかかわらず拒否する。通常のextern本体は関数参照や最適化無効時にも残る。backendは関数名による演算の選別をせず、具体化した宣言の生成情報を使う。基本型の表現・要素とスカラーの分類は次節の宣言情報を使う。Vec・Dict/Set・反復子・遅延状態の型と操作は通常のジェネリック宣言で定義する。

ジェネリックexternの`lower`・`lower_owned`・`lower_borrowed`でも、型付きの型・関数・効果の参照を展開できる。署名・参照の検査と型の推論はC++本体と共通に行い、値を返すアダプタ同士が前方参照しても宣言順に依存しない。

標準externが型付き参照やコールバックを使う場合、それらの関数を効果の依存として登録する。明示した外側の契約は最初から安全と仮定せず、参照先に書き込み・保持・返却する別名がなく、IO・失敗・停止性の効果も契約に収まると証明できた場合だけ適用する。多段の依存は不透明な状態から順に検証し、依存が循環しただけで純粋と判定しない。未知の利用者externや捕捉を変更するコールバックを、安全な外側の契約で覆い隠さない。

これは明示した標準契約を参照先に照らして検査する仕組みであり、任意のC++本体の自動検証ではない。射影を伴う効果・返却別名・保存先は、後述の型付き対応で合成する。対応から証明できない効果は不透明なまま扱う。利用者のexternに標準契約を主張する権限を与えるものでもない。

## 標準の型表現と共有先

埋め込み標準の外部型には`representation`で本体と共有先の分類を付ける。以下は内部用の宣言例であり、利用者ソースに追加する記法ではない。

```text
extern type Int { cpp_name:"std::int64_t", representation:"i64", }
extern type Str { cpp_name:"std::string", representation:"buffer<Char>", }
extern type<T> Sequence {
    cpp_name:"RuskVec<{T}>", representation:"vector<T>",
}
```

| 表現 | IR・解析に渡す情報 |
|---|---|
| `i64`・`bool`・`char`・`unit` | スカラー本体の種類。内部に別の共有値を格納する集約値としては扱わない |
| `buffer<T>` | 要素Tを持つバッファ。要素の参照元と、その論理型を共有先の射影へ渡す |
| `vector<T>` | 要素Tを格納する配列の形状 |
| `iterator<T>` | 反復で返す要素Tの情報 |
| `dict<K,V>`・`set<T>` | キー・値または集合要素の情報 |

由来が標準の場合だけ認め、未使用の利用者宣言でも拒否する。スカラーについては、C++コンパイル時にも整数の幅・符号、Bool/Charの本体、Unitの空で単純な表現を検査し、誤った表現の指定を拒否する。C++の`cpp_name`を見て表現を推測しない。同じC++型を使う利用者の外部型は不透明なままであり、表現の一致によって異なるRusk型を代入・引数の照合で同一視することもない。

ジェネリック型では、役割のラベルと参照する型を分け、参照先の型だけに型引数を代入する。役割と同名の型パラメータも混同しない。要素型の前方参照と、未使用ジェネリック宣言の型名・型引数の個数を検査する。不明な表現・誤った個数・不明な参照先はRusk側の位置で診断する。

基本型とRangeIterはcoreの宣言からIRへ情報を渡す。backendの直接保持・スカラー共有の候補、readonly/noescapeの集約値判定、文字列要素の型、ネイティブの要素取得・置換契約の整数添字もこの情報を使う。`unit`やBool条件などの言語上の意味は、IRのUnit返却・Bool条件の規約として引き続き検査する。型の表現を付けるだけで操作本体や借用ABIを自動的に用意するものではない。

配列反復型も宣言の情報へ接続する。Vec・Dict・Set・辞書や集合の反復・遅延反復も、通常の型宣言と表現・保持先の情報から登録する。一般の構造体コピーのように利用者の操作を呼ぶ可能性がある処理は、不透明さを維持する。再帰する形状や深すぎる形状も、それだけで安全なネイティブ深いコピーと仮定しない。任意のC++レイアウトや本体をRust側で検証する仕組みではなく、標準宣言の実装と共有先のモデルを一致させる責任は信頼された実装側にある。

## 未使用宣言の検査

外部ジェネリック型と関数について、未使用でも署名・型参照の型名と型引数の個数、マーカーと呼び出し参照の構文を検査する。型・enum等の宣言をすべて登録した後に行うので、前方参照も使える。型変数には仮のInt等を割り当てず、型変数のまま検査する。

`copy(T)`が実際に使えるか、具体的なオーバーロードが一意か、外部型の展開が循環するかは、型引数の確定後に検査する。未使用の参照先関数名の解決や任意のC++本体の正しさまで確認するものではない。参照内の型の入れ子は64段までとしている。

配列反復型`Iter<Vec<T>>`は`lib/collections/vec.rusk`の外部型パターンで定義し、C++表現と反復要素を宣言から登録する。具体的な`Iter<Int>`とも重ならず共存できる。型名による暗黙の登録は行わず、宣言した型パターンから解決する。Tupleはタプル構文の言語構築子として別に検査する。外部ジェネリック型は登録した型パターンの外側の引数から、Ruskの構造体・enumは宣言の型パラメータから個数を検査する。

## 対応範囲と制限

利用者の外部型・関数は、特定のライブラリ名の分岐を追加せずに定義できる。利用者externの効果には、このページの引数契約を反映する。標準ライブラリの信頼契約は組み込みの宣言に限定する。任意のC++本体とRusk署名・共有ABIの一致は、C++コンパイル時にも確認する必要がある。

型と関数の具体化・型付き参照・捕捉付きコールバック・表現と保持先・検査済みの効果・直接生成・構造の展開・外部資源と依存順序を共通化した。制限として、C++本文の任意の依存や効果の推測、完全な双方向型推論、一般の構造制約による候補選択は提供しない。未知の操作を使う契約は不透明のままとし、上限を持つ具体化・依存・展開を使う。

回帰テストは`extern_generics`・`extern_callbacks`・`library_migration`とcompilerの単体テストにある。型の具体化・型同一性・共有・コピー・保持・順序・診断と信頼元を通常版と最適化無効版で検証する。掲載した三つの実行例も`tests/extern_generics.rs`から直接読み取って実行する。

## 配列の宣言と出力契約

配列出力の標準契約には`checked_io_write`を使う。IO・停止待ち・実行時エラーの可能性を認め、型付きで参照する要素出力が引数や外部状態を書き換えず、共有値を保持せず、返却する別名もないと証明できた場合にだけ、引数の非変更・非保持の契約を有効にする。要素出力が計算のoverflow等で失敗し得ても、そのことだけでreadonly・noescapeを拒否しない。未知のexternの効果や保持を安全とは仮定しない。

標準の`Vec<T>`も`cpp_name:"RuskVec<{T}>"`と`representation:"vector<T>"`を持つ通常のジェネリック型宣言である。具体化・型引数の検査・IRの要素情報は他の外部型と共通で、Vec専用のC++型登録・IR分類・要素型の列挙を行わない。Unitや不透明な外部型も格納でき、各操作が必要とするcopy・比較等は利用時に通常の候補から解決する。Unitを返す取得・置換・反復・popもオブジェクトABIを宣言し、通常のRusk呼び出しで結果の共有値を維持する。

## enumの構築とフィールドの契約

標準宣言の`effects:"variant_constructor:N"`はenumのvariant Nを構築し、各引数を対応するpayloadへ共有して格納することを表す。結果がenumであることと、variantの存在・payloadの個数・論理型を照合し、返却した各フィールドの別名を記録する。`Some`という名前やvariant 0に固定した契約ではない。

`effects:"checked_variant_field:N:I"`は、enumである第一引数のvariant N・フィールドIへの共有を返し、取り出し時に失敗し得ることを表す。variant・フィールドの存在と返却型を検査する。Optionのvalueはこの契約を通常のジェネリックexternに付け、Unitの場合も`return_abi:"object"`で格納されている共有値を返す。これらの信頼契約は、他のeffectsと同じく埋め込み標準宣言だけが指定できる。

Optionの構築・検査・値取得・try_readは、通常のジェネリック宣言から解決する。try_readの型付き入力参照は通常のRusk関数・extern・構造化入力を選び、参照先の効果が契約を満たすまでは外側も不透明にする。言語構文の`??`・`?!`も、後述の通常の操作とenumの意味情報へ接続する。

## 任意個のフィールドを参照する

`@{fields T as F,I}`から`@{end}`までを、構造体・Tupleの各フィールドについて宣言順に展開する。`F`はフィールドのRuskの論理型、`@{index I}`は0始まりのフィールド番号を表す。例えばコピーの構築に使う明示部分は次のように書ける。

```text
@{T}{
    @{fields T as F,I}
    @{boxed_call copy(F)->F}(value->field_@{index I},loc),
    @{end}
}
```

その中の型・関数・ABI・効果の参照は既存の記法を使う。C++型が等しくても、論理型ごとに操作を解決する。Unitの格納には`boxed_call`等のオブジェクト参照を使う。生成したC++の評価順序は本体側で保証する。上の例の集約初期化リストは左から順に評価される。

`@{fields T tuple as F,I}`は、同じ展開を言語のTupleに限定する。構造体・不透明型・その他の型では、具体化時にRusk側で拒否する。通常の`fields`と同じ論理型・添字・局所束縛・展開上限を使い、`variant`との併用は未使用の宣言でも拒否する。型に応じた本体分岐と組み合わせて、ライブラリ側の操作の適用条件を記述できる。

束縛は展開内だけで有効で、入れ子にできる。外側の型引数・フィールド束縛との名前の衝突、未束縛の番号、番号を型として使うことを検査する。通常の大域型名は局所束縛を妨げない。未使用の宣言も構文・型・束縛を検査し、パースの入れ子は64段、参照は4,096個、具体化時の展開作業も4,096回に制限する。利用者externから呼び出し可能値の非公開の捕捉フィールドを列挙することはできない。

標準の自動コピーは`derive:"record_copy"`を持つ宣言を本体のテンプレートとして使う。この指定は埋め込み標準宣言だけが使え、一つの型引数と`(T)->T`の形を検査する。通常の呼び出し候補には追加せず、言語が用意するcopyの具体的な宣言を、その本体へ接続する。同じ役割の重複登録を拒否し、実装関数名では選ばない。enumのコピーには同じ署名検査と由来の規則を持つ`derive:"enum_copy"`を使う。代入・Tuple入力・多次元入力・出力・6比較も、後述の標準の役割テンプレートを使う。

## enumのvariantとpayloadを参照する

`@{variants E as V}`から`@{end}`までを、enumのvariantの宣言順に展開する。`@{index V}`で0始まりのvariant番号を参照し、`@{fields E variant V as F,I}`から`@{end}`までで、そのvariantのpayloadの論理型とフィールド番号を束縛する。既知のvariantだけを使う場合は、`variant 1`のように番号を直接書くこともできる。

```text
@{variants E as V}
case @{index V}: {
    @{fields E variant V as F,I}
    auto field_@{index I} = @{boxed_call copy(F)->F}(
        rusk_enum_payload<@{E},@{index V}>(snapshot).field_@{index I}, loc);
    @{end}
    // 本体側で保持した結果を構築へ渡す。
}
@{end}
```

variantとフィールドの束縛は局所的で、入れ子のenum・構造体・Tupleにも同じ型参照を使う。未束縛のvariant番号、番号の範囲外、enum以外の列挙・payload参照をRusk側で診断する。構文・束縛・型は未使用でも検査し、展開の深さ・作業量はフィールド展開と共通の上限を使う。

標準enumコピーは、コピー開始時のpayloadを保持し、各フィールドのコピーを宣言順に呼び出す。その後、コピー済みのオブジェクトを移して新しいenumを構築する。`derive:"enum_copy"`を持つ標準テンプレートでこの本体を記述し、コンパイラにvariantごとのコピー関数の選別やswitch本体の組立てを残さない。空のvariantと、空／単一payloadに対する表現の最適化も、共通のenum構築・射影を通して扱う。

## 集約値の代入を導出する

標準の構造体・Tuple・捕捉環境の代入本体には`derive:"record_assign"`、enumには`derive:"enum_assign"`を使う。一つの型引数と`(T,T)->Unit`の形を検査し、利用者の宣言による指定や同じ役割の重複を拒否する。コピーと同じ由来・型参照・関数参照を使い、標準の実装関数名には依存しない。

本体では、`rooted_call copy(T)->T`で元の値をコピーしてから、既存の代入先へ内容を書き戻す。外側のオブジェクトとその別名は保ち、自己代入でも先にスナップショットを作る。構造体のフィールドを更新しながら古い共有値を解放する順序も維持する。全フィールドを一度に差し替えた後で解放する操作へ変更しない。

必要になった代入だけを具体化し、型付きのコピー依存を記録する。効果・保持の契約は同じ規則で不透明として扱い、由来が標準であることだけでreadonly・noescapeを許可しない。標準テンプレートから展開した関数は、共通アダプタの宣言・定義より後に出力し、C++の名前空間付きの具体的なexternの定義順とは区別する。

## 呼び出し側が入力を保持している参照

`@{rooted_call 名前(型,...)->型}`は、引数のスロットとその共有オブジェクトを呼び出し側が処理完了まで保持すると約束したC++から使う。引数は`const Obj<...>&`、結果は`Obj<...>`、末尾は`Loc`で、所有付き参照と同じABIである。例えば代入テンプレートの値渡しの`Obj<T> source`は、この保持を満たす。コンテナの要素スロットを直接渡す代わりに、`auto held=(*values)[i]`で保持してから渡すこともできる。

標準宣言の`lower_rooted`があれば使い、なければ既存の`lower_owned`、安全と証明できるスカラー式、通常の呼び出しへ順に委譲する。`lower_rooted`は埋め込み標準宣言だけが指定でき、`lower_owned`と併記し、同じ型・束縛・引数番号を検査する。自動集約コピーにも、呼び出し側の保持を使う共通ABIの生成情報を登録する。

`owned_call`では、未知の操作が呼び出し中に格納元を消す場合も入力を保持する。`rooted_call`ではその保持を呼び出し側が担うため、すでに所有する引数の重複保持を避けられる。通常の利用者関数に対しては実際の呼び出しと返却する別名を維持し、Unitのvoid・オブジェクト両ABIも同じ返却変換へ接続する。効果や保持を安全と推測する指定ではない。

## 自動コピーを具体化する時点

構造体・Tuple・enumのcopyの宣言は型とともに登録し、本体とフィールド操作は実際の呼び出し・関数参照・効果問い合わせで必要になった時点で解決する。共有・射影・パターン照合だけなら、未使用のフィールドcopyは要求しない。`writes copy(T)->T`・`fails copy(T)->T`だけを使う場合も、導出した操作の契約を参照する。

親のcopyが子のcopyを参照した場合は、必要な操作がそろうまで解決する。実際に必要なフィールドcopyがなければRusk側で診断する。遅延反復の通常の宣言が要求するコピーも、その型付き参照の依存として保持する。

## Tuple入力の標準テンプレート

`derive:"tuple_read"`は、一つの型引数と`()->T`の署名を持つ標準専用の本体テンプレートを登録する。既存の入力操作が見つからないTupleに、言語の入力規約から接続する。通常の入力候補を先に選ぶため、利用者が定義したTuple readerの優先は維持する。

フィールドの論理型ごとに`boxed_call __read__()->F`を使い、先に各入力を宣言順に保持してから集約値を構築する。Tupleの階層を専用のC++組立てで再帰せず、同じ操作参照を使って子の入力を解決する。構築時に共有値を格納し、言語上のcopyを別途要求しない。通常の入力・関数参照・効果問い合わせで必要になった本体を具体化し、効果・保持は共通の不透明な契約を維持する。

同じ本体を通常の利用者ジェネリックexternとして記述すれば、構造体・Tupleを明示的に指定して入力できる。役割を指定する権限と、フィールド展開・型付き入力参照の利用可否は別であり、通常の利用者externが標準の由来を得ることはない。

## 固定個数の引数の列挙

ジェネリックexternの本体で、`@{arguments as P,I}`から`@{end}`までを引数の宣言順に展開できる。PはRuskの論理型、`@{index I}`は0始まりの元の引数番号であり、追加のLocは数えない。`@{arguments from 1 as P,I}`なら先頭を除き、番号は元のままにする。引数と同じ個数のオフセットでは空の展開となる。

型付きcall/invokeと効果問い合わせの引数型列では、`...arguments 1`で先頭以外の引数型を展開できる。`@{boxed_call __read__(...arguments 1)->T}`のように、通常の型付き参照の名前解決・ABI・依存関係へ接続する。C++の値は別に渡し、任意の引数式やC++字句を自動置換しない。

束縛はフィールド展開と同じ局所規則に従う。外側の型引数・添字の隠蔽、添字の型としての使用、範囲外・不正なオフセットは未使用宣言でも拒否する。引数列の展開も既存の深さ・作業量の制限を共有する。これは固定個数の引数を持つexternの本体記法であり、Ruskの可変長引数ではない。

多次元配列入力の標準テンプレートは、長さの引数列と型付き入力参照にこの展開を使う。

## 出力操作の導出と通常の契約・直接生成

標準の`derive:"tuple_write"`は、一つの型引数を持つ`(T)->Unit`をTupleの出力へ接続する。本体のフィールド列挙と`value_call`を使い、各フィールドの論理型から通常の`__write__`を解決する。役割の登録は標準の信頼元に限り、署名・重複を検査する。

この役割の`effects`と`lower`等の情報は、通常のジェネリックexternと同じ検査・具体化・契約依存へ接続する。宣言の効果契約だけで子の操作を安全と扱わない。全依存の非変更・非保持等を証明できた場合に契約を使い、未知の操作には所有元とフィールドを保持する。Unitの返却オブジェクトと引数の後処理の順序も共通の値参照ABIで扱う。

## 論理型のパターンによる本体の分岐

`@{if_type T matches Bool}`から`@{else}`・`@{end}`までで、Ruskの論理型が一致した側だけを具体化する。`@{if_type T matches Vec<E> with E}`では、一致した側に限り要素の型をEへ束縛する。`else`は省略できる。C++型が同じでも異なる論理型は区別し、繰り返す型変数は同じ型に一致しなければならない。

外側の型引数・添字の隠蔽、パターンに現れない局所変数、不正な型・参照、既知の引数の範囲は両分岐について未使用宣言でも検査する。局所変数は一致した側だけで使え、具体型の名前との衝突で束縛の意味が変わらない。選択した側だけが実際の呼び出し・効果依存を追加する。深さ64・参照数4096・展開作業量4096の共通の制限を使う。

Tupleの6比較は通常の型付き参照と、標準の`tuple_eq`・`tuple_ne`・`tuple_lt`・`tuple_le`・`tuple_gt`・`tuple_ge`の役割へ接続する。署名は一つの型引数と`(T,T)->Bool`を検査する。Bool要素の順序は、この本体分岐を使った通常の要素比較宣言で扱う。

## 構築と添字に対する通常の推論

Dict/Setの構築・主要操作も通常のジェネリックexternで宣言する。型付きの`@{boxed_call V()->V}`は、その論理型の引数なしの構築関数を通常の候補から解決する。構築関数がない場合は、その型に引数なしのコンストラクタがないことを診断する。

添字の取得・設定に必要なキーと値の型は、`__getitem__`・`__setitem__`の通常の引数型から推論する。取得結果の期待型も通常の型引数推論へ渡す。別名の利用者の外部型と操作にも同じ経路を使い、Dict等の型名から引数の型を選ばない。Unitを格納して返す操作には`return_abi:"object"`を使い、元のオブジェクトの同一性を維持する。

## 外部型の保持メンバーと返却別名

標準由来の外部型には`retains:"owner:Vec<T>"`のように、内部に保持する共有値の名前と論理型を指定できる。複数なら`source:I;callback:F;cached:R`とセミコロンで並べる。反復型の`representation:"iterator<T>"`と併用でき、表現を省略した不透明型でも使える。スカラー・配列等の別の表現との併用は拒否する。この名前は解析上の保持先であり、利用者がアクセスできるRuskのフィールドやC++のレイアウトを生成しない。

関数には既存の`effects`と併せて`aliases`を指定する。

| 宣言 | 返却値と引数の関係 |
|---|---|
| `aliases:"return.owner=0"` | 新しい結果のownerが第1引数を共有する |
| `aliases:"return.owner=0.owner"` | 結果と第1引数はownerを共有する。外側の状態は新しく作れる |
| `aliases:"return=0"` | 第1引数自体を返す。結果を新しい独立した割り当てとは扱わない |
| `aliases:"fresh;return=1"` | 第2引数を返す場合と新しい結果を作る場合がある |
| `aliases:"return=0.owner.element"` | 第1引数のownerが保持する配列要素・文字を共有して返す |

複数の対応はセミコロンで並べる。パスの各メンバーを保持宣言、構造体・捕捉環境のフィールド、配列・文字列の`element`から論理型で解決し、両端の型の一致を検査する。保持宣言は64メンバー、別名対応は64件、パスは16段までとする。型・記法・引数番号は未使用の宣言でも検査し、具体的な保持先と型の一致は具体化時に検査する。

返却値を通して共有することと、呼び出し外の別の場所に保持することを区別する。これらの対応は引数のescapeを伝えるが、外部保持のretainedを新たに主張しない。既存のreadonly/noescapeの推論・検証とヒープ上の別名追跡へ接続し、Rusk関数をまたぐ場合も保持先を維持する。型も関数も標準ライブラリ由来に限定し、利用者externの契約詐称を拒否する。未知の効果を持つ契約に対応を加えても、その効果を安全な契約へ変えない。

Vec・Dict/Setの反復子はowner、Mapped/Filteredはsource・callback・cachedを宣言する。閉じた反復子の構築・コピーと恒等操作は上の対応を使う。子の操作・コールバックの効果合成と、返却・引数へ保存する対応は次節の型付き情報で検査する。未知の子は不透明のまま扱う。保持先の型情報だけを追加して、その操作全体が非変更・非保持になったとは扱わない。

## 子の呼び出しと保持先を対応付けて効果を合成する

標準の関数・コールバック参照には、実装が渡す値と結果の格納先を明示できる。

```text
@{owned_call copy(I)->I via (0.source) into return.source}
@{boxed_invoke F(T)->R via (0,1) into return}
@{boxed_invoke F(T)->T via (2,1) into 0.value}
@{rooted_call copy(T)->T via (1) into 0}
```

`via`の各項は外側の引数番号と保持先のパスで、子の引数と順に対応する。invokeでは捕捉環境を渡す第1引数も明示する。`into return.source`は子の結果を外側の結果のsourceへ格納し、`into return`は結果自体を返す。`into discard`は子の結果を外へ返さず破棄する。`into 0.value`は第0引数のvalueへ結果を保存し、`into 0`は第0引数の内容を結果の内容で置換する。ルートへの指定は呼び出し元の引数参照の結び直しを表さない。通常のcall・boxed/value/owned/rooted参照とinvoke・boxed_invokeで同じ対応を使い、問い合わせのwrites/failsでは使わない。型の`cpp_name`にも対応の注釈は持ち込まない。

引数・結果の両端を論理型で検査し、子が返す別名のパスを対応先へ合成する。破棄した子の戻り値だけを理由に、外側の引数をescapeとはしない。子のread/write・構造変更・外部保持、IO・失敗・停止性も合成する。現行の引数効果は引数全体のmay-setなので、射影先の変更・外部保持は所有する引数全体へ保守的に伝える。外側の直接の処理または子が状態を書き換える場合は、後続の射影が別の引数を指す可能性がある。変更・構造変更・外部保持は引数間でも保守的に広げ、返却元は不明へ広げる。対応のない参照では、宣言した外側の契約に対する包含検査を使う。

標準由来に限定し、未使用でも対応の記法・引数番号と固定の引数数を検査する。具体化後に保持先・捕捉環境を含む署名・型の一致を検査し、不一致には具体化の要求位置を付ける。対応引数は64個、パスは16段、関数当たりの異なる対応は4,096個までとし、合成後の別名も64件・16段の上限を維持する。

効果の推論では、対応付きの子の効果が解決した後で外側を有効にする。未知のextern・未解決の効果・循環したネイティブ依存を純粋とは仮定しない。対応のない既存の参照は共通の契約の包含検査を維持する。一つの参照を対応付きにしても、別の対応のない参照の検査を免除しない。C++の字句や実際の引数式を解析する機能ではなく、標準実装の作者が実装と一致する対応を書く契約である。

既存の引数への保存では、保存先の論理型と子の結果型の一致を検査する。保持メンバーと構造体の物理フィールドの両方を扱い、保存先の変更・構造変更と、子の結果に含まれる入力別名の外部保持を伝える。結果が独立していれば、その保存だけでは入力を保持したとは扱わない。返却元が不明なら外側の全引数を保持し得るものとする。保存先は既存の領域なので、Ruskの局所的な集約領域の解析を流用してprivateとは証明しない。書き換え後の射影先の変化も、上記の引数間の保守的な合成を使う。

遅延反復のcopyはsource・callback・cachedのコピーにこの対応を使う。所有元を共有する子のcopyも不透明とせず、その共有を結果へ伝える。子の変更がないと分かった場合だけ、所有付きの直接生成で元の状態の追加保持を省く。未知の子、構造変更、入れ子の共有、捕捉付きコールバックにも同じ共通の解決を使う。遅延状態の代入も、copyの結果を既存の第0引数へ保存する対応を使う。Rangeの状態・スカラー捕捉だけを独立してコピーする場合はnoescape入力の代入を許可し、配列の所有元を共有する場合は外部保持として拒否する。契約がない操作や内部の一時値の効果が不明な操作は、通常のexternと同じく不透明とする。適用先と精度の境界は[処理系とライブラリの分担](architecture.md)も参照する。

## C++断片のファイル参照と依存順序

`extern symbol`は、`code`の代わりに`code_file:"native.hpp"`、または`code_files:"base.hpp;helpers.hpp"`を指定できる。パスは宣言を書いたRuskファイルのディレクトリから解決し、UTF-8の内容をそのまま埋め込む。複数ファイルは指定順に、区切り文字を挿入せず連結する。`code`・`code_file`・`code_files`の併用、空のリスト、存在しない・読めないファイルは宣言位置で拒否する。複数ファイルのリストは4,096個までとする。

`depends:"Support,Codec"`は先に出す外部シンボルを指定する。宣言順や名前の前後に依存せず、全宣言の登録後に依存を検査する。同じ時点で依存を満たした候補は名前順に出す。元の`depends`のないシンボル同士の順序を維持し、同じシンボルを二重に出さない。未定義の依存・不正な名前・重複する依存・循環はRusk側で診断する。反復的に並べ替え、シンボル4,096個・依存辺65,536個の上限を持つ。

これはC++の字句解析や`#include`の再帰展開ではない。型マーカー・コメント・文字列・マクロも含めてC++ファイルのバイトを維持し、必要な改行と宣言・依存は実装側で指定する。同じファイルを複数箇所で指定した場合も、指定ごとに内容を埋め込む。一方、`rusk dependencies`のファイル一覧はRusk includeとC++資源を正規化したパスで重複なく報告する。C++がさらに参照する独自ヘッダーは、別の外部シンボルとして宣言する等、実装側で組み立てる。

標準preludeは`lib/prelude.rusk`の通常のincludeで列挙し、C++断片は`lib/runtime/prelude.rusk`から同じプロパティで読み込む。`lib/`内のRuskとC++資源のカタログをビルド時に生成する。カタログは実行ファイルへの梱包に使い、読込順や型・関数名による操作登録、信頼判定は決めない。標準・利用者の由来はSourceの属性で渡し、ファイル名や埋込資源風の表示を権限とはしない。埋込資源が不足した場合に実ファイルへ暗黙にフォールバックしない。

[ファイル参照と依存の例](https://github.com/shogo314/rusk_b_10/blob/main/examples/beta08/runtime_resources/example.rusk)は、辞書順と逆の依存を持つ利用者シンボルと標準の遅延反復を組み合わせる。相対パス・重複include・依存ファイル一覧・リポジトリ外からの単独コンパイル・原文のマーカーの保持・宣言の信頼境界も検証する。

## 短絡演算から通常のenum操作へ接続する

`a ?? b`は、左辺を一度評価し、`__coalesce_test__(a)->Bool`と、存在する分岐内の`__coalesce_value__(a)`を通常の候補から解決する。もう一方の分岐でだけbを評価する。bの型は値取得の返却型と一致し、取得した値を暗黙にコピーしない。`a?!`も型名を検査せず、`value(a)`を通常の候補から解決する。標準のOptionはこれらの操作を宣言する。利用者のenum・構造体・externにも通常の関数で対応できる。

標準の検査と取得には`operation:"enum_test:V"`・`operation:"enum_field:V:F"`を付けられる。1引数のenum、variantとpayloadの範囲、Boolの検査結果とpayloadの論理型を検査する。検査は`read_fresh`、取得は対応する`checked_variant_field:V:F`が必要で、独自のaliasesとの併用を拒否する。Unitのpayload取得は実オブジェクトの返却ABIを必要とする。属性の記法は未使用でも検査し、型・範囲は具体化した宣言で検査する。利用者由来の属性指定を拒否する。

通常の候補解決で選んだ両操作の意味情報が同じenumの同じvariantを指し、参照先の呼び出しを伴わない場合、コンパイラは既存のVariantTestと検査済み分岐内のVariantFieldを使う。Optionの名前やvariant 0を使う条件はない。この経路は共有・寿命・効果・確保数を保つための意味情報で、C++本体の字句解析ではない。参照した子の呼び出しを省いたり、未知の利用者操作を検査済みの取得へ置き換えたりしない。単独で値取得関数を呼ぶ場合も、通常の失敗可能な呼び出しとして検査を残す。

期待される結果型から、値取得の通常の署名を通して左辺の型引数を補う。複数の候補がある場合は、左辺を作る関数・enumコンストラクタの宣言された結果型と整合する文脈だけを用いる。文脈を調べる間に左辺や右辺を実行しない。標準のNoneと別の空variant・空値構築関数が共存する場合も検証する。完全な双方向型推論を追加したものではなく、通常の宣言と型注釈の規則を使う。

[利用者の操作の例](https://github.com/shogo314/rusk_b_10/blob/main/examples/beta08/coalesce_protocols.rusk)は、短絡・共有・期待型・文字参照・構造体のvalueを確認する。標準由来の別名のenumでは、variant 1のpayload 1を取得して両モードで実行し、nullableな配置やOptionの並び順への依存がないことを検証する。

## bare値のゼロ引数構築を宣言する

具体・ジェネリックexternに`implicit_call:"true"`を付けると、bare名を参照するたびにゼロ引数で呼び出す。標準の`None`もこの宣言を使う。引数がない通常のexternだけに指定でき、不正な値・引数付き・導出テンプレートとの併用は未使用でも宣言位置で拒否する。関数名の系列にbare呼び出しの規約を登録し、その系列の通常のゼロ引数候補を期待型とともに解決する。値のキャッシュや初回だけの呼び出しは行わない。

[別名の実行例](https://github.com/shogo314/rusk_b_10/blob/main/examples/beta08/implicit_calls.rusk)では、利用者のVacantから期待型に合うOptionを構築し、tickの副作用が参照ごとに実行されることを確認する。型引数が決まらない場合は通常の推論エラーとし、ローカル変数・捕捉した変数があればそちらを優先する。指定のないRusk関数・externのbare参照は通常の関数値として扱う。修飾したenum variantの既存の構築構文とは別に扱う。

利用者のexternにも指定できるが、これは呼び出しの記法だけを決める情報である。Sourceの由来・共有ABI・未知の効果を変更せず、effects・aliases・lower等の標準専用情報を指定する権限も与えない。
