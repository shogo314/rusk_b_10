# 文書コメント

ソースに付けるAPIの説明には`///`、ファイル全体の説明には`//!`を使います。本文はMarkdownとして抽出します。これらは構文上はコメントであり、プログラムの実行の意味を変えません。

## 宣言の説明

`///`は行頭の空白に続けて書き、説明する宣言の直前に置きます。連続する行を1つの説明にまとめます。

```rusk
//! 小さな計算の例です。

/// 2つの整数の和を返します。
///
/// オーバーフローした場合は実行時エラーになります。
fn add(a: Int, b: Int) -> Int {
    return a + b;
}
wt add(2, 3);
```

出力は`5`です。空の説明行は、ソースの空行ではなく`///`だけの行にします。行頭の`///`と、その直後の空白1つを除いた部分をMarkdownの本文として使います。インデントしたコード例や箇条書きも記述できます。引数・戻り値・失敗条件はMarkdownの見出しや文章で説明し、専用タグは設けていません。

| 対象 | 書く場所 |
|---|---|
| 関数、struct、enum | `fn`・`struct`・`enum`の直前 |
| externの関数・型・symbol | `extern`の直前 |
| structのフィールド | フィールド名の直前 |
| enumのvariant | variant名の直前 |

説明と宣言の間にソースの空行や通常のコメントを挟むと、説明は宣言に付きません。コードの後ろに続けた`///`、`////`で始まるコメント、宣言先のない`///`も宣言の説明として抽出しません。変数・引数への個別の文書コメントは現在の抽出対象に含めません。

includeの前に付けた説明が、include先の宣言へ付くことはありません。抽出は各ソースファイルの構文と位置に基づいて行います。

## ファイルの説明

`//!`は、ファイル内で最初のコードが出現する前に、行頭の空白に続けて書きます。ライセンスなどの通常のコメントが先にあっても構いません。コードより後の`//!`や、コードと同じ行の末尾の`//!`はファイル説明として抽出しません。

複数の説明行を改行でつなぎ、間にソースの空行があれば段落を分けます。行頭の`//!`と、その直後の空白1つを除いた内容を使います。ファイル説明は名前空間を作るものではありません。

## 整形と文書生成

フォーマッタは説明の内容だけでなく、説明が付く宣言と、説明として抽出されないコメントの扱いも保ちます。空行で説明を切り離した状態や、開き括弧の直後の同じ行にあるコメントを、整形によって宣言の説明へ変えません。

`rusk search`と`rusk doc`は同じ宣言情報と文書コメントを使います。組み込み標準ライブラリでは、公開用の宣言ごとに説明を書きます。CLIの対象指定と出力形式は[コマンドライン](../getting-started/cli.md#api-docs)を参照してください。

標準APIの説明に単独で実行できる例を載せるときは、`rusk`のコードフェンスの後に空行、`出力`の行、空行、期待する出力を示す`text`のコードフェンスを置きます。`tests/api.rs`が該当する例を抽出し、入力なしでコンパイル・実行して出力を照合します。宣言の断片や実行しない例は`text`で記述できます。
