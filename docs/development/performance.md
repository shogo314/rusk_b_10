# 性能と最適化

最適化は、共有・コピー・評価順序・実行時エラーを保つ範囲で行います。特定のベンチマークの改善を言語全体の速度保証とは扱いません。

## 現在の仕組み

バッファ入出力、基本値の一時結果の遅延実体化、閉じたInt・Bool・Charの値保持、証明できた引数・配列要素の借用を使います。共有を外へ渡す場合や、寿命・変更・脱出を証明できない場合は所有付きの共有値を残します。

標準操作の直接生成は、宣言に付随する`lower`・`lower_owned`・`lower_borrowed`と検査済みの効果を使います。関数名を見て別の計算へ置き換える方式ではありません。[externの生成情報](extern.md#native-lowering)と[変換パイプライン](pipeline.md)を参照してください。

`--no-opt`はC++側の表現と直接生成を切り替える比較用の経路です。HIR/LIRの型検査や契約検査は共通です。extern本体に明示した値返却などの参照ABIまで変更するオプションではありません。

## 測定する

```bash
cargo build --locked --release
python3 tools/benchmark.py --compiler target/release/rusk --repeats 7 --output /tmp/rusk-benchmark.json
```

同じ入力でRusk・手書きC++、利用可能ならPyPyの出力を照合し、実行時間と環境情報をJSONへ記録します。C++のコンパイル時間は実行時間に含めません。`--baseline-compiler PATH`で保存済みの処理系、`--compare-no-opt`で最適化無効版とも比較できます。比較元が全項目を実行できる場合だけ`--baseline-all-cases`を使います。

テストや他の測定と同時に実行せず、処理系・入力・生成物のハッシュ、コンパイル条件、回数、各回の値を残します。短い実行の数%の差を、そのまま改善・退行とは判断しません。
