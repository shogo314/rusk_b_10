# エラーと制限の調べ方

Ruskの変換、C++のコンパイル、生成した実行ファイルの実行は別の段階です。どこで失敗したかによって確認する箇所が変わります。

```bash
cargo run -- compile main.rusk -o main.cpp
g++ -std=c++20 -O2 main.cpp -o main
./main < input.txt
```

シェルは各行を順に実行します。変換に失敗した場合は先にソースを直し、古い生成ファイルをコンパイルしないようにします。

## 処理系の内部エラー

処理系がpanicした場合は、標準エラーに`Rusk internal compiler error`と、処理系のバージョン・処理段階・原因・Rust側の発生位置を表示します。これは通常の型エラーや入力ソースの診断とは異なり、処理系の不具合として調べるための情報です。診断と、再現に必要なソースや実行方法を添えて報告してください。

`RUST_BACKTRACE=1 rusk compile main.rusk`でバックトレースも表示できます。内部エラーの後は処理を続行せず、以前の生成ファイルが残っていても成功した出力とは扱わないでください。内部の整合性検査と利用者向け診断の経路は継続して監査しており、すべての誤変換や利用者入力によるpanicを検出・排除できたことを保証するものではありません。

## 構文エラー

括弧やセミコロンの不足、未対応の構文などは解析段階で失敗します。パーサーの診断に続いて、`ファイル: syntax error` を表示します。示された位置の直前も確認します。

| 書いた構文 | 確認・修正 |
|---|---|
| `let x := 1` | 末尾に `;` を付ける |
| `if flag wt 1;` | 本体を `{ wt 1; }` で囲む |
| `else if ...` | `else { if ... }` にする |
| `[1, 2,]` | 配列末尾のカンマを取り除く |
| `let x := if flag { 1 };` | if式には `else { 2 }` が必要 |
| `f<Int>(x)` | 明示的な型引数は `f::<Int>(x)` |
| `(1,)` | 単一要素タプルは未対応 |

[文法一覧](grammar.md) に全構文と末尾カンマの可否を記載しています。

## 型・名前・初期化のエラー

意味の検査では、原則として `ファイル名:行:列: メッセージ` を標準エラー出力へ表示し、終了コード1で終了します。位置はエラーの検出箇所です。

| 状況 | 確認すること |
|---|---|
| 名前が見つからない | 綴り、ブロックのスコープ、`include`。名前付き関数はトップレベル変数を捕捉できない |
| 同じ名前を再宣言した | `in` も宣言。`for` の変数と本体直下は同じスコープ |
| 未初期化の読み取り | `let x: Int;` のように初期値なしで宣言した変数は、読む前に `x := value;` で初期化する。宣言後の `x = value;` は初期化に使えない。宣言時の `let x = value;` はコピーによる初期化として使える |
| 型が一致しない | `Int` と `Bool` などの暗黙変換はない。引数・戻り型も確認 |
| 空配列の型が分からない | `let a: Vec<Int> := [];` のように注釈を付ける |
| `no matching function` | 引数の個数と型、必要な演算・コピー・出力の定義を確認 |
| `ambiguous` | 適用可能なジェネリック候補を一つにする。明示型引数だけでは候補間の曖昧さを解消できない場合もある |
| タプルの添字が不正 | `p[0]` のような範囲内の非負整数リテラルにする |
| 構造体構築の失敗 | 全フィールドを一度ずつ、正しい型で指定する |
| 不明なループラベル | 対象が有効範囲内か、関数・クロージャの境界を越えていないか確認 |
| ブロックの型が合わない | 末尾の式の`;`を確認。末尾の式がなければUnit |
| 再帰的な型 | 自己参照・相互参照する型は未対応 |
| 戻り値がない経路 | 非`Unit`関数は末尾まで進まず値を返す必要がある。ループだけでは証明できない場合がある |

型引数付き関数の本体で失敗すると、定義内の失敗箇所に加え、`while instantiating` と具体化を要求した呼び出しの位置・型引数を表示します。呼び出した側で決まった型について、その演算が定義されているかを調べます。未使用のジェネリック関数が書けたことだけでは、その本体が全ての型で動くとは限りません。

## includeのエラー

パスは現在の作業ディレクトリではなく、`include` を書いたファイルの場所が基準です。見つからない場合は、その基準からファイルが存在するか確認します。循環読み込みは、関連する位置と経路を示して拒否します。

```bash
target/debug/rusk dependencies path/to/main.rusk
```

読み込んだ依存ファイルの正規化した絶対パスを確認できます。このコマンドは読み込み・構文解析を行うもので、型検査やC++生成の成功を保証するものではありません。型の検査には `compile` を使います。

## 実行時エラー

生成したプログラムは、検出したエラーをソースのファイル名・行・列とともに標準エラー出力へ表示し、終了コード1で終了します。失敗した演算の場所を示し、関数の呼び出し履歴は表示しません。`include` 先なら元のファイルの位置です。

| 原因 | 例・対処 |
|---|---|
| 整数のオーバーフロー | `Int` の範囲を超える加算・乗算、最小値の絶対値など |
| ゼロ除算 | `/` と `%` の除数を確認 |
| 添字の範囲外 | 空配列や文字列の長さ、負数添字の下限を確認 |
| 不正な入力・EOF | 必要なトークン数、型、ASCIIの制限を確認 |
| 不正な型変換 | `Int("abc")`、範囲外のASCIIコードなど |
| 負の配列長 | `[value; n]` や配列入力の長さを確認 |
| 不在の取得 | `?!`・`value()` の前に確認するか `??` で既定値を用意 |
| 走査中の辞書・集合変更 | 新規キー追加・削除・全体代入を走査の外へ移す |
| 走査中の配列変更 | 追加・反転・ソート・配列全体の代入を走査の外へ移す |
| 文字への共有中の長さ変更 | `let c := s[0];` の共有が残っていないか確認。独立した文字が必要なら `let c = s[0];` |
| `assertion failed` | `assert` の条件やデータ構造の添字・区間の前提を確認 |

検査はメモリ不足や外部C++の不具合を全てRuskの診断に変換するものではありません。自作の外部実装は共有・コピー・引数型の契約を守る必要があります。

## C++側で失敗した場合

通常の型エラーはRuskの変換時に検出する方針ですが、プロトタイプの未対応の組み合わせや外部宣言の誤りでC++のコンパイルが失敗する場合があります。`extern` を書いた場合は `cpp_name`、C++の関数シグネチャ、型のコピー処理を確認します。

処理系の問題を調べる際は、最小のRuskソース、入力、変換コマンド、C++コンパイラのバージョン、エラー出力を残すと再現しやすくなります。実装済みの範囲は [対応機能と制限](status.md) と [標準ライブラリ](../library/index.md) で確認できます。

## パターン分岐の診断

未処理の入れ子パターン、前のarmで覆われたパターン、orの束縛名・型の不一致、同名の重複束縛、構造体の不足・重複フィールドを変換時に検出します。ガード付きarmだけでは網羅的と見なしません。診断例と修正方法は[パターン分岐](patterns.md)を参照してください。
