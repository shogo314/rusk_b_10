# 演算子

使える演算子と、結果の型・共有・評価順をまとめます。通常の演算は型別の関数へ接続し、短絡評価や結び直しは処理系が構文として扱います。[型ごとの対応状況](types.md)と[演算フック](semantics.md)も参照してください。

## 一覧

| 分類 | 構文 | 主な結果・動作 |
|---|---|---|
| 符号 | `+x`・`-x` | 整数・Floatの独立した結果。整数の負号は範囲を検査 |
| 算術 | `+`・`-`・`*`・`/`・`%` | Int・Int128の検査付き演算とFloatの四則演算。型別に文字の移動・差、文字列や配列の連結も定義 |
| 累乗 | `**` | Int・Int128の検査付き累乗、Floatの累乗 |
| ビット | `&`・`\|`・`^`・`~`・`<<`・`>>` | Int・Int128のビット演算 |
| 比較 | `==`・`!=`・`<`・`<=`・`>`・`>=` | Bool。比較の連鎖は短絡 |
| 全順序 | `a <=> b` | `Ordering::Less`・`Equal`・`Greater` |
| 論理 | `!`・`&&`・`\|\|` | 真偽変換を使い、Boolを返す。`&&`・`\|\|`は短絡 |
| 最小・最大 | `<?`・`>?` | 既定では選んだ値のコピー |
| 中身の更新 | `=`・`+=`・`-=`・`*=`・`/=`・`%=` | 対象を更新し、更新先を共有する値を返す |
| 条件付き更新 | `<?=`・`>?=` | 既定では改善時だけ更新。更新先を共有 |
| 結び直し | `:=` | 名前・格納先の共有先を変更 |
| 不在の処理 | `??`・`?!` | 存在する値の共有取得、既定値の短絡評価、不在時の失敗 |
| 範囲 | `start..end` | 半開区間のRange |
| 取得・呼び出し | `a[i]`・`a.field`・`f(...)` | 型に対応する要素・フィールド・関数の結果 |

ビット演算と累乗には複合代入がありません。

## 整数・文字・連結

Intは符号付き64ビット、Int128は符号付き128ビットです。除算は負の無限大方向へ丸め、剰余はゼロまたは除数と同符号になります。オーバーフローとゼロ除算は位置付きの実行時エラーです。最小値を`-1`で割ると結果が範囲を超え、同じ2値の剰余は0です。

```rusk
wt 7 + 3, 7 - 3, 7 * 3;
wt -7 / 3, -7 % 3, 7 / -3, 7 % -3;
wt (6 & 3), (6 | 3), (6 ^ 3);
wt 'A' + 2, 'C' - 'A';
```

出力は`10 4 21`、`-3 2 -3 -2`、`2 7 5`、`C 2`です。

CharにIntを加減するとChar、Char同士の差はIntです。結果の文字コードはASCII範囲を検査します。Strの`+`は独立した文字列、Vecの`+`は外側が新しく要素を共有する配列を返します。Vecの`+=`は元の外側を保って要素を共有追加します。[配列と文字列](../library/sequences.md)を参照してください。

## 累乗とシフト { #powers-shifts }

`**`は右結合で、単項の符号より強く結び付きます。`2 ** 3 ** 2`は512、`-2 ** 2`は-4です。負の底を累乗するには`(-2) ** 2`と書きます。Int・Int128の指数は非負のIntで、`0 ** 0`は1です。負の指数と整数結果のオーバーフローは実行時エラーになります。Floatの累乗にはFloatの指数を指定でき、例えば`2.0 ** -3.0`は0.125です。

`~`はIntの64ビットまたはInt128の128ビットをすべて反転します。`<<`と`>>`の移動量はIntです。左シフトは高位からはみ出したビットを捨て、下位を0で埋めます。右シフトは符号ビットで埋めます。負の量はシフトの向きを反転し、絶対値が型のビット幅以上なら左シフトは0、右シフトは符号に応じて0か-1です。

例えば`1 << 63`はIntの最小値、`-8 >> 2`は-2、`3 >> -2`は12です。シフトは加減算より弱く、比較より強く結び付きます。

## Floatの四則演算 { #float-arithmetic }

`+`・`-`・`*`・`/`はIEEE 754 binary64の演算です。有限値の範囲を超えた演算は無限大になり、ゼロ除算もIEEE 754の結果を返します。例えば`1.0 / 0.0`は正の無限大、`0.0 / 0.0`はNaNです。`%`は整数に使います。

正のゼロと負のゼロは等しいと判定します。NaNが関わる`==`と大小比較は偽、`!=`は真です。NaNを含み得る値を並べ替える場合は、NaNの位置も決めた比較関数を使います。

## 比較と連鎖

比較は値を調べます。配列・タプル・文字列の順序は辞書順です。Boolでは偽、真の順です。

`a < b <= c`は隣接項を順に比較し、偽なら残りを評価しません。中間の式も一度だけ評価して保持します。

```rusk
fn next(counter: Int) -> Int {
    counter += 1;
    return copy(counter);
}
let count := 0;
wt 0 < next(count) < 3, count;
wt 3 < next(count) < next(count), count;
```

出力は`Yes 1`、`No 2`です。二行目の最後の`next(count)`は呼ばれません。保持した値は共有なので、後続の式が中身を更新すると、その更新が次の比較から見えます。[分岐式と比較の連鎖](expressions.md)に詳細があります。

### 全順序 { #total-order }

`a <=> b`は`__cmp__(a, b)`を呼び、`Ordering::Less`、`Ordering::Equal`、`Ordering::Greater`のいずれかを返します。Int・Int128・Char・Str・Bool・Orderingには標準の比較があり、配列とタプルでは各要素の`<=>`で辞書順に比較します。`is_less`、`is_equal`、`is_greater`で結果を調べられます。

利用者の`__cmp__`は、どの二値にも一貫した順序を与え、推移性と左右を交換したときの整合性を満たす必要があります。通常の`==`を定義する場合は、`Ordering::Equal`になる組と一致させます。処理系は比較の戻り型を検査し、順序の法則は実装者が保証します。

`<`・`<=`・`>`・`>=`では適用できる専用フックを優先します。専用フックがなく`__cmp__`を使える場合は、同じ向きの引数で一度だけ呼び、結果からBoolを得ます。曖昧さや誤った戻り型はその場で診断します。`==`・`!=`はそれぞれのフックを使います。

Floatの通常の比較はIEEE 754に従います。`partial_cmp(a, b)`はNaNが関わる場合に`None`、比較できる場合に`Some(Ordering)`を返します。`total_cmp(a, b)`と`total_less(a, b)`はFloatのビット表現を全順序で比較します。負符号のNaN、負の無限大、負の有限値、負のゼロ、正のゼロ、正の有限値、正の無限大、正符号のNaNの順です。NaN同士もビット表現で区別します。 [比較方法を選ぶソート](../library/algorithms.md#sorting)

## 論理と短絡評価

`!x`は型別の否定、`a && b`はaが真の場合だけb、`a || b`はaが偽の場合だけbを評価します。結果は独立したBoolです。Intやコンテナを条件として使う場合の真偽変換は[型の対応表](types.md)を参照してください。

```rusk
fn tick(counter: Int) -> Bool { counter += 1; return true; }
let count := 0;
wt false && tick(count), true || tick(count), count;
wt true && tick(count), false || tick(count), count;
```

出力は`No Yes 0`、`Yes Yes 2`です。ビット演算の`&`・`|`は両辺を評価し、論理演算の短絡とは別です。

## 更新と結び直し

`=`と複合代入は既存オブジェクトの中身を更新します。`:=`は名前や格納先を別のオブジェクトへ結び直します。どちらも結果を共有して返します。

```rusk
let value := 1;
let alias := value;
value += 2;
let other := 5;
value := other;
let later: Int;
later := 7;
wt value, alias, other, later;
```

出力は`5 3 5 7`です。`alias`は結び直し前のオブジェクトを保持します。

`let x = value;`はコピーによる宣言時の初期化です。初期値なしで宣言した後の`x = value;`は更新なので、未初期化変数には使えません。最初に`:=`で初期化します。添字・フィールド・分解代入の対象と評価順は[共有と代入の規則](semantics.md)を参照してください。

複合代入は対応する更新フックを優先し、なければ通常の演算と代入を組み合わせます。配列の連結のように、専用の更新フックが要素の共有を保つ場合があります。

## 不在・範囲・取得

| 操作 | 規則と詳細 |
|---|---|
| `a ?? fallback` | aを一度だけ評価し、値が存在すれば共有取得、不在時だけfallbackを評価。[Optionと短絡](expressions.md) |
| `a?!` | 通常の`value(a)`呼び出し。標準Optionは不在なら実行時エラー。[Option](expressions.md) |
| `start..end` | 端点を左から一度ずつ評価して値を保持する。開始以上・終了未満。[範囲と反復型](types.md) |
| `a[i]` | 型別の添字取得。配列・文字列は負の添字に対応、タプルは静的な非負整数。[配列](../library/sequences.md)・[タプル](records.md) |
| `a.field` | 構造体フィールドの共有取得。[構造体](records.md) |
| `f(...)`・`a.f(...)` | 引数を共有して呼ぶ。通常のメソッド形式は`f(a, ...)`。[関数](functions.md) |

## 優先順位と評価順 { #precedence }

上ほど強く結び付きます。if式・match式を算術などの一部に置くときは、括弧で囲みます。

| 順位 | 構文 | 結合・制限 |
|---|---|---|
| 1 | `a[i]`、`a.field`、`a.method(...)`、`a?!` | 左から連結 |
| 2 | `**` | 右結合。右辺に単項演算を置ける |
| 3 | 単項 `+`、`-`、`!`、`~` | 右結合 |
| 4 | `*`、`/`、`%` | 左結合 |
| 5 | `+`、`-` | 左結合 |
| 6 | `<<`、`>>` | 左結合 |
| 7 | `<?`、`>?` | 左結合・最小値／最大値 |
| 8 | `<=>` | 括弧なしで連鎖できない |
| 9 | `==`、`!=`、`<`、`<=`、`>`、`>=` | 短絡する比較の連鎖 |
| 10 | `&` | 左結合 |
| 11 | `^` | 左結合 |
| 12 | `\|` | 左結合 |
| 13 | `&&` | 左結合・短絡評価 |
| 14 | `\|\|` | 左結合・短絡評価 |
| 15 | `..` | 1回だけ |
| 16 | `??` | 右結合・不在時だけ右辺を評価 |
| 17 | `:=`、`=`、`+=`、`-=`、`*=`、`/=`、`%=`、`<?=`、`>?=` | 右結合 |


比較はビット演算より強いため、ビットの有無を調べるときは`(mask & bit) != 0`と括弧を付けます。

通常のオペランド・呼び出し引数は左から右に一度ずつ評価し、その時点のオブジェクトを保持します。短絡する右辺は必要な場合だけ評価します。`wt`は各項目を評価して順に出力します。[評価順と副作用](semantics.md)と[厳密な文法](grammar.md)を参照してください。

## 最小・最大 { #minmax }

| 式 | 既定の動作 | 結果 |
|---|---|---|
| `a <? b` | 小さい側をコピーする | 独立した値 |
| `a >? b` | 大きい側をコピーする | 独立した値 |
| `a <?= b` | `b < a`の場合だけ`a = b`で更新する | 更新先を共有する値 |
| `a >?= b` | `a < b`の場合だけ`a = b`で更新する | 更新先を共有する値 |

```rusk
let best := 100;
let alias := best;
best <?= 7 + 3;
best >?= 4;
wt best, alias, 8 <? 4 >? 6;
```

出力は`10 10 6`です。更新は`:=`による結び直しではないため、`alias`にも変更が見えます。複合代入の結果も更新先を共有するので、`let held := (best <?= candidate);`の`held`は`best`と同じ値を共有します。

### 比較とコピー

既定の実装は同じ型の二つの値を受け取ります。通常の演算子には`<`と`copy`、更新には`<`と`=`が必要です。`<`の結果にはBoolを要求します。Int、Char、Str、比較可能なタプル・配列や、比較フックを持つ構造体などに使えます。Boolなど、標準で`<`を提供しない型には自動的な順序を追加しません。

通常の`<?`・`>?`は選んだ側を`copy`でコピーします。既存の変数やフィールドを共有して返す演算子ではありません。どちらも同値なら左側を選びます。更新の比較が偽なら代入をせず、既存のpayloadや要素への共有を維持します。比較が真なら、既存の`=`と同じく右辺のスナップショットをコピーして更新します。

```rusk
struct Entry { rank:Int; data:Vec<Int>; }
fn __lt__(a:Entry, b:Entry) -> Bool { return a.rank < b.rank; }
let entry := Entry { rank:1, data:[10] };
let held := entry.data;
entry <?= Entry { rank:2, data:[20] };
held[0] = 11;
wt entry.data;
let detached := entry <? Entry { rank:1, data:[30] };
detached.data[0] = 99;
wt entry.data, detached.data;
```

出力は`11`、`11 99`です。最初の更新は不要なので共有を保ち、同順位の通常の最小値演算は左側の独立したコピーを作ります。

### 優先順位・結合・評価順

`<?`と`>?`は同じ優先順位で左結合です。加減算より弱く、比較より強く結合します。`<?=`と`>?=`は他の代入演算子と同じ優先順位で右結合です。

```rusk
wt 10 <? 3 + 4;       // 10 <? (3 + 4) → 7
wt 8 <? 4 >? 6;       // (8 <? 4) >? 6 → 6
wt 0 <= 8 <? 4 < 5;   // 0 <= (8 <? 4) < 5 → Yes
```

オペランドは左から右に一度ずつ評価します。短絡評価ではなく、更新が不要になる場合も右辺は評価します。更新先が`rows[f()][g()]`なら、行と添字を含めて一度だけ評価・保持してから右辺を評価します。右辺が行や変数を結び直しても、保持済みの更新先を使います。

先に保持した値は共有オブジェクトです。右辺がその中身を更新した場合、比較には更新後の中身が見えます。比較フック自身の副作用も通常どおり起こります。「変更が不要なら代入しない」という規則は、比較や右辺の副作用を抑止する意味ではありません。

既存の代入先と同じく、変数・フィールド・配列や辞書の要素・文字列の文字などに使えます。未初期化変数やタプルの分解代入には使えません。

### 演算フック

| 構文 | フック | 既定の実装 |
|---|---|---|
| `a <? b` | `__min__` | `b < a`なら`copy(b)`、それ以外は`copy(a)` |
| `a >? b` | `__max__` | `a < b`なら`copy(b)`、それ以外は`copy(a)` |
| `a <?= b` | `__imin__` | `b < a`の場合だけ`a = b` |
| `a >?= b` | `__imax__` | `a < b`の場合だけ`a = b` |

標準ライブラリーに型引数付きの既定フックを定義しています。具体的な型に対する通常の関数で、それぞれをオーバーロードできます。通常の演算と更新は別のフックなので、`__min__`を変更しただけでは既定の`__imin__`は変わりません。独自の更新規則が必要なら更新フックも定義します。独自フックを定義した場合のコピー・比較・更新の動作はそのフックに従います。

Int向けの`min(Int, Int)`・`max(Int, Int)`関数も提供します。演算子はそれらの名前への単純な置換ではなく、上のフックへ解決します。C++の特殊な演算子に依存せず、通常のHIRの関数呼び出しと分岐を経由します。

組み込みフックを経由する実行時エラーも、実際に演算子を書いたファイル・行・列を表示します。同じ型のフックを複数箇所から呼んでも、最初の使用箇所へ固定しません。利用者定義のフック内の操作には、通常どおりその操作の位置を使います。
