# 構造体・タプル・型引数・include

構造体、タプル、型引数を持つ関数・構造体、`include` によるファイル分割が使えます。共有・コピーの規則は [言語リファレンス](index.md) と共通です。

各コード例は独立したプログラムです。includeを使う例はリポジトリ直下に保存する想定で、別の場所ではパスを調整してください。

## 構造体

フィールドの型を明示して宣言し、名前を指定して構築します。

```rusk
struct Point {
    x: Int;
    y: Int;
}

let x := 1;
let p := Point { x: x, y: 2 };
let held := p.x;
p.x = 3;
wt x, held;  // 3 3
p.x := 9;
wt x, p.x;  // 3 9
```

構築式に渡した値はフィールドで共有します。全フィールドの指定が必要で、余分な指定、重複、省略、型の不一致はコンパイルエラーです。式は構築式に書いた順に左から評価します。フィールド名の指定順は宣言順と異なっても構いません。末尾のカンマも使えます。

`p.x` はフィールドを共有して取得します。`p.x = value` はフィールドの実体の更新、`p.x := value` はフィールドの共有先の変更です。`let local = p.x` ならコピーを取得できます。

`let independent = p` と `copy(p)` は各フィールドを再帰的にコピーします。各フィールドのRuskの型に対応する `copy` を呼びます。外部型をフィールドにする場合も、その型の `copy` が必要です。`p = q` は `p` の外側の同一性を保ち、各フィールドを新しいコピーへ置き換えます。以前取得したフィールドは古い実体を指し続けます。

ユーザー定義の構造体も `Vec<Point>` に格納でき、添字、追加、反転、走査、コピーが使えます。構造体には比較と出力を自動生成しません。必要な比較・出力フックを定義すれば、その型を含む配列でも対応する比較・探索・ソート・出力を使えます。[キー関数・比較関数を渡すソート](../library/algorithms.md) が使えます。個々の構造体については通常の関数や演算フックを定義できます。

型名と同じ名前の関数を定義すれば、通常の呼び出しで構築できます。

```rusk
struct Point { x: Int; y: Int; }
fn Point(x: Int, y: Int) -> Point {
    return Point { x: x, y: y };
}
let p := Point(1, 2);
wt p.x, p.y; // 1 2
```

引数なしの構築関数も必要なら明示的に定義します。構造体を宣言しただけでは `Point()` は使えません。

## タプルと分解

型の異なる値を `(x, y)` で組にできます。タプルへの格納は共有です。型の表記も `(Int, Str)` のように書きます。現在は2要素以上が対象です。

```rusk
fn pair() -> (Int, Str) { return (1, "hello"); }
let p := pair();
let (number, word) := p;
number = 2;
wt p[0], p[1];  // 2 hello

let (independent, text) = p;
independent = 9;
wt p[0], independent;  // 2 9
```

タプルの添字は非負の整数リテラルに限ります。`p[0]` は共有、`p[0] = value` は中身の更新、`p[0] := value` は格納先の結び直しです。添字の範囲外はコンパイルエラーです。

分解する構造・要素数・型が一致する必要があります。入れ子の分解や不要な要素の読み捨ても使えます。

```rusk
let (x, (y, _)) := (1, (2, 3));
for (number, word) in [(1, "one"), (2, "two")] {
    wt number, word;
}
```

`for` の変数と本体直下の宣言は同じスコープで、同名の再宣言はエラーです。さらに内側の `{ ... }` では名前を隠せます。

分解宣言の `:=` は要素を共有し、`=` はタプル全体をコピーしてから分解します。`_` は分解宣言の読み捨てで、変数を宣言しません。

既存の変数への分解代入もできます。

```rusk
let a := 1;
let b := 2;
(a, b) = (b, a);    // 更新前の値をコピーしてから中身を交換
wt a, b;           // 2 1
(a, b) := (b, a);   // 共有先を交換
wt a, b;           // 1 2
```

右辺を一度評価して保持し、`=` では更新前の値を再帰的にコピーします。その後、左辺の各対象を左から順に処理します。分解代入の結果は更新した対象を共有するタプルです。複合代入による分解は未対応です。

タプルの比較・出力は、各フィールド型に対応する通常の操作を使います。基本型や入れ子の配列・タプルだけでなく、必要な操作を定義した構造体なども使えます。順序は値による辞書順で、Boolフィールドはfalseがtrueより先です。比較できるタプルの配列もソートできます。

## 型引数を持つ関数と構造体

```rusk
struct Pair<A, B> {
    first: A;
    second: B;
}

fn Pair<A, B>(a: A, b: B) -> Pair<A, B> {
    return Pair::<A, B> { first: a, second: b };
}

fn first<A, B>(pair: Pair<A, B>) -> A {
    return pair.first;
}

let p := Pair(1, "hello");
wt first(p);  // 1
```

関数では引数の型と期待する返却型から型引数を推論できます。`Vec<T>`、タプル、型引数を持つユーザー型の内側からも推論します。同じ型引数に異なる型が要求される場合はエラーとなります。期待型は未確定の型引数を補いますが、すでに型引数が決まった候補同士を戻り型で選び分けることはしません。

型引数を明示する呼び出しは `first::<Int, Str>(p)` の形です。構築式でも `Pair::<Int, Str> { first: 1, second: "hello" }` と指定します。型注釈では `Pair<Int, Str>` を使います。構築式のフィールドから型引数を推論する処理はまだないため、型名と同名の関数を用意すると使いやすくなります。

型が確定した関数本体を具体化して検査し、C++の関数を生成します。例えば `T` に加算が必要なら、具体化した型で対応する演算が使える必要があります。失敗時は定義内の位置と、その具体化を要求した呼び出しの位置・型引数を表示します。再帰と、他の型引数付き関数を呼ぶ処理も使えます。

名前付き関数と型はトップレベルに限定します。具体化中の名前探索も同じグローバルの型・関数から行います。引数型が完全一致する具体型の関数を優先し、それがなければジェネリックな候補を選びます。ジェネリックな候補が複数適用できれば曖昧としてエラーにします。型引数を明示した呼び出しはジェネリックな定義から選びます。

部分的な型引数指定、特殊化候補同士の詳細な優先順位、トレイト、mixin、ローカル型・関数は未対応です。未使用のジェネリック関数の本体は具体化されません。無限に型を増やす再帰を防ぐため、型・関数の具体化には上限を設けています。

## ファイル分割

```rusk
include "examples/beta02/library/union_find.rusk";

in n: Int;
let uf := UnionFind(n);
uf.unite(0, 1);
wt uf.same(0, 1);
```

パスは `include` を書いたファイルのディレクトリを基準に解決します。`include` はトップレベルに置きます。ファイルごとの名前空間は作らず、その位置へ内容を展開します。読み込むファイルのトップレベルの実行文もその位置で実行します。

正規化した同じパスは一度だけ読み込みます。シンボリックリンクによる同じファイルの参照も重複しません。循環した読み込みは経路とソース位置付きのエラーにします。読み込んだソース内のコンパイル時・実行時エラーも、元ファイルの位置を表示します。

`rusk compile main.rusk -o main.cpp` で、依存ファイルを含めた単一のC++20ソースを生成できます。`rusk dependencies main.rusk`は、読み込むRuskソースと、extern symbolの`code_file`・`code_files`で参照するC++資源の絶対パスを一行ずつ出力します。検証ツールもこれを使い、ライブラリ変更後の再検証を判断します。

## 自作ライブラリの実例

`examples/beta02/library/` に次を置いています。

| ファイル | 内容 |
|---|---|
| `union_find.rusk` | 構造体に状態をまとめたUnion-Find。経路圧縮・サイズによる併合 |
| `fenwick.rusk` | `Fenwick<T>`。初期配列からO(N)で構築、更新・区間和はO(log N) |
| `sum_segment_tree.rusk` | `SumSegTree<T>`。O(N)で構築、更新・区間の集計はO(log N) |

Fenwick Treeは可換な加算と減算、明示的なゼロ元を持つ型が対象です。セグメント木は結合的な加算と明示的な単位元を使い、左から右の順序を保ちます。演算が独立した結果を返す規約に従います。計算量には各要素型の演算・コピーのコストが加わります。

整数だけでなく、加減算を定義したユーザー構造体でも使えます。セグメント木は文字列連結にも使えます。コピー宣言ではライブラリの状態も独立させられます。

## 現段階の制限

構造体は一つ以上のフィールドを持つ非再帰の型が対象です。再帰的な型、空の構造体、構造体の比較・出力の自動生成は未対応です。標準のソートは要素型の比較操作を必要とします。キー関数・比較関数でソートできます。クロージャは[関数と捕捉](closures.md)を参照してください。変数・引数の`readonly`注釈と共有経路への伝播は[読み取り専用のアクセス](access.md)を参照してください。`Vec<readonly T>`のような入れ子の型注釈は提供していません。

文法の厳密な形と末尾カンマの制約は [文法一覧](grammar.md)、型推論・分解代入・演算フックは [型・共有・評価の規則](semantics.md)、各ライブラリの全APIと実行例は [Ruskで記述したデータ構造](../library/data-structures.md) を参照してください。
