# 型・共有・評価の規則

文法に合ったプログラムに対して、処理系は型、名前のスコープ、初期化、関数の候補を検査します。このページでは、構文を選ぶ際に必要な規則をまとめます。

## 型の種類と一致

標準で使える型・型構文、構築例、コピー・比較・入出力などの対応状況は[型の一覧](types.md)にまとめています。ここでは型の一致と推論、共有・評価の規則を説明します。

利用者は`struct`・`enum`で新しい型を定義できます。型引数を持つ定義にも対応します。具体例に出てくる構造体名は、その例で宣言して使う名前であり、標準型ではありません。構築・分解・具体化は[構造体・タプル・型引数](records.md)を参照してください。

関数値・クロージャは、静的に呼び出し先が決まる固有の型を持ちます。その型名をソースに書く構文はなく、変数では推論し、関数では型引数を通して受け取ります。[関数の受け渡し](closures.md)を参照してください。

代入・引数・戻り値では型が一致する必要があります。整数から真偽値などへの暗黙変換は行いません。`Bool(1)` のような明示的な変換を使います。例外として、`if`・`while`・matchのガード・`&&`・`||` では型別の真偽変換を使います。`!` には型別の論理否定を使います。`assert` の引数は `Bool` なので、整数に対しては `assert(n != 0)` または `assert(Bool(n))` と書きます。

同じフィールド構成でも、名前が異なる構造体は別の型です。タプルは要素型の並びが同じなら同じ型です。`(Int, Str)` と `(Str, Int)` は別の型で、`Vec<Int>` と `Vec<Bool>` も別の型です。

`Unit` は配列・構造体の要素としても格納できます。不透明なextern型も配列に格納できますが、コピーにはその型の `copy`、比較・出力等には対応する操作が必要です。型を格納できることと、すべての操作を使えることは別です。整数範囲 `a..b` は主に `for` の走査に使う値で、配列ではありません。

## 型を推論する場所

`let x := expression;` と `let x = expression;` は式の型から宣言型を決めます。関数の引数型と構造体のフィールド型は明示します。名前付き関数は戻り型を省略するとUnitになり、無名関数は本体から戻り型を推論します。型引数付き関数は実引数と期待する返却型から型引数を推論します。例えば`fn empty<T>()->Vec<T>{return [];}`を定義すると、`let a:Vec<Int>:=empty();`で`T=Int`と決まります。実引数・明示型引数・期待型の間に矛盾があればエラーです。

空配列 `[]` は要素型を持たないので、周囲から型を受け取る必要があります。

```rusk
fn empty() -> Vec<Int> { return []; }
fn count(values: Vec<Int>) -> Int { return values.len(); }
let a: Vec<Int> := [];
a := [];
a = [];
let pair: (Vec<Int>, Int) := ([], 1);
wt a.len(), empty().len(), count([]), pair[1]; // 0 0 0 1
```

宣言の型注釈、既存の代入先、関数の戻り型、関数引数の候補から型を与えられます。ただし、後続の文や後続の引数を調べて推論し直すことはありません。候補関数が要求する型が複数あれば、空配列の型を決められないことがあります。迷う場合は、まず型注釈付きの変数へ代入するか、ジェネリック関数であれば明示的な型引数も使えます。この例の`count`自体はジェネリック関数ではないため、`count([])`と呼びます。

## 共有・コピー・更新・結び直し

変数、配列の格納先、構造体のフィールド、タプルの要素は、オブジェクトへの共有を持ちます。基本型の整数も同じ規則です。

| 操作 | 結果 | 元の値を共有する他の名前への影響 |
|---|---|---|
| `let b := a;` | 同じオブジェクトを指す名前を作る | 以後の中身の更新が互いに見える |
| `let b = a;` | 独立したコピーを作る | 互いの更新が見えない |
| `a = value;` | `a` のオブジェクトの中身を更新 | 同じオブジェクトを指す名前にも見える |
| `a := value;` | `a` の共有先を変更 | 他の名前は以前の共有先を保つ |
| `a += value;` | `a` のオブジェクトを加算更新 | `=` と同じく更新が見える |
| `copy(a)` | 独立したコピーを返す | 元の共有先は変えない |

```rusk
let a := 10;
let shared := a;
let detached = a;
a = 20;
wt a, shared, detached; // 20 20 10
a := 30;
wt a, shared, detached; // 30 20 10
```

`let x = y;` は宣言と同時にコピーで初期化する構文です。一方、`let x: Int;` のように初期値なしで宣言した後は、`x := y;` で初めて値を結びます。宣言後の `x = y;` はすでに結ばれたオブジェクトの更新なので、未初期化変数には使えません。複合代入も同様です。

### 格納時の共有と再帰的コピー

配列リテラル`[a, b]`、タプル`(a, b)`、構造体の構築式、関数引数・戻り値は、渡した値を共有します。`[a; n]`、`copy(...)`、`let x = ...` はコピーします。配列と構造体の標準コピーは、要素・フィールドごとのRuskの型に対応する `copy` を使います。利用者定義の `copy` の結果もそのまま使うため、独立性や副作用はその定義に従います。

コピーは各格納先を再帰的に独立させます。元の配列の2要素が同じオブジェクトを共有していても、コピー先の2要素は独立します。

```rusk
let x := 1;
let a := [x, x];
let b = a;
b[0] = 9;
wt a, b; // 1 1 9 1
let repeated := [x; 2];
repeated[0] = 8;
wt x, repeated; // 1 8 1
```

配列・構造体・タプルの `a = b` は、外側のオブジェクトを保ち、内側の格納先をコピーで置き換えます。以前取得した要素やフィールドへの共有は、古いオブジェクトを保持します。`a = a` も内側をコピーし直します。

```rusk
let a := [1, 2];
let outer := a;
let old_element := a[0];
a = [3, 4];
wt a, outer, old_element; // 3 4 3 4 1
```

### 代入できる対象

| 対象 | `=`・複合代入 | `:=` |
|---|---|---|
| 初期化済み変数 | オブジェクトの更新 | 変数の結び直し |
| 未初期化変数 | 不可 | 最初の初期化 |
| 配列 `a[i]` | 要素の更新 | 配列の格納先の結び直し |
| 構造体 `p.field` | フィールドの更新 | フィールドの格納先の結び直し |
| タプル `p[0]` | 要素の更新 | タプルの格納先の結び直し |
| 文字列 `s[i]` | 文字の更新 | 不可 |
| 分解 `(a, b)` | `=` が可、複合代入は不可 | 各対象の結び直し |
| 関数が返した共有値 | 対応する更新演算があれば可 | 変数・格納先ではないので不可 |

分解代入の左辺には変数だけでなく添字・フィールド、入れ子のタプルを使えます。右辺を先に一度評価して保持し、`=` なら全体をコピーしてから各対象を左から処理します。`(a, b) = (b, a)` は更新前の値を使って交換できます。`:=` では値のコピーをせず共有先を交換します。

## 評価順序と副作用

通常の二項演算と呼び出しは左から右に一度ずつ評価します。メソッド形式は受け手が最初の引数です。配列・タプルの要素と構造体構築の値も記述順に評価します。

評価済みの引数は、その時点のオブジェクトへの共有を保持します。後の引数で中身を更新すると、先の引数にも更新が見えます。

```rusk
fn show(a: Int, b: Int) { wt a, b; }
let x := 1;
show(x, x = 2);  // 2 2
show(x, x := 3); // 2 3
wt x;            // 3
```

通常の `a[i] = rhs` は配列・添字・対象要素を取得してから右辺を評価します。`a[i] := rhs` は配列・添字を保持してから右辺を評価し、格納先を変更します。式は重複評価しません。代入の結果は更新した対象を共有します。

`&&` と `||` は短絡します。右辺を評価しない経路があるため、右辺だけで変数を初期化しても、その式の後で必ず初期化済みとは扱いません。`wt` は各項目を評価して順次出力するので、後続の式による更新で出力済みの内容は変わりません。

## 名前・スコープ・初期化

ブロックごとに変数スコープがあります。同じスコープで同じ名前を再宣言できません。内側のブロックから外側の変数を参照でき、内側の宣言で同名の外側変数を隠せます。

`for` の束縛とループ本体直下の宣言は同じスコープです。関数の仮引数と本体直下の宣言も同じスコープです。`for x in values { let x := 0; }` は重複宣言になります。必要なら本体内にもう一つブロックを置きます。ループ変数はループ外へは出ません。

トップレベルの名前付き関数はトップレベルの変数を捕捉できません。必要な状態は引数で渡します。無名関数は作成時点の外側の変数を共有して捕捉できます。[関数と捕捉](closures.md) を参照してください。`include` はファイル固有のスコープを作らないため、読み込んだファイル間でも名前の重複に注意します。

初期化検査は実行経路を保守的に扱います。

- `if` の両分岐で初期化すれば、その後で読めます。
- 一方が `return` するなら、後続に到達する側の状態を使います。
- ループが必ず1回実行することや、定数条件が常に真であることは証明しません。
- ループ本体やループの `else` だけで初期化しても、後続では未初期化として扱います。

## 関数選択とジェネリクス

通常の呼び出しは名前・引数の個数・引数型を照合します。引数の暗黙変換や戻り型だけによる一般のオーバーロード選択はありません。

1. 型引数を省略した呼び出しでは、具体型が完全一致する関数を優先します。
2. 完全一致する具体関数がなければ、ジェネリックな定義の引数型と照合して型引数を推論します。
3. ジェネリックな候補が複数適用できれば曖昧としてエラーにします。「より具体的」な候補を選ぶ規則はありません。
4. `f::<Int>(...)` と明示した場合は、ジェネリックな定義だけから選びます。型引数は全て指定します。

```rusk
fn twice<T>(x: T) -> T { return x + x; }
fn twice(x: Int) -> Int { return x + 100; }
wt twice(2), twice::<Int>(2), twice("ab"); // 102 4 abab
```

推論は`Vec<T>`、タプル、利用者が定義した型引数付きの構造体・enumの内側にも及びます。同じ型仮引数`T`に異なる型が要求される場合はエラーとなります。戻り型だけに現れる`T`も期待型から推論できます。期待型がなければ明示指定します。すでに型引数が決まった複数の候補を戻り型で選び分けることはしません。

具体化した関数はグローバルの型・関数から名前を解決し、引数・ローカル変数以外の変数を捕捉しません。型引数付き関数の本体は使用された組み合わせで検査します。演算に必要な関数がなければ、その具体化でエラーになります。未使用のジェネリック本体に対する検査と、全ての型について使えることの証明は行いません。

## 走査と共有の寿命

配列の `for x in a` の `x` は各要素を共有します。`x = ...` で元の要素を更新できますが、`x := ...` はループ変数だけを結び直します。タプルの分解走査も同じです。

配列を走査中に追加・並べ替え・反転・配列全体のコピー代入などを行うと、次の反復検査でイテレータ無効化のエラーになります。要素自体の更新や `a[i] := ...` は可能です。反復とは無関係に、取得済みの要素への共有は配列の再確保後も有効です。

文字列の要素 `s[i]` は元の文字列を保持します。その共有が存在する間、文字列の長さを変える操作はエラーになります。同じ長さへの `=` は可能で、文字の共有にも更新が見えます。添字式などで作られた一時的な共有は文末に解放し、条件式の一時値は分岐・ループ本体の前に解放します。名前付き変数に保存した文字の共有は、その変数のスコープなどが終わるまで残ります。

辞書の走査はキーをコピーし、値を共有します。集合の走査は要素がキーなのでコピーします。辞書・集合の新規キー追加・削除・全体代入による走査の無効化と、取得済みの値の寿命は[辞書・集合のAPI](../library/collections.md)を参照してください。

## 整数演算と条件

`Int` の `/` は負の無限大方向への除算です。`a = (a / b) * b + a % b` を満たすように剰余を定め、剰余の符号は0でなければ除数に従います。

| 式 | 結果 |
|---|---:|
| `7 / 3` | `2` |
| `-7 / 3` | `-3` |
| `7 / -3` | `-3` |
| `-7 % 3` | `2` |
| `7 % -3` | `-2` |

ゼロ除算、範囲を超える計算、最小値の符号反転・絶対値などは位置付きの実行時エラーです。整数のビット演算は `&`・`|`・`^` に対応します。真偽値の論理演算には `&&`・`||` を使います。

条件での真偽変換は、`Bool` はその値、`Int` と `Char` はゼロ以外、`Str`・`Vec<T>`・`Dict<K,V>`・`Set<T>` は空でなければ真です。`Option<T>` は存在すれば真、不在なら偽です。一般のenum・構造体・タプルに真偽変換は自動生成しません。条件にしたい性質を明示的に比較するか、必要なフックを定義します。

## 演算フックの対応表

表に示す演算は対応する名前付き関数の呼び出しへ展開します。if式・`??`・比較の連鎖は処理系による分岐構文です。`??`の有無と値取得は`__coalesce_test__`・`__coalesce_value__`、`?!`は`value`の通常の候補解決に対応します。標準ではOptionがこれらを定義します。[評価の規則](expressions.md)を参照してください。必要な引数型・戻り型を持つ通常の `fn` を定義すれば、ユーザー型にも演算を追加できます。構文そのものを新設する機能はありません。

この表の`T`・`S`・`I`・`N`は説明用の型変数です。`S`は走査元やコンテナ、`I`は反復状態、`N`は添字、`T`は値・要素の型を表し、それ自体が標準型の名前ではありません。

| 構文・用途 | 関数名 | 典型的な型 |
|---|---|---|
| `a + b`、`a - b` | `__add__`、`__sub__` | `(T, T) -> T` |
| `a * b`、`a / b`、`a % b` | `__mul__`、`__div__`、`__mod__` | `(T, T) -> T` |
| 単項 `+a`、`-a` | `__pos__`、`__neg__` | `(T) -> T` |
| `a & b`、`a \| b`、`a ^ b` | `__bitand__`、`__bitor__`、`__bitxor__` | `(T, T) -> T`。標準ではInt・Int128 |
| `~a` | `__bitnot__` | `(T) -> T`。標準ではInt・Int128 |
| `a << n`、`a >> n` | `__shl__`、`__shr__` | `(T, Int) -> T`。標準ではInt・Int128 |
| `a ** b` | `__pow__` | 整数は`(T, Int) -> T`。Floatは`(Float, Float) -> Float` |
| `a == b`、`a != b` | `__eq__`、`__ne__` | `(T, T) -> Bool` |
| `a < b`、`a <= b` | `__lt__`、`__le__` | `(T, T) -> Bool` |
| `a > b`、`a >= b` | `__gt__`、`__ge__` | `(T, T) -> Bool` |
| `a <=> b` | `__cmp__` | `(T, T) -> Ordering` |
| 条件・短絡論理の真偽変換 | `__bool__` | `(T) -> Bool` |
| `!a` | `__not__` | `(T) -> Bool` |
| `a = b` | `__assign__` | `(T, T) -> Unit` |
| `a += b` など | `__iadd__`、`__isub__`、`__imul__`、`__idiv__`、`__imod__` | `(T, T) -> Unit` |
| `a <? b`、`a >? b` | `__min__`、`__max__` | 既定は`(T, T) -> T`、選択した値をコピー |
| `a <?= b`、`a >?= b` | `__imin__`、`__imax__` | 既定は`(T, T) -> Unit`、改善時のみ更新 |
| `copy(a)`・コピー宣言 | `copy` | `(T) -> T` |
| 添字の取得 | `__getitem__` | `(S, N) -> T` |
| 添字の結び直し | `__setitem__` | `(S, N, T) -> T` |
| `in` | `__read__` | 結果型と追加引数に依存 |
| `wt` の各値 | `__write__` | `(T) -> Unit` |
| `for` の開始 | `__iter__` | `(S) -> I` |
| 次の要素の有無 | `__iter_has_next__` | `(I) -> Bool` |
| 次の要素の取得 | `__iter_next__` | `(I) -> T` |

この表の型は典型例であり、加算の左右で異なる型を取ることもできます。`__eq__` を定義しても `__ne__` は自動生成しません。同様に、`__bool__` だけでは `!` の `__not__` は自動生成しません。

複合代入は対応する更新フックを優先し、なければ通常の演算と `__assign__` を組み合わせます。`:=` は処理系による結び直しで、`__assign__` を呼びません。構造体・タプルのフィールド取得や分解も処理系が直接扱います。配列の比較・探索・ソートは、要素型に対応する通常の比較関数を型付き参照で解決します。対応する比較を定義した構造体の配列にも使えます。

## enumの共有と分岐

[enumとmatch](enums.md)では構築・payload束縛を共有で行います。`=`は有効なvariantのpayloadをコピーして左辺の外側を更新し、`:=`は共有先を結び直します。matchは対象を一度だけ評価し、網羅性と続行するarmの型一致を検査します。取り出した共有は元のenumが別variantに変わっても生存します。

最小・最大演算子は加減算より弱く比較より強く結合します。通常の演算は選択した値のコピー、更新演算は更新先を共有する値を返します。既定の更新は改善がある場合だけ代入します。[評価と共有の詳細](operators.md#minmax)を参照してください。
